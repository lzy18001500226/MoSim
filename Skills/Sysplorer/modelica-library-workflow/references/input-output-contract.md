# 输出契约

## 角色

本文用于定义 `modelica-library-workflow` 的默认结论结构、证据表达方式和完成口径。  
它不负责判断是否真的完成；是否可称为“完成”仍以 `acceptance-checklist.md` 为准。

## 默认输入期望

用户输入越接近以下信息，落地越快：

1. 目标领域
2. 当前对象：模板、已有库、单个 `.mo` 或流程说明
3. 本轮任务：建库、整理、扩展、评审、中文化、图面修复
4. 交付粒度：方案、文件修改、首版可用库、运行级验证
5. 工具链要求：MWORKS / Sysplorer、Dymola、OpenModelica
6. 语言要求：只中文化用户可见内容，还是连标识符一起处理

## 默认结论结构

默认按以下 7 段组织结论：

1. 当前任务理解与边界
2. 本轮实际改动或本轮方案范围
3. 关键结构、接口或归位策略
4. `Examples` / `Tests` 与文档状态
5. 实际完成的验证层级
6. 风险与未闭环项
7. 下一步建议

若本轮涉及图形化系统模型，默认还要补一段：

8. 图面可见连线状态：是否仅完成 `connect(...)` 语义连接，还是已经补齐 `annotation(Line(...))`

## 必须明确写清的状态边界

### 1. 方案已完成

可写：

- 已完成优化计划
- 已完成结构方案
- 已完成评审结论

必须同时写清：

- 尚未执行真实文件修改，或
- 尚未执行真实验证

### 2. 文件已修改

可写：

- 已更新某些文件
- 已调整结构
- 已修复接口或图面

必须同时写清：

- 是否做了任何工具链验证
- 若未验证，明确写“运行未验证”或“尚未做 Sysplorer 校验”
- 若涉及系统模型图面，明确写“是否已为可见连接补齐 `annotation(Line(...))`”

### 3. 已完成结构级验证

可写：

- 已完成结构检查
- 已完成静态规则检查

不得直接写成：

- 已可运行
- 已首版可用

若涉及图形化系统模型，还必须写清：

- 是否仍存在“只有 `connect(...)`、没有 `annotation(Line(...))`、图上看不到线”的连接
- 是否已经达到“语义连接成立”与“图面可见连线成立”同时满足

### 4. 已完成运行级验证

只有在真实完成对应动作后，才可写：

- 已在 Sysplorer 中加载并打开
- 已通过 `check`
- 已通过 `translate`
- 已完成运行验证

若是首版建库，还应明确写出：

- 顶层库的加载与打开结果
- 首个 `Examples` 入口的检查、翻译、运行结果
- 首个 `Tests` 入口的检查、翻译、运行结果

## 涉及接口时的额外说明

只要本轮修改涉及 `Interfaces`，默认在结论中补充：

1. 接口是否全部归口在当前模型库 `Interfaces`
2. 哪些接口属于标准库移植，哪些属于新建自定义接口
3. 是否按接口族补齐通用接口与方向型接口
4. 是否补了 `defaultComponentName`、图形层实例化和 `%name`

## 涉及图面连线时的额外说明

只要本轮修改、生成或交付对象包含系统模型图面，默认在结论中补充：

1. `connect(...)` 是否已按图面需求补齐 `annotation(Line(...))`
2. 哪些连接已经具备图上可见连线，哪些连接仍只有语义连接
3. 若尚未补齐可见连线，是否已在风险项中单列

## 缺失输入时的默认输出口径

| 缺失项 | 默认输出方式 |
| --- | --- |
| 领域不明确 | 先给中性结构方案，并说明前提假设 |
| 正式包名未明确 | 先给正式命名建议，不保留占位名 |
| 验证要求未明确 | 默认只宣称已完成结构层工作，不擅自写运行通过 |
| 中文化范围未明确 | 默认只中文化用户可见内容 |

## 不得出现的表述

- 没有真实验证却写“已验证通过”
- 只做了结构整理却写“案例可运行”
- 只生成了文件却写“首版模型库可用”
- 未区分 `Examples` 与 `Tests` 的验证状态
- 图上仍看不到组件之间的线，却写成“系统模型连线已完成”

## 建议的证据表达方式

- 文件层：写明改动了哪些关键文件
- 结构层：写明 package、接口和归位策略是否落地
- 验证层：写明实际完成的 `load/open/check/translate/simulate`
- 结果层：若有运行验证，写关键变量或关键观测结论
- 图面层：若涉及系统模型，写明哪些连接已补 `annotation(Line(...))`，图上是否可见组件间连线
