# 任务识别与分流

## 角色

本文件只负责一件事：把用户的自然语言请求快速映射成 **模型库任务类型、当前缺口和默认起步动作**。  
它不负责重复定义 package 规则、接口硬约束或交付口径；这些内容分别交给 `template-package-scheme.md`、`executor-base.md`、`workflow-checklist.md` 和 `input-output-contract.md`。

## 任务类型映射

| 用户意图 | 默认任务类型 | 起步动作 | 首轮重点产物 |
| --- | --- | --- | --- |
| “按流程建一个模型库” | 从 0 到 1 建库 | 先定领域边界、顶层 package 和正式库名 | 顶层结构、首批业务包、Examples/Tests 入口 |
| “参考模板整理这个库” | 沿模板整理模型库 | 先比对模板结构与当前结构差异 | 差异清单、归位方案、重命名方案 |
| “给这个库补组件/接口/示例/测试” | 扩展已有模型库 | 先查现有分层和可扩展位置 | 新增位置、影响范围、最小验证范围 |
| “帮我评审一下这个库” | 评审已有模型库 | 先按检查清单找缺口和错位 | 发现列表、风险、修补顺序 |
| “把说明改成中文” | 中文化修订 | 先区分标识符、显示名、文档说明 | 中文化范围、兼容性风险 |
| “图里没连线/布局很乱” | 图面与连线修复 | 先查 `connect(...)` 是否缺 `annotation(Line(...))`，再查 `Placement`、`Diagram` | 图面修复点、影响范围、复核点 |

## 最小输入集

理想情况下，先确认以下信息：

1. 目标领域：液压、热液压、气动、机械、电气、控制或跨域
2. 当前对象：模板库、已有库、单个 `.mo` 文件或流程说明
3. 本轮目标：建库、整理、扩展、评审、中文化、图面修复
4. 交付粒度：方案、真实文件修改、最小案例、首版可用库
5. 工具链：MWORKS / Sysplorer、Dymola、OpenModelica 或混合兼容
6. 语言要求：仅中文化用户可见内容，还是连标识符一起处理

## 缺失输入时的默认补足

| 缺失项 | 默认补足策略 |
| --- | --- |
| 未给模板 | 先按通用顶层结构规划 |
| 未给正式包名 | 先给正式命名建议，不保留占位名 |
| 未给交付粒度 | 默认做到“结构方案 + 首批模型名单 + 示例/测试入口建议” |
| 未给中文化范围 | 默认只中文化用户可见内容，不改标识符 |
| 未给验证要求 | 默认只做结构级说明，不擅自写运行级结论 |

## 各任务类型的默认输出重点

### 从 0 到 1 建库

重点输出：

1. 顶层 package 结构
2. 正式库名方案
3. 第一阶段模型名单
4. `Examples` 与 `Tests` 的最小闭环入口

### 沿模板整理模型库

重点输出：

1. 模板与现状差异
2. 顶层分层保留项
3. 占位包替换方案
4. 公用层归位调整

### 扩展已有模型库

重点输出：

1. 可扩展位置
2. 新增业务包或子包建议
3. 对现有结构的影响
4. 最小验证范围

### 评审已有模型库

重点输出：

1. 保留项
2. 缺口
3. 错位项
4. 首批修补顺序

### 中文化修订

重点输出：

1. 需要中文化的范围
2. 应保留英文标识符的范围
3. 文档修订优先级
4. 潜在兼容性风险

### 图面与连线修复

重点输出：

1. 缺失的图面注释类型
2. 影响范围
3. 是否存在“仅有 `connect(...)`、未补 `annotation(Line(...))`”的连接
4. 修复顺序
5. 导图或图面复核要求

## 分流后的下一步

- 任务类型已明确后，进入 `template-package-scheme.md` 和 `executor-base.md`
- 若用户只要方案，停留在结构与执行路线层
- 若用户要真实落地，进入真实文件修改与阶段检查

## 完成标志

当以下三项都明确后，本文件的职责即完成：

1. 当前任务类型已识别
2. 缺失输入的默认补足策略已确定
3. 下一份应读取的参考资料已明确
