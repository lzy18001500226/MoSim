# CoAgent Evidence

## Purpose

This directory owns compact evidence manifests for CoAgent tasks.

The manifest builder is read-only apart from writing the requested manifest. It
collects evidence paths from runtime metadata and known ignored `Results/`
locations, then writes a JSON/Markdown index that a reviewer or fresh
conversation can use without searching several status folders manually.
It also indexes blocker-notification packets under
`Results/agent_packets/blockers/` when a task-health decision requires human,
review, safety, or rework intervention.

Each existing file records `modified_at` and
`fresh_after_task_last_event`. Stale files do not fail the manifest by
themselves because some evidence can intentionally predate a later checkpoint,
but `stale_count` and the stale item list make outdated status, review, doctor,
or evidence packages visible before a resumed conversation relies on them.

When `stale_refresh_recommended=true`, use the emitted `refresh_commands`
before treating the stale artifacts as current. The expected sequence is
generated by `CoAgent/evidence/refresh_commands.py`:

```text
quick doctor
full doctor
Git handoff
closeout verification
task health
status/resume export
evidence manifest
review package
```

Both quick and full doctor outputs are refreshed because either can be
registered as current recovery evidence in runtime metadata.
The review package is generated last because it summarizes the freshly
generated evidence manifest.

This is advisory, not a hard failure. Missing evidence still controls `ok`;
stale evidence is a recovery warning for resumed conversations.

Freshness is split by role:

- `critical_stale_count`: current recovery artifacts referenced by runtime
  metadata, such as status/resume, task-health, doctor, Git handoff, blocker,
  or closeout-verification files.
- `archival_stale_count`: older support files discovered by glob or generic
  evidence metadata. These remain visible for audit but do not by themselves
  trigger `stale_refresh_recommended`.
- `review_package_path` and `review_package_markdown` are downstream package
  outputs. The manifest lists them, but their freshness is not counted because
  the package summarizes the manifest and is normally generated after it.

## Command

```bash
python3 CoAgent/evidence/evidence_manifest.py \
  --task-id COAGENT-IMPL-LONGRUN-20260531 \
  --output Results/coagent_status/COAGENT-IMPL-LONGRUN-20260531.evidence_manifest.json \
  --markdown-output Results/coagent_status/COAGENT-IMPL-LONGRUN-20260531.evidence_manifest.md
```

The command does not dispatch work, send notifications, stage Git, commit,
push, or mutate runtime task state.
