# 02 模型、坐标系与统一接口设计

## 1. 目标

统一四旋翼模型、控制器、轨迹、扰动、编队和评估模块的数据接口，保证各模块可以独立开发和替换。

系统新增三个跨模块接口：

1. `task_mode_bus`：描述任务阶段、扰动类型、故障状态和控制模式；
2. `replay_bus`：面向三维回放和视频素材导出，不参与控制闭环。
3. `hardware_status_bus`：描述飞控、GPS、Mid360、ORIN NX 机载计算、电源和通信健康状态，用于模式管理和安全返航；该接口是系统级抽象，不要求在官方机体模型中新增实物部件。

## 2. 坐标系

### 2.1 世界坐标系 W

```text
p_w = [x, y, z]^T
v_w = [vx, vy, vz]^T
```

建议使用 Z 向上。若 MWORKS 模型采用不同约定，以模型为准，并提供转换函数。

### 2.2 机体系 B

```text
ω_b = [p, q, r]^T
```

- p：roll rate；
- q：pitch rate；
- r：yaw rate。

### 2.3 姿态

接口使用：

```text
att = [roll, pitch, yaw]^T
```

模型内部可使用四元数，但需提供转换。

## 2.4 状态预处理约定

控制器不得直接假设所有状态都由模型原生提供，需经过 `state_preprocessor` 统一整理。

```text
sensor/model output
  → coordinate_transform
  → velocity_filter
  → angular_acceleration_estimator
  → state_bus
```

状态来源：

| 状态 | 优先来源 | 回退来源 | 处理方式 |
|---|---|---|---|
| position | 模型/传感器直接输出 | - | 坐标系转换 |
| velocity | 模型直接输出 | position 差分 | 一阶低通滤波 |
| attitude | 模型欧拉角或四元数 | - | 四元数转欧拉角 |
| angular_rate | 陀螺仪/模型输出 | attitude 差分 | 一阶低通滤波 |
| angular_acceleration | 模型直接输出 | angular_rate 差分 | INDI 专用低通滤波 |

推荐滤波：

```text
x_f(k) = alpha * x_f(k-1) + (1-alpha) * x_raw(k)
```

推荐参数：

```yaml
state_preprocessor:
  velocity_filter_alpha: 0.6
  angular_rate_filter_alpha: 0.7
  angular_acc_filter_alpha: 0.85
  max_velocity: 20.0
  max_angular_rate: 8.0
```

## 3. 动力学模型

### 3.1 平动

```text
p_dot = v
v_dot = g + (T/m) R e_z + d_v
```

### 3.2 转动

```text
J ω_dot = τ - ω × Jω + d_τ
```

### 3.3 电机

```text
f_i = k_f Ω_i^2
m_i = k_m Ω_i^2
Ω_dot = (Ω_cmd - Ω) / τ_m
```

### 3.4 执行器效率

```text
f_i_actual = η_i f_i_cmd
η_i ∈ [0,1]
```

## 4. 控制分配

```text
[T, τx, τy, τz]^T = B [f1, f2, f3, f4]^T
```

电机编号采用俯视图约定，若官方模型不同，以官方模型为准并在适配层转换：

```text
        front +x
           1
           ^
           |
   4 <--- C ---> 2
           |
           v
           3
        rear -x
```

推荐旋转方向：

```text
motor 1: CCW
motor 2: CW
motor 3: CCW
motor 4: CW
```

X 构型控制分配矩阵建议写成：

```text
B = [
  1,   1,   1,   1
  l,  -l,  -l,   l
 -l,  -l,   l,   l
  c,  -c,   c,  -c
]
```

其中：

```text
l = arm_length / sqrt(2)
c = k_m / k_f
```

如果官方模型使用 `+` 构型或不同电机编号，应提供 `motor_mapping`：

```yaml
motor_mapping:
  official_order: [1, 2, 3, 4]
  project_order: [1, 2, 3, 4]
  frame_type: x
  command_type: normalized
```

控制器内部统一先计算电机推力 `f_cmd[4]`，再根据平台需要转换为归一化指令、转速或 PWM 等效量：

```text
Omega_cmd_i = sqrt(max(f_cmd_i, 0) / k_f)
motor_cmd_i = normalize(Omega_cmd_i, Omega_min, Omega_max)
```

故障时：

```text
B_fault = B diag(η)
```

伪逆重构：

```text
f_cmd = pinv(B_fault) [T, τx, τy, τz]^T
```

### 7.1 规划器接口

单机规划模块的职责是从地图和任务目标生成 `reference_bus`，不直接输出电机指令，不替代控制器。

输入：

```json

  "map": {
    "map_id": "map_open_blocks",
    "bounds": {"x": [-2, 8], "y": [-3, 3], "z": [0, 3]},
    "resolution": 0.2,
    "safety_margin": 0.35,
    "obstacles": [
      {"type": "box", "min": [2.0, -1.2, 0.0], "max": [2.8, -0.2, 2.2]},

  },
  "mission": {
    "start": [0, 0, 1],
    "goal": [6, 0, 1],
    "yaw_mode": "face_velocity"
  },
  "limits": {
    "v_max": 1.5,
    "a_max": 2.0,
    "j_max": 8.0,
    "tilt_max_deg": 35
  }
}
```

输出：

```text
path_bus:
  path_points[N,3]
  path_length
  planning_success

trajectory_bus:
  time
  position_ref[3]
  velocity_ref[3]
  acceleration_ref[3]

  map_id

  planning_time
```

接口用途：

```text
hardware_status_bus
  → task_mode_manager
  → controller_mode / safety_filter / return_land_manager
```

当前实现边界：

| 子系统 | 当前进入闭环 | 当前只做抽象 |
|---|---|---|
| 飞控 | 控制器更新频率、模式管理变量 | MAVLink、PX4 内部 EKF |
| GPS | 位置健康状态和后续 failsafe 触发 | 真实卫星解算 |
| Mid360 | 局部栅格更新频率和障碍感知接口 | 非重复扫描线、完整点云 SLAM |
| ORIN NX | 规划、局部地图、安全监督的计算健康状态 | CUDA 推理、真实 ROS 节点 |
| 电池 | `bus_voltage`、`power_ok`、`voltage_margin` 和后续低电量 failsafe | 真实 BMS 通信、温度和内阻估计 |
| 电调 | 电机命令限幅、`esc_health`、饱和估计 | 真实 DSHOT/UAVCAN ESC 协议 |

PX4-like 系统状态映射：

| 项目字段 | PX4 参考 | 当前/后续用途 |
|---|---|---|
| `arming_state` | `VehicleStatus.ARMING_STATE_*` | `INIT/ARM/DISARM` 状态和电机使能 |
| `nav_state` | `VehicleStatus.NAVIGATION_STATE_*` | `TAKEOFF/MISSION/AVOID/RETURN/LAND/FAILSAFE` |
| `failsafe` | `VehicleStatus.failsafe` | 总安全状态 |
| `home_position_valid` | `HomePosition` / `FailsafeFlags.home_position_invalid` | 返航可用性 |
| `offboard_heartbeat_ok` | `OffboardControlMode` / `FailsafeFlags.offboard_control_signal_lost` | GUI/外部规划链路可用性 |
| `mission_feasible` | mission/navigator checks | 规划器是否有可执行参考 |
| `geofence_ok` | `FailsafeFlags.geofence_breached` | 地图边界和禁飞区检查 |
| `battery_warning` | `BatteryStatus.warning` | 低电量返航/降落 |
| `esc_health[4]` | `EscStatus` / `FailsafeFlags.fd_motor_failure` | 电机/电调故障隔离 |

### 8.1 GUI Experiment Studio 配置接口

GUI 定位为项目实验软件，不是通用 UAV Toolbox。它只负责生成配置、编排仿真、读取日志和展示证据，不做 QGroundControl 类地面站、MAVLink 真实接口、硬件在环或 Gazebo/PX4 SITL 主线。若接入 Unreal，它只作为外部渲染器读取状态流，不反向驱动控制器、规划器或指标计算。GUI 不直接改 `QuadrotorModel/package.mo` 或控制器源码。标准链路如下：

```text
GUI selections
  → scenario.yaml
  → controller_params.yaml
  → planner_map.yaml
  → batch_run_plan.yaml
  → results/{group}/{scene}/{experiment}/
  → log analysis / evidence dashboard
```

外部 Unreal 渲染链路必须保持单向只读：

```text
MWORKS/Sysplorer closed-loop simulation
  → raw.csv / native result / realtime state frame
  → TCP/UDP publisher
  → Unreal receiver
  → UAV mesh/material, propeller animation, terrain/material, radar sector, local plan, camera
  → video recording / screenshots
```

状态帧最小接口：

```yaml
frame:
  t: seconds
  uav:
    position_m: [x, y, z]
    rpy_rad: [roll, pitch, yaw]
    motor_speed_or_command: [m1, m2, m3, m4]
  reference:
    position_m: [x_ref, y_ref, z_ref]
  local_plan:
    points_m: [[x, y, z], ...]
  perception:
    radar_origin_m: [x, y, z]
    yaw_rad: yaw
    near_radius_m: 6
    far_radius_m: 9
    fov_deg: 120
  event:
    mode: NORMAL
    fault_id: none
```

坐标约定：MWORKS 输出单位保持米和弧度；Unreal 接收端内部按需要转换为厘米和 Z-up 坐标。转换必须只发生在渲染端，不能污染 raw CSV、metrics 或规划真值。

当前离线回放发送器：

```text
scripts/stream_unreal_udp.py
```

该脚本读取标准 raw CSV 字段 `time,x,y,z,x_ref,y_ref,z_ref,roll,pitch,yaw,u1,u2,u3,u4`，向 `udp://127.0.0.1:5005` 发送 `quadrotor.unreal_state.v1` JSON 帧。它只用于外部渲染 POC 和视频录制，不参与 MWORKS 仿真证据链。

接口规则：

1. GUI 生成的配置必须保存为 YAML/JSON，不能只保存在界面状态中。
2. 已实现算法必须写入正式 `controller_id`、`planner_id` 和 `evidence_level`。
3. 未实现算法可显示为 `experimental/not_implemented`，但不能进入通过结论。
4. 随机障碍物数量固定，位置由 seed 决定；同一个 seed 必须复现同一张地图。
5. 有障碍和无障碍地图共享同一坐标系、起终点、控制接口和结果目录规范。
6. UAV 数量范围为 1-5；单机实验自动关闭编队误差和机间距离指标。
7. GUI 调用现有 `scripts/run_mworks_scenario.py`、`scripts/summarize_experiments.py`、`scripts/audit_evidence_bundle.py`，不重复实现评估逻辑。
8. 日志分析器只读取已有 raw、metrics、event_log、MCP log、native_result manifest 和人工审核清单，不重新定义质量门。
9. 地图数据层和显示层必须分离：`0.16 m` 等细栅格可以用于规划、碰撞和局部感知计算，但不能逐格实例化为 Sysplorer 三维组件。
10. 新地图渲染方案必须先跑短时 GUI 审查；若出现卡死、动画缺失、求解器失败或人工观感不达标，回退到 `stable_low_complexity_pillars`。

## 12. MWORKS 模型集成位置

### 12.1 模型替换原则

基于官方四旋翼案例时，优先保留机体、电机、传感器和可视化模块，只替换或并联控制器部分。这样 baseline 与优化算法共享同一被控对象，便于公平对比。

```text
官方参考轨迹/任务输入
    ↓
控制器子系统（替换重点）
    ↓
控制分配/电机指令
    ↓
电驱模型
    ↓
四旋翼本体模型
    ↓
传感器/状态输出
```

### 12.2 建议替换位置

| 官方模块类型 | 处理方式 | 自定义模块 | 说明 |
|---|---|---|---|
| 轨迹/指令输入 | 保留并扩展 | reference_manager | 支持悬停、阶跃、8 字、螺旋和 CSV 轨迹 |
| PID 位姿控制器 | 复制一份后替换 | controller_pid_improved / controller_pid_indi / controller_mpc_indi | 不直接覆盖官方 baseline |
| 控制分配模块 | 保留并加接口 | allocation_fault_aware | P0 可用官方分配，P1/P2 加入电机效率 eta |
| 电机模型 | 保留 | motor_fault_injector | 通过效率系数或响应时间注入故障 |
| 机体动力学 | 保留 | plant_quadrotor | 所有控制器共用同一 plant |
| 传感器模型 | 保留并扩展输出 | sensor_logger | 输出位置、速度、姿态、角速度和噪声配置 |

图形化布局验收要求：`QuadrotorModel/Resources/Images/` 中的图片必须由 `references/CUAV/` 当前透明 PNG 原图直接复制，不做白底化或 RGB 转换；顶层模块放置应保持等比例缩放，避免 V6X、ORIN NX、GPS、Sunray150、电池、电调等图片被拉伸；端口图标尺寸应保持小尺寸，避免顶层放大后出现过大的箭头；布局应紧凑但保留清晰列结构；跨模块连接线应足够可见并尽量沿模块外侧走线，不应压住硬件图片。

它用于人工审核完整信号流，不替代当前可运行性能主线。由于当前 Sysplorer/Sysblock 在图形化控制器嵌入 Modelica 整机时仍存在多输入端口解析限制，完整系统顶层使用 `AWFF_FullControllerEquation_Sysblock` 作为控制律执行桥接模型；`AWFF_FullControllerFlatGraphical_Sysblock` 继续作为图形化结构审核材料，并必须与桥接模型保持连接语义一致。

2026-05-15 系统级收尾更新：`Sunray150CompleteSystemGraphical_Sysblock` 已从静态硬件框图升级为最小飞控系统信号流。`PerceptionInterfaceModule` 输出 `gps_valid`、`mid360_valid`、`obstacle_margin` 和传感器健康度；`V6XFlightControllerModule` 增加一阶状态估计器，输出 `position_est`、`attitude_est`、`motor_speed_est`、`estimator_quality` 和 `estimator_mode`；`ORINNXMissionComputerModule` 增加最小飞控状态机和 setpoint 仲裁，输出 `flight_mode`、`active_setpoint_source`、`safety_status` 和 `event_code`。当前 smoke 使用 `airframe.position[1:3]` 与 `mission_computer.reference_position[1:3]` 作为结果变量。

2026-05-15 GPS 失效场景补充：`QuadrotorExperiments.Sunray150CompleteSystemGPSDropoutSysblock` 用于 P1-B 系统级 failsafe 证据，失效窗口为 0.35-0.85 s。该场景新增 `SystemSupervisorModule`，输出 `degraded_nav_active`、`flight_mode`、`active_setpoint_source` 和 `safety_status`。实测中，Sysplorer 对未进入闭环的顶层条件变量和二级依赖输出存在常量折叠/导出差异，因此系统模式质量门槛以可靠导出的 `gps_valid`、`degraded_nav_active`、`flight_mode=6`、`active_setpoint_source=90`、`safety_status=3` 为准；`event_log.json` 在 `flight_mode=6` 时映射为 `DEGRADED_NAV`，不再依赖单独的 `event_code` 导出作为唯一证据。

2026-05-15 PX4-like failsafe 扩展：`SystemSupervisorModule` 已从单一 GPS 降级触发扩展为五类可复测安全触发，并保留电池-电调-电机数据流。`battery.voltage_margin` 通过真实连接进入系统监督器，低于阈值或进入低电量窗口后触发 `battery_low_active`；`offboard_loss_active`、`mission_failure_active`、`geofence_breach_active` 由场景窗口触发，用于模拟外部控制链路丢失、任务不可行和地理围栏越界。当前优先级为 `geofence > mission_failure > offboard_loss > battery_low > degraded_nav > normal`，均输出 `flight_mode=6` 作为返航/降级模式。事件编码约定：`60=DEGRADED_NAV`、`61=BATTERY_LOW_RETURN`、`62=OFFBOARD_LOSS_RETURN`、`63=MISSION_FAILURE_RETURN`、`64=GEOFENCE_RETURN`。新增场景文件位于 `scenarios/system/`：`sunray150_complete_system_battery_low_sysblock.yaml`、`sunray150_complete_system_offboard_loss_sysblock.yaml`、`sunray150_complete_system_mission_failure_sysblock.yaml`、`sunray150_complete_system_geofence_breach_sysblock.yaml`。这些场景用于系统状态机和安全仲裁证据，不替代控制器性能主线。质量门以稳定导出的 `event_code` 和触发变量为主判据，`active_setpoint_source` 与 `safety_status` 在 metrics 中按事件码写入 inferred 字段；这是为了规避 Sysplorer 对部分派生顶层标量的常量折叠导出差异。

## 13. 信号接口清单

### 13.1 状态输入 state_bus

| 信号 | 单位 | 维度 | 来源 |
|---|---:|---:|---|
| time | s | 1 | 仿真时钟 |
| position | m | 3 | 机体/传感器输出 |
| velocity | m/s | 3 | 机体/传感器输出 |
| attitude | rad | 3 | 姿态解算或模型输出 |
| angular_rate | rad/s | 3 | 陀螺仪或模型输出 |
| motor_speed | rad/s | 4 | 电机模型输出 |

### 13.2 参考输入 reference_bus

| 信号 | 单位 | 维度 | 来源 |
|---|---:|---:|---|
| position_ref | m | 3 | 场景管理器/轨迹 CSV |
| velocity_ref | m/s | 3 | 轨迹生成器 |
| acceleration_ref | m/s^2 | 3 | 轨迹生成器 |
| yaw_ref | rad | 1 | 场景管理器 |

P0 若暂时没有速度/加速度参考，可由 position_ref 差分或置零；P1/P2 再使用平滑轨迹生成完整参考。

### 13.3 参数输入 param_bus

| 参数 | 含义 |
|---|---|
| mass | 质量 |
| inertia | 转动惯量 |
| arm_length | 机臂长度 |
| motor_limits | 电机上下限 |
| controller_gains | PID/INDI/MPC 参数 |
| safety_limits | 姿态、推力、速度、高度限制 |
| motor_efficiency | 电机效率 eta |

### 13.4 控制输出

| 信号 | 单位 | 维度 | 用途 |
|---|---:|---:|---|
| thrust | N | 1 | 总推力调试量 |
| torque | N*m | 3 | 姿态控制输出 |
| motor_cmd | 归一化或 rad/s | 4 | 电机输入 |
| controller_mode | enum/int | 1 | NORMAL/SAFETY/FAULT 等模式 |
| debug | - | 多维 | 误差、约束、扰动估计、求解状态 |

### 13.5 任务模式 task_mode_bus

| 信号 | 取值 | 用途 |
|---|---|---|
| task_phase | TAKEOFF/TRACKING/DELIVERY/RETURN/LAND | 任务阶段机 |
| controller_mode | NORMAL/WIND_REJECTION/MASS_ADAPTATION/FAULT_TOLERANT/SAFETY_PROTECTION/EMERGENCY_LAND | 控制模式切换 |
| disturbance_type | NONE/WIND/GUST/MASS_CHANGE/SENSOR_NOISE | 扰动识别 |
| fault_level | NONE/LIGHT/MEDIUM/HEAVY | 故障等级 |
| mode_switch_reason | string | 事件日志和报告说明 |

模式切换建议由 `task_mode_manager` 输出，控制器只根据模式启用或关闭补偿、限幅、故障重构和降级策略。

### 13.6 三维回放 replay_bus

| 信号 | 单位 | 用途 |
|---|---:|---|
| time | s | 回放时间轴 |
| pose | m/rad | 无人机位置和姿态 |
| reference_pose | m/rad | 参考轨迹 |
| motor_cmd | - | 电机状态可视化 |
| disturbance_vector | N 或 m/s^2 | 风扰箭头/扰动标记 |
| event_marker | - | 故障、模式切换、投递、返航等事件 |

`replay_bus` 只用于导出，不反向影响 MWORKS 控制结果。

## 15. 平台实现回退路线

| 风险 | 回退实现 |
|---|---|
| Sysblock 中 NMPC 求解困难 | 使用线性 MPC 或 PID-INDI 作为 P1 主控制器 |
| 速度/加速度参考无法直接导入 | Syslab 预生成 reference.csv 后用查表模块读取 |
| 控制器替换影响官方模型 | 保留官方模型副本，每个控制器使用独立模型版本 |
| 结果变量导出不全 | 先导出 P0 必需变量，再逐步增加 debug 信号 |
| MCP 不稳定 | 使用手动 Sysplorer 仿真 + Syslab 脚本计算指标，并记录失败工具名和错误信息 |

MCP 工具细则不在本设计文档重复维护，统一查看 `docs/index/api_index.md`、`workflows/debug_mcp.md` 和 `Skills/Mworks/mworks-mcp-operations/SKILL.md`。
