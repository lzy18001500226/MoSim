## 4. 控制指标

位置 RMSE：

```text
RMSE = sqrt(mean(||p-p_ref||²))
```

最大误差：

```text
Emax=max||p-p_ref||
```

稳态误差：

```text
Ess=mean(error in last T seconds)
```

超调量：

```text
OS=(max-response-target)/target
```

调节时间：

```text
error enters tolerance band and stays
```

推荐统一口径：

| 指标 | 统计口径 |
|---|---|
| RMSE | 全时段位置三维误差的均方根 |
| max_error | 全时段最大三维位置误差 |
| steady_error | 最后 5 s 的平均位置误差；若总时长小于 10 s，取最后 20% 时段 |
| overshoot | 仅用于阶跃场景，按目标方向单轴响应统计 |
| settling_time | 误差进入 0.1 m 或目标幅值 5% 容差带，并持续 2 s |
| recovery_time | 扰动开始后，误差重新进入 0.2 m 容差带并持续 2 s 的时间 |

## 6. 控制代价

```text
control_energy = ∫||u||²dt
control_smoothness = ∫||du/dt||²dt
control_energy_per_second = control_energy / duration_s
control_smoothness_per_second = control_smoothness / duration_s
saturation_ratio = saturation_samples/total_samples
```

当不同实验的导出采样率不同，例如同为 50 s 但分别导出 5001 行和 25001 行时，报告优先使用 `control_energy_per_second` 和 `control_smoothness_per_second`。原始积分值仍保留在 metrics JSON/CSV 中，用于同采样率结果内追溯。


推荐统一口径：

| 指标 | 统计口径 |
|---|---|
| planning_success | 规划器返回完整 path/reference 且起终点合法 |
| planning_time | 从读取地图到输出平滑轨迹的总耗时 |
| expanded_nodes | A*/搜索类规划器展开节点数 |
| path_length | 离散路径点折线长度 |
| trajectory_length | 平滑轨迹按采样点积分的长度 |
| min_obstacle_distance | 实际轨迹到膨胀前障碍物表面的最小距离 |
| safety_margin_violation_count | `distance < safety_margin` 的采样点数量 |
| collision_count | `distance <= 0` 的采样点数量 |
| dynamic_violation_count | 速度、加速度、jerk、倾角任一超限的采样点数量 |
| replan_count | 动态障碍或安全层触发重新规划的次数 |
| replan_latency_max | 从触发事件到新轨迹可用的最大延迟 |
| fallback_used | 是否使用预设航点、限速折线或安全返航回退 |
| trackability_score | 规划阶段预测的可跟踪性评分 |

P1 单机避障通过标准：

```text
planning_success = true
collision_count = 0
safety_margin_violation_count = 0
dynamic_violation_count = 0
min_obstacle_distance >= safety_margin
trackability_score >= 0.8
closed_loop_tracking_rmse <= 0.35 m
max_tracking_error <= 1.00 m
saturation_ratio <= 0.20
```

P2 动态重规划通过标准：

```text
collision_count = 0
replan_count >= 1
replan_latency_max <= 1.0 s
fallback_used = false 或有明确 event_log 说明
动态障碍出现后 safety_margin_violation_count = 0
```

规划类场景必须额外保存：


## 12.1 控制健康度评分

健康度评分用于把多个指标统一成 0~100 分，便于批量实验排序、雷达图展示和视频总结。评分不替代原始指标，报告中必须同时保留 RMSE、恢复时间、稳态误差、约束违规次数和饱和比例等原始数据。

分项：

| 分项 | 输入指标 | 含义 |
|---|---|---|
| tracking_score | RMSE、max_error、steady_error | 跟踪精度 |
| robustness_score | recovery_time、degradation、disturbance RMSE | 抗扰能力 |
| safety_score | constraint_violation_count、min_altitude、min_obs_dist | 安全约束 |
| energy_score | control_energy、saturation_ratio | 控制代价 |
| smoothness_score | control_smoothness、jerk_integral | 控制和轨迹平滑度 |
| fault_tolerance_score | fault recovery、allocation_error、degraded_task_completion | 容错能力 |

归一化建议：

```pseudo
score_lower_better(value, target, fail):
    if value <= target: return 100
    if value >= fail: return 0
    return 100 * (fail - value) / (fail - target)

score_higher_better(value, target, fail):
    if value >= target: return 100
    if value <= fail: return 0
    return 100 * (value - fail) / (target - fail)
```

总分：

```text
total_health_score =
  0.30 tracking_score
+ 0.25 robustness_score
+ 0.20 safety_score
+ 0.10 energy_score
+ 0.05 smoothness_score
+ 0.10 fault_tolerance_score
```

建议阈值：

| 指标 | 满分阈值 target | 失败阈值 fail | 评分方向 |
|---|---:|---:|---|
| RMSE | 0.20 m | 1.00 m | 越低越好 |
| max_error | 0.60 m | 3.00 m | 越低越好 |
| steady_error | 0.10 m | 0.80 m | 越低越好 |
| recovery_time | 2.0 s | 10.0 s | 越低越好 |
| saturation_ratio | 0.10 | 0.80 | 越低越好 |
| constraint_violation_count | 0 | 10 | 越低越好 |
| constraint_violation_rate_hz | 0.00 Hz | 0.20 Hz | 越低越好 |
| min_obstacle_distance | 0.50 m | 0.00 m | 越高越好 |
| min_inter_uav_distance | 0.80 m | 0.20 m | 越高越好 |
| degraded_task_completion | 1.0 | 0.0 | 越高越好 |

阈值应写入 `score_config.yaml`，不同场景可以覆盖默认值。报告中若使用健康度总分，必须同时列出分项指标，避免用主观总分替代原始证据。

验收：

```text
每个 batch 输出 health_score.csv
每个 controller-scene 组合有分项评分
summary.md 自动列出 top controller 和失败原因
```

## 18. 三维回放与视频素材生成

三维回放是展示模块，不参与控制算法，也不替代 MWORKS/Syslab 的仿真和指标计算。

当前控制器仿真阶段的主路线是导出 `replay.json`，用于记录真实 raw CSV 对应的实际轨迹、参考轨迹、事件和指标摘要。浏览器 HTML 回放只作为临时预览工具，不进入正式控制器仿真证据链。后续展示阶段优先使用 MWORKS native result、Sysplorer GUI 动画、项目 GUI 审查面板或轻量数据回放读取 `replay.json/raw.csv`，不把 Gazebo 作为当前核心依赖。

推荐流程：

```text
raw.csv/reference.csv/metrics.csv/event_log.json
  → replay_exporter
  → replay.json
  → MWORKS GUI / native result / 项目 GUI 审查面板 / 临时浏览器预览
  → 截图、短视频、双机对比画面
```

三维展示最低功能：

| 功能 | 要求 |
|---|---|
| 轨迹显示 | 参考轨迹和实际轨迹颜色区分 |
| 无人机模型 | 支持姿态更新和多机显示 |
| 障碍物 | 支持 box/sphere/cylinder 简化几何 |
| 风扰 | 支持箭头或半透明区域显示 |
| 故障高亮 | 故障电机变色，显示 eta |
| 事件时间轴 | 显示 wind_enter、mass_change、motor_fault、emergency_land |
| 对比模式 | 支持 baseline 与 proposed 双机/双轨迹同步播放 |
| 导出素材 | 支持截图和录屏 |

不建议在当前控制器仿真阶段把 ROS/Gazebo 通信作为核心依赖。三维展示读取 MWORKS 导出的真实仿真数据，展示效果由 MWORKS GUI、native result、项目 GUI 审查面板或轻量回放工具承担；控制器可信度仍由 CSV/JSON/metrics/MCP 日志保证。

## 20. GUI 指标面板、日志分析与实验编排

最终 GUI 不单独计算或伪造指标，只作为实验配置、运行状态、日志分析和证据展示入口。所有展示值必须来自 `metrics.json`、`metrics.csv`、summary、event_log、MCP log、native_result manifest 或人工审核清单。该 GUI 是项目级实验软件，不是 UAV Toolbox、QGC 地面站、MAVLink 真实接口或 Gazebo/Unreal 高保真视觉仿真替代品。

| 面板 | 功能 | 数据来源/输出 |
|---|---|---|
| Experiment Composer | 选择场景、轨迹生成、路径规划、控制器、增强模块、编队、扰动 | `scenario.yaml`、`controller_params.yaml`、`planner_map.yaml` |
| Simulation Runner | 显示运行状态、MCP 日志、模型检查、仿真进度、失败原因 | raw.csv、metrics.json、mcp log、native result |
| Log Analyzer | 解析 raw、metrics、event_log、MCP log、native_result manifest 和人工审核清单，生成事件时间线、质量门和失败原因摘要 | `event_log.json`、`*.jsonl`、`native_result_manifest.json`、`人工审核清单.csv` |
| Evidence Dashboard | 展示指标表、质量门、人工审核入口、图表和 native result 路径 | summary、`人工审核清单.csv`、报告素材 |

### 20.1 GUI 必选指标

| 指标 | 含义 | 适用场景 |
|---|---|---|
| RMSE | 位置或姿态均方根误差 | 所有轨迹跟踪 |
| 最大误差 | 全程最大跟踪误差 | 所有轨迹跟踪 |
| 稳态误差 | 稳态区间平均误差 | 悬停、阶跃、鲁棒性 |
| 超调量 | 阶跃或高度响应峰值超出比例 | 阶跃、起飞、降落 |
| 调节时间 | 误差进入并保持在阈值内的时间 | 阶跃、扰动恢复 |
| 控制能量 | 电机/推力/力矩指令积分 | 控制器对比 |
| 控制平滑性 | 控制输入变化率或 jerk 代价 | 规划和控制器对比 |
| 推力/电机饱和比例 | 电机或推力命令触及限幅的时间占比 | 复杂轨迹、故障、鲁棒性 |
| 最小障碍物距离 | 飞行轨迹到障碍物膨胀体的最小距离 | 避障和局部重规划 |
| 最小机间距离 | 多机之间的最小距离 | 编队和多机避障 |
| 编队误差 | 实际相对位置与目标队形的误差 | 编队 |
| 鲁棒性保持率 | 扰动下相对 nominal 的性能保持程度 | 风扰、质量、惯量、电机效率、噪声、脉冲 |

### 20.3 GUI 实现边界

1. GUI 可以用 Syslab/Julia GUI、MWORKS App 或轻量 Web UI 实现，但 YAML/JSON 配置是唯一可信输入。
2. GUI 不直接修改 `QuadrotorModel/package.mo`、控制器 `.mo` 或 Sysblock 模型源文件。
3. GUI 不重新计算核心指标，只读取正式 metrics 和 summary 文件。
4. 未完成算法可以在界面中灰显，但不能生成 `pass` 结论。
5. GUI 必须遵守 `AGENTS.md` 中的 MCP 窗口、授权、native result 和人工审核规则。
6. 地图渲染只服务人工审查，不参与质量门计算；高精度栅格不能逐格变成 Sysplorer 组件。
7. 新渲染模式必须记录 `visualization_mode`、`display_cell_resolution_m`、`manual_review_status` 和 `fallback_used`；人工审核不通过时回退稳定低复杂度显示方案。
