# 00 系统总体设计

## 1. 项目定位

项目名称建议：

**面向复杂任务场景的四旋翼无人机自适应鲁棒位姿控制与智能仿真验证系统**

核心口径：

> 以 MWORKS 四旋翼模型为基础，围绕“官方 PID baseline → 改进 PID → PID-INDI/MPC-INDI → 扰动补偿”的逐级消融路线，完成复杂轨迹跟踪、风扰/质量摄动鲁棒性验证和量化评估；在主线稳定的基础上扩展安全过滤、故障注入、路径规划、编队与 Syslab/MCP 自动化评估。

## 4. 关键创新点

### 4.1 自适应鲁棒位姿控制

1. **统一控制链路**：MPC/NMPC 外环、INDI 姿态内环、L1-inspired 加速度残差补偿、安全过滤和故障重构串成一条可替换控制链。
2. **扰动识别与模式切换**：根据速度/加速度残差、姿态残差、电机效率 eta 和传感器噪声指标，切换 `NORMAL`、`WIND_REJECTION`、`MASS_ADAPTATION`、`FAULT_TOLERANT`、`SAFETY_PROTECTION` 和 `EMERGENCY_LAND`。
3. **逐级消融验证**：PID → 改进 PID → PID-INDI/线性 MPC-INDI → NMPC-INDI → +L1-inspired → +Safety/Fault，每个增强模块必须有独立对比指标。

### 4.2 可跟踪性感知规划创新

1. **Trackability-aware Trajectory Planning**：规划轨迹不仅满足几何避障，还检查速度、加速度、jerk、倾角、推力余量和电机饱和风险。
2. **控制反馈修正轨迹**：若仿真结果显示跟踪误差或饱和比例过高，自动放大时间分配、降低参考速度或增加转弯半径。
3. **轻量 EGO-inspired 局部优化**：不强依赖完整 ROS/ESDF，只用局部障碍物几何距离构造碰撞代价和安全引导路径。

### 4.3 故障诊断与安全降级创新

1. **故障链路闭环**：故障注入 → 残差检测 → 故障分类 → 控制分配重构 → 安全降级 → 指标评估。
2. **分级容错**：轻度故障继续任务，中度故障启用重构，重度故障降级返航或安全降落。
3. **事件日志驱动展示**：每次故障、模式切换、安全保护和降级动作都记录到 event_log，支撑报告和视频复现。

### 4.4 多机协同任务创新

1. Leader-Follower 编队；
2. 多队形配置和平滑切换；
3. 狭窄通道自动队形收缩；
4. 机间安全距离约束；
5. Leader 规划绕障 + Follower 可行性检查；
6. Leader 故障或 Follower 异常时的队形降级策略。

### 4.5 智能仿真评估创新

1. 多场景扰动测试矩阵；
2. 风扰、质量摄动、电机效率下降、传感器噪声；
3. Syslab 批量实验与自动指标；
4. 健康度评分：tracking、robustness、safety、energy、smoothness、fault_tolerance；
5. 数据驱动三维回放：读取 MWORKS 导出的 CSV/JSON，生成真实仿真数据对应的视频素材。

### 4.5.0 外部仿真平台对标结论

近期调研对象包括 RflySim、MATLAB UAV Toolbox、Flightmare、RotorS、XTDrone、Pegasus Simulator 和 AirSim。结论不是照搬其中任一平台，而是吸收它们的架构分工：

| 参考平台 | 可借鉴点 | 本项目采用方式 |
|---|---|---|
| RflySim | MBD 主线、PX4/Simulink、SIL/HIL、UE 场景、UDP/共享内存、多机集群测试 | 保持 MWORKS/Sysplorer 为求解和控制主线，UE5 作为只读外部渲染与视频层 |
| MATLAB UAV Toolbox | Scenario 配置、传感器仿真、Unreal 场景、自定义场景、代码生成出口 | 设计 `Quadrotor Experiment Studio`，统一生成 scenario/controller/planner/render 配置 |
| Flightmare | 物理引擎和渲染引擎解耦，Unity/渲染层只负责场景和传感器输出 | MWORKS 输出真实状态，UE5 读取 raw/native/realtime frame，不回写控制结论 |
| RotorS / XTDrone | ROS/Gazebo 下的传感器、控制器、消息接口和多机组织方式 | 借鉴接口分层，不把 ROS/Gazebo 作为当前比赛主证据链 |
| Pegasus Simulator | PX4/ROS2/Isaac Sim、多机和 GUI 化配置 | 借鉴插件化和场景切换思想，避免引入重型 Isaac 依赖 |
| AirSim | Unreal 视觉、API 控制、PX4/ArduPilot SIL/HIL | 仅作为 UE 视觉桥接参考，不作为唯一方案 |

因此当前技术路线确定为：

```text
MWORKS/Sysplorer/Sysblock:
  dynamics + controller + planner + disturbance + metrics truth

Syslab/Python:
  batch orchestration + metrics + evidence packaging + UDP playback

Unreal/UE5:
  render-only scene + material + camera + radar sector + video capture

Future export:
  C/C++ controller wrapper + ROS2/Gazebo/PX4 adapter template
```

不能让外部渲染器、ROS 节点或 UE 蓝图成为控制器真实性来源。若 UE 画面和 MWORKS 指标冲突，以 MWORKS raw/native result、metrics 和 event_log 为准，UE 只作为人工审查和视频表达。

### 4.5.1 外部可视化渲染创新

当前不再把 Gazebo 作为近期主线。近期视频展示采用“MWORKS/Sysplorer 负责真实闭环仿真，UE5/Unreal 负责视觉表达”的解耦方案。UE5 只作为显示层，不参与动力学、控制、路径规划、碰撞验收或指标计算。MATLAB UAV Toolbox / Simulink Coder 的“模型到代码再到 Gazebo/外部仿真”能力作为后续工程化出口保留，当前不阻塞 UE5 渲染主线。

外部渲染必须采用 **asset-first** 路线。此前从零堆盒子、立柱和简单材质只能作为调试场景，不足以支撑最终视频质量。正式 UE5 场景应优先复用成熟场景和模型资产：

1. 本地 `references/Sunray/simulation/sunray_simulator/models` 中已有 Sunray150/Mid360、Gazebo/SDF 场景、AWS RoboMaker residential/retail、树、房屋、窗框、门框、目标区、地形等资产；
2. 本地 `*.world` 文件可作为场景布局参考，例如 planning_test、outdoor、vins_house、yundrone_cup、competition map 等；
3. RflySim/CopterSim 和 RflyExpCode 公开仓库主要提供 Simulink/MAVLink/HIL/实验接口参考，目前未发现完整 UE 场景资产工程；若要复用 RflySim3D/RflySimUE 场景，应优先检查用户本机安装目录或官方资产包，而不是只克隆公开代码仓库；
4. UE Marketplace 或其他开源 UE 场景可作为 P2 视觉升级，但必须先检查许可证、文件大小、贴图依赖、缩放比例、碰撞代理和性能。

因此 UE5 工作流从“生成几何”调整为：

```text
场景/模型资产盘点
  → SDF/world/mesh 解析
  → scene_asset_registry
  → Unreal 导入、材质、碰撞代理、跟随相机
  → MWORKS 状态流驱动
  → 视频审查
```

手工生成的障碍物和栅格只保留为规划真值、碰撞调试和局部感知叠加，不作为最终视觉主体。

RflySim 安装完成后，优先检查 `RflySim3D` / `RflySimUE` / `RflySimUE5` 是否包含可编辑的 `.uproject`、`Content/`、`.umap`、材质、网格、插件源码和通信示例。如果只有打包后的可执行文件或 `.pak`，则只能作为视觉目标和接口参考，不能直接把其场景资产纳入仓库。任何 RflySim 资源进入本项目之前，必须先记录许可证、来源路径、文件大小、可编辑性、坐标系、材质依赖和碰撞代理。

当前最可落地的视觉资产来源不是公开 RflySim 仓库，而是本地 `references/Sunray/simulation/sunray_simulator` 已有的 Gazebo/SDF/DAE/PNG 资产。优先把 `*.world` 和 `model.sdf` 解析成 `scene_asset_registry`，再导入 UE5，而不是继续在 UE 中手搓低质量盒子场景。RflySim 的价值主要体现在“MWORKS/Simulink 状态流驱动外部 3D 引擎”的架构、UDP/共享内存通信和多机场景组织方式。

若 RflySim 下载或授权暂时不可用，备选调研路线不应转回 Gazebo 主线，而是继续保持“外部渲染只读”架构：

| 备选平台 | 采用方式 |
|---|---|
| Cosys-AirSim / Colosseum | 参考 Unreal 插件、API、传感器、相机和状态流组织方式 |
| CARLA-Air / CARLA | 参考高质量 UE 城市场景和道路/建筑资产组织方式；只在资产容易复用时采用 |
| AirSim | 参考成熟 Unreal API 和相机/分割/天气接口；因上游归档，不作为主依赖 |
| Flightmare / FlightGoggles | 参考物理和渲染解耦、敏捷飞行门框场景表达；不直接切换到 Unity 主线 |
| Pegasus Simulator | 参考多机/PX4/传感器架构；Isaac Sim 依赖过重，不作为当前路线 |
| XTDrone / RotorS | 参考 ROS/PX4 多机组织和接口命名；不作为视频渲染路线 |

因此后续不需要一次性下载所有仿真平台。只有当某个平台能提供明确价值时再抓取对应仓库：UE 插件/API 看 Cosys-AirSim 或 Colosseum，城市级 UE 场景看 CARLA-Air/CARLA，门框敏捷飞行表达看 Flightmare/FlightGoggles，ROS/PX4 多机组织看 XTDrone/RotorS。

外部渲染层需要解决 Sysplorer 原生动画难以稳定处理的问题：

1. **无人机与背景上色**：Sunray150 机体、桨叶、传感器、障碍物、地面、轨迹和安全区域在渲染器内使用独立材质，不再依赖 Sysplorer 大量 `Shape` 组件调色。
2. **雷达扫描表达**：Mid360 抽象扫描范围由状态流驱动，显示前向扇形、近距原色区域、远距弱化区域和已感知障碍高亮；未感知区域不参与规划显示。
3. **跟随相机与视频录制**：外部渲染器提供跟随相机、固定全景相机、俯视相机和局部第一视角，避免人工拖动 Sysplorer 视角导致卡顿。
4. **数据真实性**：所有位置、姿态、参考轨迹、局部计划、障碍显示状态和事件标记均来自 MWORKS raw/native result 或实时 TCP/UDP 状态流，禁止外部渲染器自行补轨迹或改结果。

场景系统采用 `Scenario Profile` 抽象，而不是为每个展示目标单独硬编码一个模型。Profile 由以下对象组成：

```yaml
scenario_profile:
  world_geometry: map / obstacle_field / walls / gates / terrain
  mission_route: start / goal / waypoint / gate_sequence
  planner_profile: waypoint / astar / rrt_star / ego_inspired / min_snap / bspline
  controller_profile: pid / linear_mpc / nmpc / indi / l1 / safety_filter / fault_allocator
  disturbance_profile: wind / gust / mass / inertia / motor_efficiency / sensor_noise
  render_profile: sysplorer_native / unreal_offline / unreal_realtime
  evaluation_spec: metrics / event_log / manual_review / video_clip
```

这样斜框穿越、自主避障、风扰鲁棒、旋翼退化和多机编队都使用同一套配置入口，只替换 Profile，而不是复制模型和脚本。

推荐分两步实现：

```text
step1_offline_playback:
  MWORKS raw.csv / replay.json
    -> UDP/TCP frame stream
    -> Unreal receiver
    -> UAV pose / reference / local plan / radar sector / map material

step2_realtime_bridge:
  Sysplorer running model
    -> state publisher at 20-50 Hz
    -> Unreal receiver
    -> synchronized review and recording
```


#### 4.5.2 模型到外部仿真/代码生成出口

该功能放在 UE5 视频展示之后实施，不作为当前单机闭环与 UE5 渲染的前置条件。目标是学习 MATLAB/Simulink 的工具箱式工作流：用户在实验软件中选择控制器和场景后，可以从 MWORKS.Sysblock/等价控制器生成标准 C/C++ 控制器接口，再生成 ROS2/Gazebo/PX4 或其他外部仿真适配模板。

推荐分阶段验收：

1. **控制器接口冻结**：统一 `QuadState`、`QuadReference`、`QuadCommand`、`QuadEvent` 等结构体，保证 MWORKS、C++、UE5、后续 ROS2/Gazebo 适配器使用同一字段语义。
2. **C/C++ 导出一致性测试**：同一输入序列下，导出控制器输出与 MWORKS raw CSV 控制输出在容差内一致。
3. **外部仿真适配模板**：生成 ROS2 node / Gazebo plugin / PX4 offboard adapter 的骨架代码，但不把 Gazebo 调参作为当前比赛主线。
4. **部署证据分级**：C++ 一致性测试可作为工程化证据；Gazebo/PX4 运行结果只有真实跑通并通过指标检查后，才能进入附加展示，不替代 MWORKS/Sysplorer 主证据。

现阶段优先使用 DeviceDrivers 或项目 UDP bridge 把 MWORKS 状态流送入 UE5。ROS/rosbridge 仅作为无人船资料中的通信模式参考，不引入完整 ROS 导航栈。

### 4.6 交互式实验配置与算法组合创新

最终作品需要提供类似 MATLAB App Designer / UAV Toolbox / Simulink 参数面板风格的交互式实验软件，暂定名为 `Quadrotor Experiment Studio`。该模块不是 QGroundControl/MAVLink 地面站，也不是 Gazebo/PX4 SITL 主线；它只作为本项目的实验配置、仿真编排、日志分析、UE5 渲染控制和证据审查入口。GUI 不替代 MWORKS.Sysplorer/Sysblock 模型本身，而是生成标准 `scenario.yaml`、控制器参数、规划器参数、批量运行任务和渲染配置。若接入 UE5，该 GUI 只负责选择渲染 preset、启动/停止状态流和打开录屏审查，不让 UE5 反向修改控制器或规划器。后续 C++/ROS2/Gazebo 导出功能也必须作为独立导出向导存在，不能混入当前控制证据链。

核心能力：

1. **算法组合选择**：可选择轨迹生成、路径规划、位置控制、姿态控制、增强模块、鲁棒扰动和多机编队配置。
2. **参数可视化**：显示起点、终点、地图模式、扰动强度、控制器频率、传感器频率、约束阈值和当前质量门。
3. **可复现实验生成**：随机障碍物只随机位置，数量固定，使用 seed 固化；GUI 生成的所有配置必须落盘。
4. **仿真编排**：调用现有 MWORKS MCP / Syslab / Python 工作流，运行单场景或批量矩阵，不直接手工改模型源码。
5. **日志分析器**：读取 raw CSV、metrics JSON/CSV、event_log、MCP log、native_result manifest 和人工审核清单，定位模型检查、授权、仿真、质量门和 GUI 审查问题。
6. **指标面板**：读取 metrics JSON/CSV 和人工审核清单，展示 RMSE、最大误差、稳态误差、控制能量、安全距离、编队误差和鲁棒性保持率等指标。
7. **地图渲染审查**：规划地图可以保持高精度栅格，Sysplorer 动画只显示低复杂度合并几何和局部感知高亮；高质量视频渲染交给外部 Unreal 显示层。任何显示方案必须经人工审核；若效果差或拖慢/破坏求解器，立即回退到当前稳定的低复杂度审查方案。

## 8. 参考算法路线

| 方向 | 借鉴点 | 本项目定位 |
|---|---|---|
| Minimum Snap | 四旋翼平滑轨迹、速度/加速度连续 | P2 轨迹平滑或离线参考生成 |
| EGO-Planner / Fast-Planner | ESDF-free、B-spline、局部优化思想 | 只借鉴轻量思想，不完整移植 ROS 栈 |
| INDI | 角加速度反馈、降低模型依赖 | P1 姿态内环增强 |
| MPC/NMPC | 约束跟踪、预测优化 | P1/P2 外环增强，保留线性 MPC 回退 |
| L1 adaptive control | 快速扰动补偿思想 | 采用 L1-inspired 残差估计与低通补偿 |
| CBF / Safety Filter | 安全关键约束保护 | P1/P2 安全过滤，初赛可用裁剪式限幅 |
| MCP | 模型查询、仿真调用、结果读取 | P2 自动化验证辅助，不作为控制算法创新 |
