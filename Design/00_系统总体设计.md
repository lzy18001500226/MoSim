# 00 系统总体设计

## 1. 项目定位

项目名称建议：

**面向复杂任务场景的四旋翼无人机自适应鲁棒位姿控制与智能仿真验证系统**

核心口径：

> 以 MWORKS 四旋翼模型为基础，围绕“官方 PID baseline → 改进 PID → PID-INDI/MPC-INDI → 扰动补偿”的逐级消融路线，完成复杂轨迹跟踪、风扰/质量摄动鲁棒性验证和量化评估；在主线稳定的基础上扩展安全过滤、故障注入、路径规划、编队与 Syslab/MCP 自动化评估。

## 4. 关键创新点

### 4.1 自适应鲁棒位姿控制

1. **统一控制链路**：MPC/NMPC 外环、INDI 姿态内环、L1-inspired 加速度残差补偿、安全过滤和故障重构串成一条可替换控制链。
2. **扰动识别与模式切换**：根据速度/加速度残差、姿态残差、电机效率 eta 和传感器噪声指标，切换 `NORMAL`、`WIND_REJECTION`、`MASS_ADAPTATION`、`FAULT_TOLERANT`、`SAFETY_PROTECTION` 和 `EMERGENCY_LAND`。
3. **逐级消融验证**：PID → 改进 PID → PID-INDI/线性 MPC-INDI → NMPC-INDI → +L1-inspired → +Safety/Fault，每个增强模块必须有独立对比指标。

### 4.2 可跟踪性感知规划创新

1. **Trackability-aware Trajectory Planning**：规划轨迹不仅满足几何避障，还检查速度、加速度、jerk、倾角、推力余量和电机饱和风险。
2. **控制反馈修正轨迹**：若仿真结果显示跟踪误差或饱和比例过高，自动放大时间分配、降低参考速度或增加转弯半径。
3. **轻量 EGO-inspired 局部优化**：不强依赖完整 ROS/ESDF，只用局部障碍物几何距离构造碰撞代价和安全引导路径。

### 4.3 故障诊断与安全降级创新

1. **故障链路闭环**：故障注入 → 残差检测 → 故障分类 → 控制分配重构 → 安全降级 → 指标评估。
2. **分级容错**：轻度故障继续任务，中度故障启用重构，重度故障降级返航或安全降落。
3. **事件日志驱动展示**：每次故障、模式切换、安全保护和降级动作都记录到 event_log，支撑报告和视频复现。

### 4.4 多机协同任务创新

1. Leader-Follower 编队；
2. 多队形配置和平滑切换；
3. 狭窄通道自动队形收缩；
4. 机间安全距离约束；
5. Leader 规划绕障 + Follower 可行性检查；
6. Leader 故障或 Follower 异常时的队形降级策略。

### 4.5 智能仿真评估创新

1. 多场景扰动测试矩阵；
2. 风扰、质量摄动、电机效率下降、传感器噪声；
3. Syslab 批量实验与自动指标；
4. 健康度评分：tracking、robustness、safety、energy、smoothness、fault_tolerance；
5. 数据驱动三维回放：读取 MWORKS 导出的 CSV/JSON，生成真实仿真数据对应的视频素材。

### 4.5.0 外部仿真平台对标结论

近期调研对象包括 RflySim、MATLAB UAV Toolbox、Flightmare、RotorS、XTDrone、Pegasus Simulator 和 AirSim。结论不是照搬其中任一平台，而是吸收它们的架构分工：

| 参考平台 | 可借鉴点 | 本项目采用方式 |
|---|---|---|
| RflySim | MBD 主线、PX4/Simulink/DLL/CopterSim、SIL/HIL、UE 场景、UDP/共享内存、多机集群测试 | 只作为机制对标、协议参考和可授权资产迁移来源；最终渲染运行时采用项目自有 UE5 工程 |
| MATLAB UAV Toolbox | Scenario 配置、传感器仿真、Unreal 场景、自定义场景、代码生成出口 | 设计 `Quadrotor Experiment Studio`，统一生成 scenario/controller/planner/render 配置 |
| Flightmare | 物理引擎和渲染引擎解耦，Unity/渲染层只负责场景和传感器输出 | MWORKS 输出真实状态，UE5 读取 raw/native/realtime frame，不回写控制结论 |
| RotorS / XTDrone | ROS/Gazebo 下的传感器、控制器、消息接口和多机组织方式 | 借鉴接口分层，不把 ROS/Gazebo 作为当前比赛主证据链 |
| Pegasus Simulator | PX4/ROS2/Isaac Sim、多机和 GUI 化配置 | 借鉴插件化和场景切换思想，避免引入重型 Isaac 依赖 |
| AirSim | Unreal 视觉、API 控制、PX4/ArduPilot SIL/HIL | 仅作为 UE 视觉桥接参考，不作为唯一方案 |

因此当前技术路线确定为：

```text
MWORKS/Sysplorer/Sysblock:
  dynamics + controller + planner + disturbance + metrics truth

Syslab/Python:
  batch orchestration + metrics + evidence packaging + UDP playback

Unreal/UE5:
  project-owned render-only scene + material + camera + radar sector + video capture

Future export:
  C/C++ controller wrapper + ROS2/Gazebo/PX4 adapter template
```

不能让外部渲染器、ROS 节点或 UE 蓝图成为控制器真实性来源。若 UE 画面和 MWORKS 指标冲突，以 MWORKS raw/native result、metrics 和 event_log 为准，UE 只作为人工审查和视频表达。

### 4.5.0.1 高效实时架构基准：Gazebo/RflySim 对标

Gazebo 和 RflySim 低延迟的共同点不是“渲染更强”，而是把求解、控制、传感器、渲染和 GUI 分成不同进程/模块：

| 机制 | Gazebo 做法 | RflySim 做法 | 本项目采用方式 |
|---|---|---|---|
| 求解与渲染解耦 | `server` 运行物理/传感器系统，`client` 只做 GUI | CopterSim/PX4/外部 DLL 与 RflySim3D 分进程 | MWORKS/Sysplorer 是真值求解端，UE5 是只读渲染端 |
| 高频通信 | Gazebo Transport 发布 pose/sensor/command | 固定 UDP 端口、二进制结构体、共享内存图像/点云 | 使用固定结构状态帧，避免 JSON 大包进入实时闭环 |
| 独立频率 | physics step、sensor update、GUI FPS 分开 | 控制、视觉传感器、RflySim3D FPS 分开 | 控制/建图/规划/渲染分别限频和超时 |
| 轻量批处理 | headless server 可脱离 GUI | `CopterSimNoUI`、低 FPS、大集群独立运行 | 指标批处理不依赖 UE5；视频审查才打开渲染 |
| 可选同步 | lockstep 用于一致性，牺牲实时率 | 通过时间戳/心跳/端口分发维持一致性 | 录制可用 lockstep；日常仿真默认异步丢弃过期帧 |

因此项目实时架构固定为：

```text
MWORKS/Sysplorer authoritative solver
  -> StateBroadcaster @20-50 Hz
  -> SensorMapWorker @20 Hz minimum
  -> PlannerWorker @5-20 Hz
  -> ControllerWorker @20-50 Hz
  -> UE5 RenderClient @30-60 FPS
```

关键约束：

1. 控制器和安全过滤至少按 `20 Hz` 工作，目标 `50 Hz`；局部建图至少 `20 Hz`，传感器/点云输入可 `20-30 Hz`；UE5 渲染目标 `30-60 FPS`。
2. UE5 不进入控制器求解环。渲染卡顿只能影响视频，不允许影响 MWORKS 指标、控制输出或 event_log。
3. 每个实时包必须包含 `seq`、`sim_time`、发送时间戳、pose、velocity、attitude、motor/fault/mode、reference、local plan 摘要和质量标志。
4. 超时策略必须明确：传感器过期则保持上一帧并标记 stale；规划超时则复用上一条仍安全轨迹或减速悬停；控制超时则触发 Safety Filter/Hold；渲染超时直接丢帧。
5. RflySim 不作为最终渲染运行时。它只用于学习 UDP/共享内存/多进程分工、车辆参数数据库、Mid360/点云接口和场景资产组织。经用户授权后，可把可编辑地图、模型、材质、XML 或参数迁移到项目自有 UE5 工程，再重命名、重材质、重碰撞代理和重场景逻辑。
6. 地图真值不能从 RflySim 运行时偷读给规划器。最终数据结构应落到项目自己的 `render_world`、`world_geometry.primitives`、`collision_proxy` 和 `planner_known_map` 中。

### 4.5.1.1 RflySim/UE 场景系统架构

后续视觉展示不再局限于 MWORKS/Sysplorer 原生动画。最终外部场景层采用项目自有 UE5 渲染器，承担高质量地图、材质、相机、雷达点云显示和视频录制；MWORKS 仍承担控制器、动力学、轨迹、扰动和指标真值。RflySim3D 只作为参考运行时和资产迁移来源，不作为最终交付视频的必需依赖。

场景 Profile 分为以下几类：

| Profile | 场景来源 | 典型任务 | 说明 |
|---|---|---|---|
| `dense_forest` | 开源/可用 UE 森林、密林、山地资产或 RflySim 可用场景 | 密集障碍避障、局部感知、路径重规划 | 重点验证未知地图下的规划能力，不把全局地图提前给规划器 |
| `maze_building` | 自建迷宫或 RflySim/UE 建筑室内场景 | 狭窄通道、墙体遮挡、局部地图 | 验证雷达不能穿墙、局部规划和安全距离 |
| `old_factory` | RflySim `OldFactory` 或自有 UE 工厂场景 | 建筑/管道/墙体穿越 | 当前已确认本机 RflySim 能加载该场景并采集 Mid360 点云 |
| `park_patrol` | RflySim `NeighborhoodPark`、UE 公园/社区资产 | 巡检、物流、树木避障 | 适合答辩视频中的真实业务场景 |
| `gate_ring_indoor` | RflySim `VisionRing`、`RobotMissionChallenge`、`MatchScene2025` 或自建室内场景 | 斜穿框、穿环、高速姿态控制 | 重点展示姿态控制、轨迹跟踪和相机视角 |
| `open_grass_wind` | RflySim `Grasslands` / `3DDisplay` / 自建开阔草地 | 风扰、阵风、电机效率退化 | 场景简单，突出控制鲁棒性 |

每个 Profile 必须有两套地图表达：

```text
render_world:
  project-owned UE5 可见真实地图、材质、树木、墙、地形、框、环

planner_known_map:
  起始为空或局部已知；只由 Mid360/抽象传感器按范围、FOV、遮挡逐步更新
```

这样视频中可以显示“真实世界”和“无人机当前已知点云/局部地图”两个视图。真实地图界面用于观众理解环境；点云/局部地图界面用于证明规划器没有偷看未探索区域。若采用单窗口展示，则真实地图保留正常材质，已感知区域用扇形/点云/高亮叠加，未感知区域只能弱化显示，不能作为规划输入。

随机化策略只在仿真开始前执行：

```text
select_profile
  -> choose seed
  -> randomize obstacle/building/gate relative transforms
  -> save scenario_profile.yaml
  -> run simulation with local sensing only
```

随机位置必须落盘并可复现。GUI 可以提供“随机生成建筑物/障碍物位置”按钮，但生成后需要固化 seed、地图对象 ID、包围盒和材质，不允许仿真中途修改真值地图，除非该场景明确为动态障碍物测试。

延迟与卡死保护按外部仿真平台思路设计：

1. 控制器主循环和渲染循环分离，渲染卡顿不影响控制器证据；
2. 规划器设置最大求解时间预算，例如 20 Hz 下单步预算不超过 50 ms，超时则沿用上一条安全局部轨迹或进入 Hold/Safety Filter；
3. 点云处理、占据栅格、路径优化和渲染 actor 更新使用不同频率，不把所有对象放进同一个求解器；
4. 高质量地图使用视觉 mesh，规划使用简化碰撞代理/占据栅格；
5. 如果 NMPC/QP/Safety Filter 超时，event_log 必须记录 `planner_timeout`、`controller_timeout` 或 `safety_hold`。

多机扩展仍使用同一套 Profile，只增加 `uav_count`、队形、机间距离和通信延迟。密林、迷宫、旧工厂、公园、穿环和风扰场景都应支持从 1 架扩展到 3-5 架，但 P1 先完成单机闭环，P2 再扩展 Leader-Follower 编队。

### 4.5.1 外部可视化渲染创新

当前不再把 Gazebo 作为近期主线，也不把 RflySim3D 作为最终渲染主线。近期视频展示采用“MWORKS/Sysplorer 负责真实闭环仿真，项目自有 UE5 工程负责视觉表达”的解耦方案。外部渲染只作为显示层，不参与动力学、控制、路径规划、碰撞验收或指标计算。MATLAB UAV Toolbox / Simulink Coder 的“模型到代码再到 Gazebo/外部仿真”能力作为后续工程化出口保留，当前不阻塞视觉展示路线。

外部渲染必须采用 **asset-first** 路线。此前从零堆盒子、立柱和简单材质只能作为调试场景，不足以支撑最终视频质量。正式 UE5 场景应优先复用成熟场景和模型资产：

1. 本地 `references/Sunray/simulation/sunray_simulator/models` 中已有 Sunray150/Mid360、Gazebo/SDF 场景、AWS RoboMaker residential/retail、树、房屋、窗框、门框、目标区、地形等资产；
2. 本地 `*.world` 文件可作为场景布局参考，例如 planning_test、outdoor、vins_house、yundrone_cup、competition map 等；
3. RflySim/CopterSim 和 RflyExpCode 公开仓库主要提供 Simulink/MAVLink/HIL/实验接口参考；本机 `D:\PX4PSP` 中的 RflySim3D/UE 内容可作为资产迁移候选，但迁移后必须进入项目自有 UE5 工程并重新建立材质、碰撞代理、命名和场景配置；
4. UE Marketplace 或其他开源 UE 场景可作为 P2 视觉升级，但必须先检查许可证、文件大小、贴图依赖、缩放比例、碰撞代理和性能。

因此视觉渲染工作流已经再次收敛为“真实资产优先”：

```text
真实 UE/Fab/Epic/open-source 场景资产
  → 地图本体人工审核
  → 资产注册 / 坐标与尺度校准
  → 碰撞与规划真值代理
  → MWORKS 状态流驱动
  → 视频审查
```

旧的栅格、STL、低质量盒子、RflySim 直接挂载、YunZong/Sunray
primitive 重建和 metadata-only migration staging 路线均已退役。它们只能作为历史经验或
机制参考，不作为最终视觉路线。当前保留的 Unreal 工程只承担两个职责：

## 5.1 完整四旋翼系统组成

当前单机主线使用 `sunray150_with_mid360` 作为完整四旋翼系统背景。系统级闭环的核心是机体动力学、电机/旋翼、控制器、扰动、安全状态和结果导出；CUAV、Mid360、ORIN NX 图片只作为图形化仿真和答辩素材参考，不作为新增实物仿真部件。

| 层级 | 模块 | 当前实现 | 后续扩展 |
|---|---|---|---|
| 机体结构 | Sunray150 机架、四电机、四桨 | `QuadrotorModel.Mechanics.QuadChassis`，Sunray150 STL，1.0 kg 等效质量 | 进一步按实物手册细化电池/载荷质量分布 |
| 执行机构 | 电机、桨叶、旋翼升力 | 电机转速输入、升力系数、电机速度传感器 | 电机效率、响应延迟、饱和和温升模型 |
| 飞控/定位背景 | PX6C / CUAV V6X / GPS | 当前不改变官方物理模型；仅在模式管理和安全逻辑中抽象健康状态 | 传感器冗余、Offboard loss、Return/Land 状态机 |
| 环境感知背景 | Livox Mid360 | 当前不改变官方物理模型；规划层按 20 Hz 局部栅格接口建模 | 量程、FOV、噪声、局部障碍更新 |
| 机载计算背景 | ORIN NX 级计算平台 | 当前不改变官方物理模型；用于解释规划、安全监督和多机通信的计算平台 | 后续承载路径规划、局部地图、安全过滤和多机通信 |
| 控制软件 | AWFF / INDI / L1 / MPC / Safety | 已有 Sysblock 控制器和包装实验 | 与规划、模式管理、故障诊断统一接口 |
| 任务软件 | 轨迹、规划、返航、降落 | 已有官方轨迹、返航/降落实验 | 单机避障、多机编队、动态重规划 |

实现边界：

```text
必须真实参与仿真闭环：
  机体动力学、电机/旋翼、传感器状态输出、控制器、电机指令、结果导出

  V6X/PX6C 飞控硬件、GPS/GNSS、Mid360 局部栅格更新节拍、ORIN NX 计算平台
```

## 8. 参考算法路线

| 方向 | 借鉴点 | 本项目定位 |
|---|---|---|
| Minimum Snap | 四旋翼平滑轨迹、速度/加速度连续 | P2 轨迹平滑或离线参考生成 |
| EGO-Planner / Fast-Planner | ESDF-free、B-spline、局部优化思想 | 只借鉴轻量思想，不完整移植 ROS 栈 |
| INDI | 角加速度反馈、降低模型依赖 | P1 姿态内环增强 |
| MPC/NMPC | 约束跟踪、预测优化 | P1/P2 外环增强，保留线性 MPC 回退 |
| L1 adaptive control | 快速扰动补偿思想 | 采用 L1-inspired 残差估计与低通补偿 |
| CBF / Safety Filter | 安全关键约束保护 | P1/P2 安全过滤，初赛可用裁剪式限幅 |
| MCP | 模型查询、仿真调用、结果读取 | P2 自动化验证辅助，不作为控制算法创新 |
