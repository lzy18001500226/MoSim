# 04 安全约束、故障注入与容错控制详细设计

## 1. 设计目标

安全和故障模块用于保证控制器输出可执行、飞行过程不越界、多机不碰撞，并验证系统在执行器故障下的鲁棒性。

---

## 1.1 功能拆分

安全与故障功能拆成 4 个独立模块，避免实现时互相绑定：

| 模块 | 作用 | 输入 | 输出 | 优先级 |
|---|---|---|---|---|
| safety_filter | 对姿态、推力、速度、高度、障碍距离和机间距离进行约束保护 | raw command / state / limits | safe command | P1 |
| fault_injector | 按场景配置注入电机效率下降、响应延迟或饱和 | motor_cmd / fault_config | motor_actual / eta | P1 |
| fault_detector | 根据残差判断是否发生故障 | state / motor / residual | fault_flag / fault_type | P2 |
| fault_reallocator | 根据 eta 或故障估计重构控制分配 | desired wrench / eta | motor_cmd_reallocated | P2 |
| emergency_manager | 根据故障等级和安全状态执行返航、降落或安全终止 | task_mode / state / limits | emergency_ref / event_log | P2 |

初版可直接由场景配置给定 `eta`，先完成故障注入和对比实验；故障检测作为增强功能，不阻塞 Safety 和 Fault Reallocation。

推荐链路：

```text
controller
  → safety_filter
  → fault_reallocator
  → fault_injector
  → motor/plant
  → residual_monitor
  → task_mode_manager
  → emergency_manager
```

## 2. Safety Filter 类型

### 2.1 控制指令过滤

```text
raw command → clamp/project → safe command
```

约束：

```text
|roll| <= roll_max
|pitch| <= pitch_max
T_min <= T <= T_max
u_min <= u_i <= u_max
```

### 2.2 轨迹安全检查

```text
trajectory → velocity/acc/jerk/collision check → safe trajectory
```

### 2.3 编队安全检查

```text
multi-UAV references → inter-distance check → adjusted references
```

## 3. 基础安全约束

| 类别 | 约束 |
|---|---|
| 姿态 | roll/pitch/yaw rate 限制 |
| 推力 | 总推力、电机推力限制 |
| 速度 | 最大速度 |
| 加速度 | 最大加速度 |
| 高度 | 最低高度 |
| 障碍物 | 最小障碍距离 |
| 编队 | 最小机间距离 |
| 控制平滑 | 最大控制变化率 |

## 4. 裁剪式安全过滤

```pseudo
roll_ref = clamp(roll_ref, -roll_max, roll_max)
pitch_ref = clamp(pitch_ref, -pitch_max, pitch_max)
thrust = clamp(thrust, T_min, T_max)

if z < z_min:
    z_ref = z_min + margin
```

优点：简单稳定。
缺点：可能破坏最优性。

---

## 5. QP 投影式安全过滤

```text
u_safe = argmin ||u - u_raw||²
s.t. constraints
```

可用于：

1. 推力限幅；
2. 倾角限幅；
3. 避障速度约束；
4. 机间距离约束。

---

## 6. CBF-inspired 设计

障碍物安全函数：

```text
h(p) = ||p - p_obs||² - d_safe²
```

安全条件：

```text
h(p) >= 0
```

CBF 约束：

```text
h_dot + α h >= 0
```

构造 QP：

```text
min ||u-u_raw||²
s.t. h_dot + αh >= 0
```

初赛不一定实现完整 CBF，可写为“CBF-inspired 安全过滤”。

## 7. 执行器故障模型

### 7.1 电机效率下降

```text
f_i_actual = η_i f_i_cmd
```

典型：

```text
η = [1.0, 0.7, 1.0, 1.0]
```

### 7.2 电机响应延迟

```text
f_dot = (f_cmd - f_actual) / τ_m
```

故障时：

```text
τ_m_fault = 2τ_m
```

### 7.3 电机饱和

```text
f_i = clamp(f_i_cmd, f_min, f_max)
```

## 8. 故障检测

### 8.1 残差

```text
r = ω_dot_meas - ω_dot_pred
```

或：

```text
r_a = a_meas - a_model
```

### 8.2 阈值

```pseudo
if norm(r) > threshold for N samples:
    fault_detected = true
```

### 8.3 扰动/故障分类

| 类型 | 主要特征 | 模式 |
|---|---|---|
| 恒定风 | 水平加速度残差持续偏置，姿态残差较小 | WIND_REJECTION |
| 阵风 | 残差周期或脉冲变化 | WIND_REJECTION |
| 质量变化 | z 向残差突变，投递事件同步出现 | MASS_ADAPTATION |
| 电机效率下降 | 角加速度残差和某电机 eta 异常 | FAULT_TOLERANT |
| 传感器噪声 | 高频残差增大但均值不明显偏移 | SAFETY_PROTECTION |

分类伪代码：

```pseudo
if eta_min < eta_threshold:
    fault_type = MOTOR_EFFICIENCY_DROP
elif delivery_event and abs(acc_residual_z) > mass_threshold:
    fault_type = MASS_CHANGE
elif norm(acc_residual_xy_mean) > wind_threshold:
    fault_type = WIND_DISTURBANCE
elif residual_variance > noise_threshold:
    fault_type = SENSOR_NOISE
else:
    fault_type = NONE
```

## 9. 控制分配重构

正常：

```text
y = Bf
f = B^{-1}y
```

故障：

```text
B_fault = B diag(η)
f = pinv(B_fault)y
```

当前已落地的最小实现为已知效率退化控制分配补偿：`AWFF_L1FaultAllocationControllerEquation_Sysblock` 在 `rotor1_efficiency=0.85` 条件下对 1 号电机指令施加混合补偿：

```text
gain_1 = 1 + blend * (1 / eta_1 - 1)
u_1 = saturate(gain_1 * u_1_raw)
```

该实现属于“已知故障参数下的控制分配重构”。进一步的在线估计雏形已经落地到 `AWFF_L1OnlineFaultAllocationControllerEquation_Sysblock`：控制器不直接读取真实 `eta=0.85`，而是由横向残差签名生成低通估计 `eta_hat`，再用 `eta_hat` 进入同一分配补偿链路：

```text
signature_1 = max(( -x_error_filter + y_error_filter ) / 2 - deadband, 0)
eta_target = clamp(1 - k_eta * signature_1, eta_min, eta_max)
dot(eta_hat) = (eta_target - eta_hat) / T_eta
gain_1 = 1 + blend * (1 / eta_hat - 1)
u_1 = saturate(gain_1 * u_1_raw)
```

当前 `Example1Rotor1Loss15L1OnlineFaultAllocationSysblockClosedLoop` 已在 1 号旋翼 85% 效率退化场景中通过真实 Sysplorer MCP 50 s 仿真和质量门，`eta_hat` 末值约 `0.904`，RMSE 相比 `awff_sysblock` 降低 `29.363%`。该结果只能表述为“单旋翼效率退化在线估计雏形”，还不能扩展声明为任意旋翼故障隔离。

多旋翼故障隔离雏形已经落地到 `AWFF_L1MultiFaultIsolationControllerEquation_Sysblock`。该控制器输出 `eta_hat1..4` 和 `fault_index`，并按四个升力增益映射进行诊断：

```text
rotor_1 -> quadChassisTest17_1.gain2.k
rotor_2 -> quadChassisTest17_1.gain3.k
rotor_3 -> quadChassisTest17_1.gain4.k
rotor_4 -> quadChassisTest17_1.gain5.k
```

当前实现使用首次可靠识别锁存策略，适用于持续单旋翼效率退化：

```text
fault_index = latch(argmax(signature_i))
if max(signature_i) - second_max(signature_i) > margin
```

`Example1Rotor1Loss15L1MultiFaultIsolationSysblockClosedLoop` 已在 rotor1 85% 退化场景完成真实 Sysplorer MCP 50 s 仿真并通过质量门，`5-50 s` 内 `fault_index=1` 正确率为 `100%`。该证据说明多旋翼隔离结构和诊断输出已经接入整机闭环；完整四旋翼隔离还需要补 rotor2/3/4 退化场景。

带约束：

```text
min ||B_fault f - y||² + λ||f||²
s.t. f_min <= f <= f_max
```

## 10. 容错模式

```text
NORMAL
DISTURBANCE_REJECTION
SAFETY_PROTECTION
FAULT_TOLERANT
EMERGENCY_LAND
```

切换逻辑：

```pseudo
if motor_eta < 0.6:
    mode = EMERGENCY_LAND
elif motor_fault:
    mode = FAULT_TOLERANT
elif obstacle_distance < d_safe:
    mode = SAFETY_PROTECTION
elif wind > wind_threshold:
    mode = DISTURBANCE_REJECTION
else:
    mode = NORMAL
```

### 10.1 故障等级与降级策略

| 等级 | eta | 策略 | 验收口径 |
|---|---:|---|---|
| 轻度 | 0.9 | 继续任务，记录性能退化 | RMSE 和饱和比例可接受 |
| 中度 | 0.7 | 启用 fault_reallocator，对比有/无重构 | 最大误差或饱和比例下降 |
| 重度 | 0.5 | 不承诺继续完成任务，进入降级或 emergency_land | 保持可控下降或安全终止 |

重度故障不要作为“性能提升”主结论，只作为安全降级展示。

降级策略：

```pseudo
if eta_min >= 0.85:
    mode = NORMAL_OR_LIGHT_FAULT
elif eta_min >= 0.65:
    mode = FAULT_TOLERANT
elif eta_min >= 0.5:
    mode = DEGRADED_RETURN_OR_LAND
else:
    mode = EMERGENCY_LAND
```

### 10.3 应急管理器

应急管理器只在中重度故障或安全约束持续违规时介入。

策略：

| 策略 | 触发条件 | 输出参考 |
|---|---|---|
| continue_task | 轻度故障，误差可控 | 原参考轨迹 |
| slow_down_return | 中度故障，仍可稳定飞行 | 降速返航轨迹 |
| hover_and_land | 重度故障但姿态可控 | 当前点悬停后下降 |
| emergency_cutoff | 持续失稳或仿真安全终止 | 标记 failure，不做性能提升结论 |

伪代码：

```pseudo
if mode == FAULT_TOLERANT and error < return_threshold:
    reference = generate_return_home(v_safe)
elif mode == EMERGENCY_LAND and attitude_stable:
    reference = generate_vertical_land(z_rate_safe)
elif mode == EMERGENCY_LAND:
    status = failure
    write_event_log("emergency_cutoff")
```

### 10.4 safety_filter 实现规格

输入：

```text
thrust_ref
attitude_ref
state_bus
safety_limits
```

输出：

```text
thrust_safe
attitude_ref_safe
debug.constraint_violation
debug.safety_mode
```

P1 裁剪式实现：

```pseudo
roll_ref = clamp(roll_ref, -roll_max, roll_max)
pitch_ref = clamp(pitch_ref, -pitch_max, pitch_max)
thrust_ref = clamp(thrust_ref, thrust_min, thrust_max)

if state.z < z_min:
    thrust_ref = max(thrust_ref, hover_thrust + climb_margin)
    safety_mode = LOW_ALTITUDE_PROTECTION
```

P2 再加入障碍物/机间距离 QP 或 CBF-inspired 约束。

### 10.5 fault_injector 实现规格

输入：

```text
motor_cmd[4]
fault_config
time
```

输出：

```text
motor_cmd_actual[4]
eta[4]
fault_event
```

伪代码：

```pseudo
eta = [1, 1, 1, 1]
if time >= fault.start_time:
    eta = fault.eta

for i in 1..4:
    motor_cmd_actual[i] = eta[i] * motor_cmd[i]
```

事件日志：

```json
{
  "time": 12.0,
  "event": "motor_efficiency_drop",
  "motor": 2,
  "eta": 0.7
}
```

### 10.6 fault_reallocator 实现规格

输入：

```text
desired_wrench = [T, tau_x, tau_y, tau_z]
eta[4]
motor_limits
allocation_matrix
```

输出：

```text
motor_cmd_reallocated[4]
debug.allocation_error
debug.saturation_ratio
```

实现：

```pseudo
B_fault = B * diag(eta)
f_cmd = pinv(B_fault) * desired_wrench
f_cmd = clamp(f_cmd, f_min, f_max)
allocation_error = norm(B_fault * f_cmd - desired_wrench)
```

验收：

```text
motor_fault_eta70:
  +Fault Reallocation 的 max_error 或 saturation_ratio 低于 no Reallocation
heavy_fault_eta50:
  系统进入 DEGRADED_RETURN_OR_LAND 或 EMERGENCY_LAND，并记录 event_log
```
