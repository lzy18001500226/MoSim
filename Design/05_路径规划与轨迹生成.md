# 05 路径规划与轨迹生成详细设计

## 1. 定位

路径规划模块不是替代控制器，而是为控制器生成复杂任务轨迹。规划结果不仅要“几何上可走”，还要“控制器可稳定跟踪”：

```text
地图/障碍物/起终点
  → 路径规划
  → 轨迹平滑
  → 动态可行性检查
  → 可跟踪性评分
  → 当前控制器跟踪
  → 饱和/误差反馈修正轨迹
```

---

## 2. 规划算法池

### 2.1 预设航点

适合保底：

```text
start → waypoint1 → waypoint2 → goal
```

### 2.2 A*

```text
f(n)=g(n)+h(n)
```

适合栅格地图。
优点：确定、简单。
缺点：折线、不考虑动力学。

### 2.3 Dijkstra

无启发搜索，适合验证，不建议主用。

### 2.4 RRT

随机采样树：

```pseudo
sample
nearest
steer
collision_check
add
```

适合 3D 几何障碍。

### 2.5 RRT*

加入 rewiring，路径质量更好，但规划时间更长。

### 2.6 Informed RRT*

在找到初解后缩小采样区域，提高收敛效率。可作为高级选项。

### 2.7 Kinodynamic A*

状态包含速度：

```text
[x,y,z,vx,vy,vz]
```

动作是加速度：

```text
[ax,ay,az]
```

优点：更接近无人机真实可飞轨迹。
缺点：实现难度高。

### 2.8 人工势场 APF

```text
F = F_att + F_rep
```

适合局部避障、安全修正，不适合主规划器。

### 2.9 CHOMP/TrajOpt 思路

把轨迹作为优化变量：

```text
min smoothness + collision + dynamics
```

适合做局部轨迹优化。

### 2.10 EGO-inspired 局部优化

借鉴：

1. ESDF-free；
2. 碰撞轨迹与安全引导路径对比；
3. 局部障碍物信息；
4. B-spline 轨迹优化；
5. 动态不可行时延长时间。

不完整移植 ROS 包，只实现轻量思想。

### 2.11 Fast-Planner / FASTER / RAPTOR 设计借鉴

| 方法 | 可借鉴点 |
|---|---|
| Fast-Planner | 前端搜索 + B-spline 优化 |
| FASTER | 快速安全重规划、安全飞行思想 |
| RAPTOR | 多拓扑路径、感知约束 |
| EGO-Planner | ESDF-free 局部碰撞代价 |
| Minimum Snap | 四旋翼平滑轨迹 |

## 3. 轨迹平滑算法

### 3.1 Minimum Snap

优化四阶导数：

```text
min ∫ ||p''''(t)||² dt
```

适合四旋翼。

### 3.2 Polynomial Trajectory

每段：

```text
p(t)=c0+c1t+...+cnt^n
```

满足位置、速度、加速度连续。

### 3.3 B-spline

```text
p(t)=Σ P_i B_i,k(t)
```

优点：局部可控、适合优化。

### 3.4 Bezier

适合简单平滑展示。

### 3.5 时间分配

```text
T_i = max(||p_i-p_{i-1}||/v_ref, T_min)
```

若速度/加速度超限：

```text
T_i ← scale*T_i
```

## 4. 推荐组合

| 规划等级 | 组合 | 用途 |
|---|---|---|
| Plan-A | 手工航点 + Minimum Snap | 保底 |
| Plan-B | A* + Minimum Snap | 栅格地图 |
| Plan-C | RRT* + B-spline | 3D 几何障碍 |
| Plan-D | Kinodynamic A* + B-spline | 高级可行轨迹 |
| Plan-E | 局部已知 A* + EGO-inspired ESDF-free 优化 | 局部优化 |
| Plan-F | 在线重规划 | 冲高分 |

主实现路线：

```text
Plan-A: 手工航点 + Minimum Snap
Plan-B: A* + Minimum Snap
Plan-C: RRT* + B-spline
Plan-D: Trackability-aware A*/RRT* + time scaling
Plan-E: EGO-inspired ESDF-free local optimization
```

其中 Plan-B 作为保底主线，Plan-E 已迁入 `planning_open_blocks`：仍用局部已知 A* 提供拓扑引导路径，再用 EGO-Planner 思想的 ESDF-free 局部优化层处理平滑、导向保持和障碍安全距离。Kinodynamic A*、RRT* 和完整 B-spline 动力学优化仍作为后续扩展，不阻塞当前闭环证据。

### 5.2 3D 占据栅格

```text
resolution = 0.2 m
grid[i,j,k] = occupied/free
```

推荐地图配置：

```yaml
map:
  bounds:
    x: [-2, 12]
    y: [-4, 8]
    z: [0, 5]
  resolution: 0.2
  safety_margin: 0.3
  obstacles:
    - type: box
      min: [3, 2, 0]
      max: [5, 4, 3]
    - type: sphere
      center: [7, 3, 2]
      radius: 0.8
```

规划栅格和动画渲染必须解耦。`0.16 m` 或 `0.2 m` 栅格用于 A*/局部感知/碰撞检测是合理的，但不能把每个栅格直接实例化为 Sysplorer 组件。此前全地图 `0.16 m` 小格会导致 GUI 卡死或求解器长时间不返回，因此正式策略为：

```text
planning_grid: high_resolution_occupancy_grid
collision_check: geometry + inflated occupancy / distance check
sysplorer_display: merged pillars / clustered boxes / local highlight
manual_review: required
fallback: stable_low_complexity_pillars
```

地图渲染实验只影响显示层，不允许改变规划器输入、控制器参考或质量门计算。若人工审核发现效果差、障碍物表达不清、局部感知不真实、动画卡顿或仿真结果异常，立即回退当前稳定低复杂度立柱簇方案。

### 5.2.1 静态地图资产与在线局部感知解耦

为解决 Sysplorer 动画窗口在大量小尺寸地形/障碍组件下卡死的问题，`planning_open_blocks` 采用“静态地图资产 + 动态关键对象”的显示策略：

```text
  UAV body / axes / trajectory trace
  8 L/T wall groups

  local re-planning preview
```

重要边界：

1. 静态地图只用于背景/人工审查/后续 GUI 贴图，不允许作为在线规划器的全局真值输入；
2. 在线规划器只能使用局部已探索地图和当前传感范围内的障碍信息；
3. 未探索区域可以在 GUI 中遮罩、灰显或延迟显现，但不能被规划器提前用于全局最优路径；
4. 8 组 L/T 墙保留为 Sysplorer 动态对象，便于人工观察高度、遮挡和穿越效果；
5. 若需要正式展示完整环境，可把静态地图作为“真实环境底图”，再叠加局部感知高亮表达“无人机当前已知区域”。

### 5.4 障碍物来源策略

单机规划避障阶段优先使用项目内生成的标准地图，不从网上下载随机地图作为 P1 主证据。

理由：

1. 标准地图可固定 `seed`，便于复现实验；
2. 自生成障碍物的尺寸、坐标系、安全边界和起终点合法性可控；
3. 评审更关注“规划器是否能稳定避障、轨迹是否可跟踪、指标是否可复现”，而不是地图来源复杂度；
4. 外部地图容易引入版权、尺度、坐标系、格式转换和无关依赖，适合 P2/P3 展示增强，不应阻塞主线。

因此当前实现顺序为：

```text
P1: 标准几何障碍物生成 → 栅格地图 → A* → 平滑轨迹 → 控制器闭环跟踪
P2: 动态障碍物/局部重规划 → Safety Filter/CBF → Mid360 局部感知抽象
P3: 引入真实地图或外部公开地图作为展示增强
```

### 5.5 标准单机地图集

所有地图必须由配置文件描述，并支持固定随机种子：

```yaml
map:
  map_id: map_open_blocks
  seed: 20260514
  bounds:
    x: [-2, 8]
    y: [-3, 3]
    z: [0, 3]
  resolution: 0.2
  safety_margin: 0.35
  start: [0, 0, 1]
  goal: [6, 0, 1]
  obstacles:
    - type: box
      min: [2.0, -1.2, 0.0]
      max: [2.8, -0.2, 2.2]
    - type: cylinder
      center: [4.2, 0.8, 1.0]

      height: 2.0
```

P1 必须完成三类标准地图：

| 地图 | 目的 | 验收重点 |
|---|---|---|
| `map_open_blocks` | 稀疏方块/圆柱障碍 | 基础 A* 避障、路径长度、最小障碍距离 |
| `map_corridor_gate` | 窄通道/门洞 | 安全边界、轨迹平滑后是否擦碰 |

## 7.1 A* + Minimum Snap 主实现规格

模块名：

```text
planner_astar_min_snap
```

输入：

```text
map.yaml
start: [x, y, z]
goal: [x, y, z]
v_ref
v_max
a_max
j_max
yaw_mode
```

输出：

```text
path.csv
reference.csv
planning_summary.json
```

A* 推荐参数：

```yaml
astar:
  grid_resolution: 0.2
  neighbor_type: 26
  heuristic: euclidean
  tie_breaker: 1.001
  max_iterations: 200000
  collision_sample_step: 0.1
```

A* 伪代码：

```pseudo
function astar(start, goal, grid):
    open_set.push(start)
    g[start] = 0
    parent[start] = none

    while open_set not empty:
        current = pop_min_f(open_set)
        if distance(current, goal) < resolution:
            return reconstruct_path(parent, current)

        for neighbor in get_neighbors(current, neighbor_type):
            if out_of_bounds(neighbor) or occupied(neighbor):
                continue
            tentative_g = g[current] + distance(current, neighbor)
            if tentative_g < g[neighbor]:
                parent[neighbor] = current
                g[neighbor] = tentative_g
                h = euclidean(neighbor, goal)
                f = g[neighbor] + tie_breaker * h
                open_set.push_or_update(neighbor, f)

    return failure
```

路径后处理：

```text
raw_path → line_of_sight_simplify → angle_simplify → waypoint_list
```

Minimum Snap 约束建议：

```text
每段 7 阶多项式
起点/终点约束：位置、速度、加速度
中间点约束：位置连续，速度/加速度/jerk/snap 连续
```

时间分配：

```pseudo
for each segment i:
    length_i = norm(p_i - p_{i-1})
    T_i = max(length_i / v_ref, T_min)

while dynamic_violation:
    T_i = T_i * 1.2
    regenerate_trajectory()
```

yaw 生成：

```pseudo
if yaw_mode == "face_velocity":
    yaw_ref = atan2(vy_ref, vx_ref)
else:
    yaw_ref = fixed_yaw
```

动态可行性检查：

```pseudo
if max_norm(v_ref) > v_max: violation
if max_norm(a_ref) > a_max: violation
if max_norm(j_ref) > j_max: violation
if max_tilt > tilt_max: violation
if min_obstacle_distance < safety_margin: violation
```

可跟踪性评分：

```pseudo
trackability_score = 1.0
trackability_score -= w_v * violation_ratio(v_ref, v_max)
trackability_score -= w_a * violation_ratio(a_ref, a_max)
trackability_score -= w_j * violation_ratio(j_ref, j_max)
trackability_score -= w_tilt * violation_ratio(tilt_ref, tilt_max)
trackability_score -= w_sat * predicted_saturation_ratio
trackability_score = clamp(trackability_score, 0, 1)
```

控制饱和风险可用保守估计：

```pseudo
required_thrust = mass * norm([ax_ref, ay_ref, az_ref + g])
predicted_saturation_ratio = count(required_thrust > thrust_max * margin) / sample_count
```

轨迹修正规则：

```pseudo
if trackability_score < min_score or dynamic_violation_count > 0:
    segment_time = segment_time * 1.2
    regenerate_trajectory()

if predicted_saturation_ratio > sat_threshold:
    v_ref = 0.8 * v_ref
    increase_turning_radius()

if tracking_rmse_after_sim > rmse_threshold:
    mark_scene_for_replanning()
```

## 7.2 可跟踪性闭环优化流程

该流程是规划模块的核心创新：规划器不仅生成轨迹，还根据控制器实际跟踪结果反向修正轨迹。

```text
初始地图/任务
  → A*/RRT*/航点生成粗路径
  → Minimum Snap/B-spline 平滑
  → 动态可行性检查
  → trackability_score 预测
  → MWORKS 控制器跟踪仿真
  → 读取 RMSE、saturation_ratio、tilt_violation
  → 若不达标，调整时间分配/速度/转弯半径
  → 重新生成 reference.csv
```

闭环伪代码：

```pseudo
function generate_trackable_reference(map, start, goal, controller_limits):
    for iter in 1..max_trackability_iterations:
        path = plan_path(map, start, goal)
        reference = smooth_path(path, time_scale)
        precheck = evaluate_trackability(reference, controller_limits)

        if precheck.dynamic_violation_count > 0:
            time_scale *= 1.2
            continue

        sim_metrics = run_or_load_tracking_test(reference)
        if sim_metrics.rmse <= rmse_threshold and
           sim_metrics.saturation_ratio <= saturation_threshold:
            return reference, precheck, sim_metrics

        time_scale *= 1.2
        v_ref *= 0.85
        turning_radius *= 1.1

    return fallback_safe_reference()
```

推荐阈值：

```yaml
trackability_loop:
  max_iterations: 5
  min_trackability_score: 0.8
  rmse_threshold: 0.35
  saturation_threshold: 0.2
  tilt_violation_threshold: 0
  time_scale_growth: 1.2
  velocity_decay: 0.85
```

输出：

```text
reference.csv
planning_summary.json
trackability_report.json
```

`trackability_report.json` 至少包含：

```json
{
  "iterations": 2,
  "final_trackability_score": 0.86,
  "dynamic_violation_count": 0,
  "predicted_saturation_ratio": 0.08,
  "tracking_rmse_after_sim": 0.24,
  "accepted": true
}
```

规划失败回退：

```text
A* 失败 → 手工航点绕障
Minimum Snap 失败 → 分段五次多项式
动态约束超限 → 放大时间分配
仍失败 → 预设安全轨迹
```

验收：

```text
planning_success = true
min_obstacle_distance >= safety_margin
dynamic_violation_count = 0
trackability_score >= 0.8
predicted_saturation_ratio <= 0.2
reference.csv 字段完整
控制器跟踪后 tracking_rmse 可计算
```

## 7.3 单机规划避障闭环主线

单机规划工作从当前已完成的控制器闭环继续扩展，不重新定义被控对象。规划模块只产生参考轨迹，控制器仍使用已有 Sysblock 控制器。

主链路：

```text
map.yaml
  → grid_map_builder
  → planner_astar
  → path_simplifier
  → trajectory_smoother
  → trackability_checker
  → reference_bus
  → Sysblock controller
  → Quadrotor plant
  → metrics + event_log + replay_bus
```

P1 实现边界：

| 模块 | P1 要求 | 不做内容 |
|---|---|---|
| `grid_map_builder` | box/cylinder/sphere 膨胀，占据栅格导出 | 真实点云建图 |
| `planner_astar` | 2D/2.5D A*，固定高度或少量高度层 | 完整 kinodynamic search |
| `path_simplifier` | 直线可见性简化、角点保留 | 复杂拓扑优化 |
| `trajectory_smoother` | B-spline 或 minimum-snap，输出 p/v/a/yaw | 在线非线性轨迹优化 |
| `trackability_checker` | v/a/tilt/推力预测限幅 | 完整电机热模型 |
| `planning_controller_closed_loop` | 接入 AWFF/LinearMPC 等已有控制器 | 重新写底层姿态控制器 |

P1 场景：

| 场景 | 地图 | 控制器 | 输出 |
|---|---|---|---|
| `single_obstacle_astar_awff` | `map_open_blocks` | AWFF Sysblock | A* 路径、平滑轨迹、闭环 RMSE、最小障碍距离 |
| `corridor_gate_astar_awff` | `map_corridor_gate` | AWFF Sysblock | 通过窄门、无碰撞、轨迹平滑后安全距离 |
| `corridor_gate_astar_mpc` | `map_corridor_gate` | Linear MPC Sysblock | 与 AWFF 对比跟踪误差和饱和比例 |

P2 场景：

| 场景 | 地图 | 目标 |
|---|---|---|
| `dynamic_intruder_replan` | `map_dynamic_intruder` | 障碍物出现后触发局部重规划 |
| `dynamic_intruder_cbf` | `map_dynamic_intruder` | 不改全局路径时由 Safety Filter 保底避障 |
| `mid360_local_grid` | 局部感知地图 | 20 Hz 局部栅格更新与噪声建模 |

显示原则按真实自主导航处理：在线动画不预先展示未知区域的完整全局轨迹，只展示短视野局部计划；障碍物本体不因为未被雷达扫描而消失，局部感知地图只通过重新着色表达“已观测/已更新”的区域。当前 `planning_open_blocks` 使用 `90 m x 60 m` 横向地图，边界为 `x=[-45,45]`、`y=[-30,30]`，起点 `(-41,-26,1.69)`，终点 `(41,26,1.28)`；XY 起终点对应左下角到右上角，高度由地形跟随剖面生成，而不是固定 `z=1`。固定墙体必须完整落在地图边界内，并避开起点/终点安全半径，不能把墙直接放到起飞点上。规划搜索栅格为 `0.4 m`，局部感知显示细格为 `0.2 m`。在线感知半径为 `3.0 m`，显示层使用径向/圆形局部高亮，不再使用完整方形窗口或前向扇形着色；规划侧障碍发现也从“障碍中心点进入窗口”改为“无人机到障碍几何距离进入 3 m 半径”，否则长 L/T 墙会出现墙角已进入雷达但墙体中心未进入雷达的假未知问题。规划器维护“已知障碍集合”，每次只把当前局部感知范围内的真值障碍加入已知地图，再从当前位置向局部子目标滚动重规划 A*，其他未进入感知窗口的真值障碍对规划器保持未知，只用于环境显示和事后碰撞评价。局部子目标距离为 `10 m`，避免每一轮都在未知全局地图上直接搜索到最终目标。A* 邻居扩展必须检查连续线段安全，提交路径必须保留局部 A* 折线子段，不能只保存端点；否则对角线段会从墙角安全裕度内擦过。EGO-inspired 局部优化层不依赖 ROS/ESDF：它以 A* guide path 为拓扑种子，用平滑代价、guide-fitness 代价和障碍物几何距离代价更新中间航点；候选结果未满足验收裕度时必须回退到安全 A* guide path。当前局部规划同步到闭环模型后为 `73` 段参考，模型段容量为 `90` 段。轨迹输出使用 `quintic_segment` 五次段插值，参考采样 `0.05 s`，闭环模型输出间隔 `0.05 s`，与 20 Hz 控制/局部感知节拍一致。高度环参考采用 `terrain_follow_agl`：每个航点高度为静态地形高度加 `1.0 m` AGL，并夹紧在 `1.0-1.8 m`，本轮参考高度范围约 `1.12-1.73 m`。实时局部规划线从无人机实际位置出发，并限制在局部窗口尺度内，不提前伸到下下个区域；显示采样点数为 12，避免短视野轨迹看起来像单根直线。全地图地形不再用一整块平面，也不再用滚动局部地面数组替代全图；当前显示组件使用静态 STL 表达 `0.2 m` 分辨率、`0.1-0.8 m` 高度范围、`0.01 m` 台阶量化和逐格确定性扰动的实体地形柱阵列，并关闭深色网格线，只用高度带颜色表达起伏；随机障碍仍为 `1000` 个长方柱，动态层只保留随机障碍碰撞真值以外的关键对象。所有动态障碍 box 采用“中心点坐标 + 显式 length/width/height”规则：`pillar_position.z = pillar_z_min + 0.5*pillar_height`，同时 `r_shape.z` 必须为 `0`，禁止再写 `-0.5*pillar_height`，否则会把 3 m 墙体显示成一半在地上、一半在地下。当前在线审查版关闭边界围墙，只保留静态地图资产、标准 L/T 墙、径向局部高亮和短视野规划线。实际飞行历史轨迹从 MWORKS/native result 或独立审查视图读取真实仿真输出。规划与碰撞判定仍以 YAML 几何障碍、安全裕度和 `trackability_report.json` 为准；静态 STL 仅用于人工审查时看清障碍区域、地面起伏、局部规划和无人机之间的空间关系。注意：不要在显示组件内部用 `sample/pre` 或 `delay()` 记录实际历史轨迹。两种方案都可能把显示层变成影响求解器的动态子系统，前者曾导致 RMSE 从 `0.1667 m` 退化到 `70.08 m`，后者曾触发 `simulate_api_reported_failure=true`。当前模型级在线显示只保留当前实际位置；实际历史轨迹以 raw/native result 或外部审查工具显示，不能牺牲闭环证据可信度。

当前局部 A* 仍可能出现短暂回拉现象：这是局部已知地图只按最短路重新规划导致的参考路径行为，不是控制器 20 Hz 采样本身。直接把 `commit_distance_m` 从 `1.2 m` 降到 `0.48/0.64 m` 会导致重规划次数超过上限；加入简单目标方向惩罚也未降低回退量。后续若要提高飞行速度或控制频率到 50 Hz，应优先升级局部规划策略，例如引入 D* Lite / Anytime Repairing A*、局部轨迹优化器、曲率/进度/滞回代价，或在 A* 之后增加带进度约束的局部 B 样条优化，而不是只提高控制器频率。

```text

  → 放宽安全边界或提高高度层
  → 仍失败则切换预设绕障航点

平滑后碰撞
  → 增加路径点约束或降低平滑强度
  → 仍失败则回退折线限速轨迹

闭环跟踪误差过大
  → 降低 v_ref
  → 放大段时间
  → 增大转弯半径
  → 重新仿真
```

## 8. 局部优化目标

```text
J = λs Jsmooth + λc Jcollision + λd Jdynamic + λg Jgoal
```

其中：

```text
Jsmooth = Σ ||P_{i+1}-2P_i+P_{i-1}||²
Jcollision = Σ max(0,d_safe-d(P_i,obs))²
Jdynamic = penalty(v>vmax)+penalty(a>amax)+penalty(j>jmax)
Jgoal = ||P_end-goal||²
```

## 9. 动态可行性

检查：

```text
max ||v(t)|| <= v_max
max ||a(t)|| <= a_max
max ||j(t)|| <= j_max
tilt <= tilt_max
```

倾角估计：

```text
tilt ≈ atan(||a_xy||/(g+a_z))
```
