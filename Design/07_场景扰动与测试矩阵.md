## 1.1 Scenario Profile 统一场景抽象

后续不再为“自主避障、斜框穿越、风扰鲁棒、多机编队、视频展示”分别维护互不兼容的场景模型。所有场景统一使用 `Scenario Profile` 描述：

| 字段 | 含义 | 例子 |
|---|---|---|
| `world_geometry` | 地图、地形、障碍物、墙体、门框、边界 | `map_open_blocks`、`tilted_gate`、`obstacle_field` |
| `mission_route` | 起点、终点、航点、门框序列、任务阶段 | 左下起飞、右上终点、穿越 `gate_01` |
| `planner_profile` | 路径规划和轨迹平滑算法 | waypoint、A*、RRT*、EGO-inspired、B-spline、Minimum Snap |
| `controller_profile` | 位置/姿态控制和增强模块组合 | LinearMPC + INDI + L1-inspired + Safety |
| `disturbance_profile` | 风扰、质量、惯量、电机效率、传感器噪声 | crosswind、gust、rotor1_loss15 |
| `render_profile` | Sysplorer/UE5 显示模式、相机、雷达扇形、轨迹留痕 | unreal_follow_camera、radar_sector_120deg |
| `evaluation_spec` | 指标、质量门、人工审核项 | RMSE、min_distance、gate_clearance、video_review |

Profile 允许同一任务在不同渲染后端复用：

```text
same MWORKS simulation truth
  -> sysplorer_native_review
  -> unreal_offline_video
  -> unreal_realtime_bridge
```

验收规则：

1. `world_geometry` 中出现的门框、墙体和障碍物必须有规划/碰撞真值，不能只有渲染资产；
2. `render_profile` 不能改变仿真结果、控制器输出或碰撞判定；
3. `disturbance_profile` 必须进入 MWORKS 模型或等价控制器输入，不能只在视频里表现；
4. 每个正式 Profile 必须绑定 `scenario.yaml`、raw/native result、metrics、event_log 和人工审核状态。

## 2. 基础场景

悬停：

```text
p_ref=[0,0,2]
```

阶跃：

```text
A=[0,0,1] → B=[2,2,2]
```

圆轨迹：

```text
x=Rcos(wt), y=Rsin(wt), z=z0
```

---

## 3. 复杂轨迹

8 字：

```text
x=A sin(wt)
y=B sin(2wt)
z=z0
```

螺旋：

```text
x=Rcos(wt)
y=Rsin(wt)
z=z0+vzt
```

S 型搜索：

```text
x=vt
y=A sin(wt)
```

## 4. 业务场景

城市巡检：

```text
螺旋爬升 + 障碍物 + 横风
```

物流配送：

```text
起飞 → 绕障 → 投递 → 质量变化 → 返航
```

应急搜索：

```text
S型搜索 + 阵风 + 定点悬停
```

编队巡检：

```text
三机横队/三角队形区域巡检
```

故障返航：

```text
巡检中电机效率下降 → 模式切换 → 降速返航或安全降落
```

风场穿越：

```text
进入风扰区域 → WIND_REJECTION → 离开风场后恢复 NORMAL
```

## 5. 扰动库

扰动场景必须区分“名义机体参数”和“故意施加的场景覆盖”。在 PX4 ULog
参数辨识完成前，质量、惯量、`motor_efficiency`、电机时间常数和阻力
相关场景均基于 `source=SDF_migration` 名义参数做鲁棒性测试；报告中应写成
参数摄动/故障注入验证，而不是实物 Sunray150 参数精确复现实验。参数辨识
完成后，先按 `workflows/identify_quadrotor_parameters.md` 生成带来源和验证
结果的参数 YAML，再更新本矩阵中的名义值和摄动比例。

恒定风：

```yaml
wind: {type: constant, value: [1.0,0,0]}
```

阵风：

```yaml
wind: {type: gust, amplitude: [1,0.3,0], frequency: 0.5}
```

质量变化：

```yaml
mass_scale: 1.2
```

投递：

```yaml
mass_schedule:
  - {time: 0, scale: 1.2}
  - {time: 15, scale: 1.0}
```

电机故障：

```yaml
motor_efficiency:
  start_time: 10
  eta: [1.0,0.7,1.0,1.0]
```

传感器噪声：

```yaml
sensor_noise:
  position_std: 0.02
  attitude_std: 0.005
```

### 7.2 UE5 视频级场景矩阵

该矩阵用于视频展示和人工审核，不替代控制器/规划器指标矩阵。每个场景必须先有 MWORKS 仿真真值，再由 UE5 读取状态流渲染。

| 场景 Profile | 目的 | 必须显示 | 必须保留的 MWORKS 证据 |
|---|---|---|---|
| `obstacle_local_replan_unreal` | 自主避障、局部感知、实时重规划 | Sunray150、局部雷达扇形、已感知障碍、实时轨迹、局部计划曲线 | raw、metrics、min_obstacle_distance、manual_review |
| `tilted_gate_tracking_unreal` | 高速穿越斜框，展示姿态控制性能 | 倾斜门框、机体姿态、机体系 xyz 轴、门框 clearance | gate_clearance、attitude_error、tracking_error |
| `wind_corridor_unreal` | 风扰鲁棒性和模式切换 | 风区材质、mode/event 标记、轨迹偏差和恢复 | disturbance_hat、recovery_time、event_log |
| `rotor_fault_return_unreal` | 电机效率下降和安全返航/降落 | 故障电机高亮、返航/降落路径、状态机事件 | eta_hat、fault_index、return_or_land_status |
| `formation_obstacle_unreal` | 多机编队和避障展示 | 队形、机间距离、队形收缩/恢复 | min_inter_uav_distance、formation_error |

斜框穿越场景建议分三档：

| 档位 | 速度 | 门框姿态 | 目的 |
|---|---|---|---|
| gate_basic | 低速 | 无倾斜 | 验证坐标、尺寸和碰撞距离 |
| gate_tilted | 中速 | roll/pitch/yaw 倾斜 | 展示姿态和轨迹跟踪 |
| gate_tilted_crosswind | 中高速 | 倾斜 + 横风/阵风 | 展示鲁棒控制和安全过滤 |

## 8. 场景配置示例

```yaml
scene_id: formation_obstacle_fault
duration: 40
dt: 0.01

task:
  type: formation_obstacle
  start: [0,0,1]
  goal: [10,6,2]

map:
  obstacles:
    - type: box
      min: [3,2,0]
      max: [5,4,3]

planner:
  algorithm: rrt_star
  smoother: min_snap

controller:
  type: nmpc_indi_l1_safe

task_manager:
  enabled: true
  target: delivery_or_return
  mode_switch: true

formation:
  type: triangle
  uav_count: 3
  spacing: 1.5

disturbance:
  wind:
    type: constant
    value: [1,0,0]
  motor_efficiency:
    start_time: 20
    eta: [1,0.7,1,1]

evaluation:
  health_score: true
  replay_export: true
```
