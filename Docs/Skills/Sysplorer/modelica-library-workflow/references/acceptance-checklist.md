# 验收清单

## 目的

定义模型库开发任务在不同交付粒度下，什么情况下才能称为“完成”。

## A. 方案级完成

可称为“方案已完成”，至少满足：

1. 已明确任务类型和边界
2. 已给出顶层 package 结构
3. 已给出正式包名方案
4. 已给出首批模型名单或修订范围
5. 已写明假设、风险和下一步

## B. 文件级完成

可称为“文件已完成修改”，至少满足：

1. 真实文件已经改动
2. 结构或文案修改点可追溯
3. 没有明显失效链接或自相矛盾规则
4. 已区分“已修改”和“未验证”

首次生成模型库时，额外要求：

5. 至少已有一个 `Examples` 案例和一个 `Tests` 入口
6. 已在 Sysplorer 中成功加载并打开顶层库
7. 不把“仅能编译”描述成“可用”，首次生成默认还需进一步运行成功

## C. 结构级验证通过

可称为“结构级检查通过”，至少满足：

1. 顶层 package 结构完整
2. 公用层与业务层归位正确
3. `Examples` 与 `Tests` 已分离
4. 中文化策略一致
5. 图形化模型需要时已补必要图面注解
6. 图标层接口位置、主体比例和文字位置基本协调
7. 图形层主链路、控制链和测量链布局清楚，不存在明显压线、乱线和悬空测点
8. 若交付对象包含系统模型图面，则不存在仅有 `connect(...)` 但缺少 `annotation(Line(...))` 的应显示连接

## D. 运行级验证通过

只有在真实工具链证据存在时，才可称为“运行级验证通过”：

1. 最小样例已检查通过
2. 如有翻译步骤，翻译通过
3. 如有仿真步骤，结果证据存在
4. 已说明验证范围和未覆盖范围
5. 若交付对象包含系统模型图面，已明确说明图面可见连线是否补齐

首次生成模型库时，如果顶层库尚未在 Sysplorer 中成功加载并打开，则不得称为“首次生成完成”。  
首次生成模型库时，如果首个 `Examples` 案例未通过 `check` 或 `translate`，则不得称为“首版可用”或“首次生成完成”。  
首次生成模型库时，如果首个 `Examples` 案例或首个 `Tests` 入口未运行成功，则不得称为“首版可用”或“首次生成完成”。

## E. 推广发布前通过

准备推广给其他人使用前，至少确认：

1. `SKILL.md` 与 `agents/openai.yaml` 一致
2. 主要 references 已更新
3. 工作流和模板入口可用
4. 默认话术和展示文案为中文
5. 至少经过一次真实任务回放或人工校验

## 不得宣称完成的情况

以下任一情况存在时，不要写“已完成优化”：

1. 只有计划，没有产物
2. 只改了文案，没有落实结构
3. 已改文件但没区分验证状态
4. 有明显缺失的样例、测试或文档入口
5. 用户要求验证，但实际上未跑
6. 首次生成模型库时，尚未在 Sysplorer 中成功打开顶层库
7. 首次生成模型库时，首个 `Examples` 案例编译失败
8. 首次生成模型库时，首个 `Examples` 案例或首个 `Tests` 入口运行失败
9. 交付的系统模型图上仍无组件间可见连线，却宣称图面已完成
