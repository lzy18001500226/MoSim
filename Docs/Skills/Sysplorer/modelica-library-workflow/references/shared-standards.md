# Shared Standards

Modelica 模型库开发任务的全局执行约束。

---

## 1. 串行规则

- 所有步骤必须按顺序执行
- 顶层结构未定型前，不进入大批量组件扩写
- 公用层未收口前，不把跨库复用内容继续散落到业务包
- 首个 `Examples` 和首个 `Tests` 未明确前，不宣称形成最小闭环
- 失败后必须进入修复闭环，再回到失败步骤

---

## 2. 输出规则

- 每一步都必须输出结构化中间结果
- 关键假设必须单列
- 结构调整、接口迁移、包名替换必须说明原因
- 结果结论必须区分“方案”“文件”“结构级验证”“运行级验证”
- 未执行真实验证时，必须显式写明“未验证”

---

## 3. 模型库规则

- 优先保留 `UsersGuide`、`Examples`、业务包、`Sensors`、`Sources`、`Interfaces`、`Utilities`、`Tests`
- 不直接交付 `Components1`、`Components2` 等占位包名
- 目录式 package 默认同步维护 `package.order`
- `package.order` 用于表达正式交付结构，不用于把“先收口 `Interfaces` 等公用层”的执行顺序写成顶层展示顺序
- 接口默认只从当前模型库 `Interfaces` 使用
- 跨多个组件复用的函数、常数、类型和图标默认收口到 `Utilities`
- 用户可见内容默认中文，技术标识符默认保留 ASCII

---

## 4. 验证规则

- 用户只要方案或评审时，可停留在结构层
- 用户要求“已验证”“可运行”“首版可用”时，必须进入真实验证链
- 首次生成模型库时，顶层库、首个 `Examples` 入口和首个 `Tests` 入口是最低验证对象
- 未完成真实加载、`check`、`translate` 或运行验证时，不得写“已验证通过”

---

## 5. 修复规则

- 不得在发现结构、接口、图面或交付口径问题后直接停止
- 修复必须记录现象、根因、动作、结果
- 修复后必须重跑失败步骤，而不是口头宣布“应该可以了”
