# 执行基线

## 角色

本文件定义 `modelica-library-workflow` 的 **标准执行顺序、阶段门槛和最小闭环要求**。  
它不重复 `SKILL.md` 前置硬约束中的命名、接口、中文化和图面细则；执行时若遇到规则冲突，以 `SKILL.md` 的前置硬约束为准。

## 默认依赖版本

- 未特别说明时，`Modelica` 依赖版本默认按 `4.0.0.TY.1` 处理
- 需要写 `uses(...)`、版本说明或交付基线时，显式写成 `Modelica 4.0.0.TY.1`
- 若现有库使用其他版本，先保留现状并标记差异，不擅自覆盖

## 标准执行顺序

1. 识别任务类型
2. 提取领域边界、工具链和交付粒度
3. 固定顶层 package 结构与正式库名
4. 固定 `Interfaces`、`Utilities`、`Sources`、`Sensors`
5. 落首个业务包及其 `Basics`
6. 落 `Examples`
7. 落 `Tests`
8. 做阶段自检
9. 按需做 Sysplorer 校验
10. 按输出契约组织交付

## 阶段门槛

### 阶段 1：任务识别

进入条件：

- 用户已经给出目标、模板、已有库，或至少一个明确任务方向

完成标志：

- 已判断属于建库、整理、扩展、评审、中文化或图面修复中的哪一类

### 阶段 2：结构定型

进入条件：

- 任务类型已明确

完成标志：

- 顶层 package 结构已确定
- 正式库名已确定或已形成建议
- 首轮交付粒度已确定

### 阶段 3：公用层收口

进入条件：

- 顶层结构已确定

完成标志：

- `Interfaces`、`Utilities`、`Sources`、`Sensors` 已确定归位
- 首个业务包的公共依赖不再散落在业务组件内部

### 阶段 4：最小闭环

进入条件：

- 公用层已具备承接能力

完成标志：

- 至少有一个业务包
- 至少有一个 `Examples` 入口
- 至少有一个 `Tests` 入口

### 阶段 5：实施与自检

进入条件：

- 已产生可核对的真实文件修改

完成标志：

- 已按 `workflow-checklist.md` 做结构、接口、图面和闭环自检

### 阶段 6：验证与交付

进入条件：

- 用户要求“已验证”“可运行”“首版可用”或当前任务本身就是首版建库

完成标志：

- 已完成对应层级的证据收集，并能按 `input-output-contract.md` 清楚表述

## 首版模型库的最低闭环

只要任务属于“从 0 到 1 建库”，默认最低闭环为：

1. 顶层库文件已生成
2. 顶层库已在 Sysplorer 中成功加载并打开
3. 首个 `Examples` 入口通过 `check`
4. 首个 `Examples` 入口通过 `translate`
5. 首个 `Examples` 入口完成运行验证
6. 首个 `Tests` 入口通过 `check`
7. 首个 `Tests` 入口通过 `translate`
8. 首个 `Tests` 入口完成运行验证

未达到以上闭环前，不输出“首版模型库可用”。

## 何时必须做真实验证

以下情况默认不能只停留在结构说明：

- 用户明确要求“能在 Sysplorer 中加载”
- 用户明确要求“案例能够仿真”
- 用户明确要求“首版模型库”
- 用户明确要求“已验证”“可运行”“可发布”

## 何时可以停留在方案层

以下情况可以不强制进入运行验证：

- 用户只要优化计划
- 用户只要结构评审
- 用户只要命名方案
- 当前环境不支持验证，且用户接受先做文件层整理

但即使停留在方案层，也必须明确写出“未执行真实验证”。
