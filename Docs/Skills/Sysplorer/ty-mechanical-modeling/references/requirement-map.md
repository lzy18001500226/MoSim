# 需求映射 / Requirement Map

用于把用户自然语言需求快速映射为 TY 机械建模任务类型、默认执行入口和首轮推进路径。

## 任务判断表

| 用户说法 | 任务判断 | 推荐入口 | 默认路径 |
|---|---|---|---|
| “搭一个机械系统”“建一个传动模型”“生成一个多体机构” | 新建模型 | `workflows/build-from-scenario.md` | 先收敛到最小可检查闭环，再补细化结构与工况 |
| “修一下 check/translate/simulate 报错”“帮我改连线或参数” | 修复模型 | `workflows/repair-existing-model.md` | 先定位失败阶段，再做最小修复并回到标准闭环 |
| “跑一下官方样例”“验证公司样例”“看看样例结果对不对” | 样例验证 | `workflows/verify-example.md` | 先确认样例仅用于验证，不可直接改壳交付 |
| “帮我看结果是否合理”“复核一下这组曲线” | 结果复核 | `workflows/verify-example.md` | 先确认关键变量与判断标准，再回看模型结构、参数与工况 |

## 触发与默认执行规则

- 用户明确提出 `使用TY商业库进行机械建模` 或 `用同元模型库进行机械建模` 时，必须触发本 Skill。
- 用户虽未复述上述短语，但已明确要求在 TY 机械库范围内完成机械建模、修模、样例验证或结果复核时，应触发本 Skill。
- 建模相关问题默认按执行型任务处理，而不是只给概念性建议；仅当用户明确要求纯说明、纯对比或纯原理解释时，才退回解释模式。
- 若用户目标过宽，先收敛以下最小信息：任务类型、运动维度、目标系统、边界条件、最关心的结果变量。

## 首轮信息补齐清单

用户输入不足时，优先读取 `templates/scenarios/user-input-minimum-form.md`，把已知信息填入表单，只追问阻塞建模的必须字段。

| 信息项 | 是否必须 | 说明 |
|---|---|---|
| 运动维度 | 是 | 1D、2D、3D 会直接决定 TY 子库选择 |
| 目标系统或机构对象 | 是 | 用于进入正确的组件映射路径 |
| 边界条件与激励 | 是 | 决定最小闭环能否成立 |
| 输入输出接口 | 是 | 决定测试用例和观测变量 |
| 关键结果变量 | 推荐 | 便于提前定义 `result verify` 目标 |
| 已有模型或报错日志 | 修复任务必需 | 用于定位最小修复路径 |

## 默认推进纪律

- 新建任务优先参考 `templates/scenarios/user-input-minimum-form.md` 整理最小输入，再进入 `references/component-map.md` 的快速分流表收敛 TY 子库。
- 修复任务优先保留原模型结构，只修改与当前失败阶段直接相关的部分。
- 样例验证任务优先确认“验证样例”与“基于样例重建模型”是两类不同任务。
- 任意任务都不得跳过父级闭环。
