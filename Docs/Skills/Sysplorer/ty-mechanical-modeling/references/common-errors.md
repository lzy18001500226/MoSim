# 常见错误 / Common Errors

用于统一 TY 机械模型在检查、翻译、仿真和结果复核阶段的排查顺序。

## 高频问题排查表

| 报错阶段 | 现象 | 可能原因 | 排查顺序 | 修复建议 |
|---|---|---|---|---|
| `check` 失败 | 接口漏连、连接方向不对、组件层级混乱 | 漏连、重复连、未放世界组件、图形结构不清 | 先查世界与接口，再查连接语义，再查测试用例接口 | 只修当前结构问题，修后重新 `check` |
| `translate` 失败 | 状态选择冲突、非线性迭代量报错、初值不足 | `stateSelect` 不合理、自由度冗余、初值缺失、约束过强 | 先查 `stateSelect`，再查初值，再查冗余约束 | 不要先调求解器；优先最小修复结构和初值 |
| `simulate` 失败 | 初始阶段发散、积分失败、响应不连续 | 初始值冲突、约束冲突、参数数量级失衡、激励过猛 | 先查初始值，再查约束，再查参数数量级和激励边界 | 求解器调整只作为最后一步优化 |
| 结果异常 | 曲线方向错、峰值异常、变量不连续 | 变量选错、参数未真正生效、工况与边界不匹配 | 先核对观察变量，再核对参数来源，再回查结构 | 明确说明异常变量与可能根因 |
| 组件缺失 | 库内找不到直接可用组件 | 路径检索不完整、帮助文档未扫全、TY 库确实无件 | 先按组件映射重走检索，再扫帮助文档 | 确认无等效组件后再告知缺件，不得绕库替代 |

## 修复优先级

1. 先修库边界和结构闭合问题。
2. 再修参数生效和初始化问题。
3. 再修仿真稳定性和结果异常问题。
4. 最后才做求解器和性能优化。

## 禁止做法

- 不要通过切换到 `Modelica`、`TA` 或其他外部库来规避问题。
- 不要在 `translate` 未收敛前直接跳到求解器调参。
- 不要用大量随意初值覆盖问题而不解释物理依据。
- 不要把“官方样例能跑通”当成“用户模型已完成”。
