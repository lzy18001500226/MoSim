# Controller Family Gazebo Final Acceptance

Status: closed with blockers, 2026-07-17 CST.

## 1. Goal

Close the controller platform with one auditable matrix instead of promoting
individual run directories by inspection. The final bundle must distinguish:

```text
accepted
executed_blocked
provenance_missing
not_run
not_applicable
```

An executed or landed run is not accepted when its declared metric gate fails.
MWORKS, generated-C SIL, source registration, or an old profile name cannot
replace same-run Gazebo runtime provenance.

## 3. Single-UAV Gate

For P1-P5 and G9, acceptance requires all of the following in the same run:

```text
pre_takeoff_state_gate.status=passed
takeoff_reached_altitude=true
landing_disarm.success=true
PX4CTRL_BASIC_MISSION_METRICS.status=passed
generated runtime provenance.status=passed
runtime-loaded controller id/name matches the matrix row
```

The existing mission threshold remains authoritative. Do not relax the hover
threshold merely to increase the accepted count. A failed controller may be
tuned only through a new versioned profile and must retain its failed run.

Representative trajectory acceptance additionally requires a fresh
figure-eight result with nonempty trajectory metrics and the same provenance
contract. Do not infer trajectory performance from hover.

## 4. Reuse And Rerun Policy

1. Reuse immutable P6-P9 evidence after schema/path/status audit.
2. Reuse a P1-P5 result only when mission and same-run provenance both pass.
3. If a run passed flight metrics but lacks same-run provenance, rerun it; do
   not attach a provenance record from a different executable build.
4. Stop a controller after its first current-gate failure. Preserve the result
   and continue only when the failure is controller-local.
5. Run trajectories only for rows that pass the basic gate and are selected
   for the final report comparison. Do not run every experimental variant by
   default.
6. Do not retune the plant, state source, common safety thresholds, planner or
   mission geometry while comparing controllers.

## 5. Final Outputs

The authoritative output root is:

```text
Results/control_platform/controller_family_final_acceptance_20260717/
  CONTROLLER_FAMILY_FINAL_MATRIX.json
  CONTROLLER_FAMILY_COMPARISON.csv
  SUMMARY.md
  figures/acceptance_status_counts.png
  figures/cohort_status_distribution.png

```

Every row records family, controller, implementation state, MWORKS/SIL state,
Gazebo execution, provenance, landing, metrics, representative trajectory,
acceptance status, claim ceiling, blocker and evidence paths.

The matrix is generated by:

```powershell
python Scripts/control_platform/summarize_controller_family_final_acceptance.py
```

Each G9 mission is run through the frozen serial entrypoint:

```bash
bash Scripts/sunray/run_g9_controller_final_acceptance.sh <controller> <takeoff_hover_land|figure8>
```

The entrypoint uses a per-result PX4 work directory, the accepted six sensor
bias overrides, the isolated G9 launch, and a same-run generated-runtime
provenance check. A nonzero mission result remains failed evidence while the
provenance result is still recorded separately.

There are no remaining `provenance_missing` rows. The strict G9

the new provenance record.

The authoritative outputs are the matrix, CSV, summary and figures under the
result root in Section 5. This closes the acceptance audit, not the blocked
controller capabilities.

## 7. Stop Conditions

Stop the shared runtime and preserve a blocker when preflight fails, another
owner holds the runtime lock, official baseline provenance cannot be proved,
PX4/Gazebo is unstable before controller selection, or a proposed fix changes
the accepted architecture. Frontend and UE work are outside this closeout.
