```markdown
## 第八章 px4ctrl工程控制器设计与验证

本章介绍本团队工程控制器 px4ctrl 的总体设计、MWORKS 图形化实现和整机闭环验证。px4ctrl 作为工程部署主线，在前三章的理论控制器族完整建立之后单独成章，以突出其在代码生成、Gazebo/PX4/MAVROS 部署和实飞验证中的核心地位。

### 8.1 px4ctrl总体设计与定位

px4ctrl 是本团队针对云纵150虚拟飞机定制的工程控制器，也是后续代码生成和 Gazebo/PX4/MAVROS 部署的主线基线。其替换范围限定为位置/速度外环：输入为位置、速度、姿态、角速度、位置/速度/加速度参考、航向、质量、重力和采样周期；输出为期望姿态四元数与物理总推力（`ATTITUDE_THRUST` 边界）。PX4 姿态环、角速度环和控制分配仍由飞控侧承担，因而本文不将 px4ctrl 表述为替代整套飞控。

与第五章 Official PID 基线和第六章理论控制器族的主要区别在于：px4ctrl 以工程可部署性为首要设计目标，优先考虑接口兼容（MAVLink/MAVROS）、计算效率（代码生成后嵌入机载计算机）和鲁棒性（七场景全部通过G3门禁），而不追求理论最优性。

### 8.2 位置/速度外环结构

px4ctrl 的外环分为位置环和速度环：
- **位置环**：位置误差 → 期望速度（P控制或PD控制）
- **速度环**：速度误差 → 期望加速度 → 期望姿态四元数 + 总推力

坐标系：MWORKS 侧使用 ENU/FLU；PX4 侧使用 NED/FRD。坐标转换在 Adapter 边界完成（`PX4CtrlAttitudeThrustAdapter`），控制核心保持 ENU/FLU。

### 8.3 MWORKS图形化实现

px4ctrl 已完成从 Julia/Python 参考实现到 MWORKS 图形化外环的迁移，通过 `HinfHoverWrenchAdapter` 同款的 EquationBridge + CFunction 模式接入整机模型。

> **图占位：px4ctrl图形化外环与整机闭环**
> - 内容：Sysplorer中px4ctrl外环的图形化Sysblock模型，显示位置环→速度环→姿态参考输出链路
> - 来源候选：`Results/control_platform/px4ctrl_graphical_completion_20260728/screenshots/`
> - 图前正文：如图所示，px4ctrl外环在MWORKS中以图形化Sysblock实现，位置误差和速度误差经串级反馈生成期望姿态四元数与归一化总推力，输出至ATTITUDE_THRUST边界。

![图8-1-px4ctrl工程外环的MWORKS图形化实现与整机接入](./figures/fig8-1.png)

- px4ctrl方程桥闭环证据：`Results/control_platform/px4ctrl_graphical_completion_20260728/`
- MWORKS实现：`Models/MoSimQuadrotorModel/Control/Adapters/` 对应Adapter文件

### 8.4 ClimbPath50s整机闭环验证

px4ctrl 已完成 `ClimbPath50s` 场景的 MWORKS 方程桥整机闭环记录，是当前仅有的具备原生窗口证据的工程控制器验证。

**关键结论**：
- CheckModel：通过
- SimulateModel：仿真至50.0 s，退出码0
- ClimbPath50s G3门限：终端位置误差 < 5 m（已通过）

**证据边界**：
该记录证明 px4ctrl 在 MWORKS 整机模型下的闭环有界性，但不等价于：代码生成质量、SIL 同输入对照结果、Gazebo/PX4/MAVROS 运行时性能、实飞精度或七场景横向排名。上述内容在第十三章独立验证。
```
