# Results 发布与归档计划

> 状态：计划和预算，非破坏性盘点。生成时间：2026-08-01。
> 本文件不授权删除、移动或覆盖任何现有结果。

## 1. 目标

将本地 `Results/` 从“全部实验历史、缓存、运行输出和证据混合目录”整理为两
个用途：

1. 发布包只包含能够支撑报告结论和第三方复核的最小证据；
2. 完整历史结果保留在归档介质中，并通过清单、哈希和索引追溯。

发布包不需要携带全部 `Result.msr`、原始点云、全部 rosbag 或每次调试日志。
这些文件仍可归档保存，用于需要时复查。

## 3. 发布包分级

### A 类：必须进入发布包

- 与报告结论直接对应的 `RUN_MANIFEST.json`、`RUN_RECORD.json`、指标 JSON、
  合同/Profile 哈希和结果索引；
- C99 名义起飞-悬停-降落、风扰、电机故障恢复三条代表性记录；
- MWORKS `px4ctrl` 基线、图形化完成、代码生成/SIL 和代表性控制器汇总证据；
- 七场景和 48 控制器的汇总矩阵；无效记录保留摘要和状态，不默认携带全部原始
  `Result.msr`；
- 报告中实际引用的 QGC、RViz、UE 和 MWORKS 图片；
- 与源码、配置和资产包匹配的 SHA-256 清单。

预估体积：结果证据约 1-5 GB；不含源码、MWORKS 安装和 Gazebo 资产包。

### B 类：保留为完整证据归档

- 所有原始 `Result.msr`、CSV、日志和调试截图；
- `phase2_full_48_climbpath` 的全部原始文件；
- 历史失败记录、负样本、超时记录和旧版实验结果；
- rosbag、完整点云、轨迹回放和视频素材。

处理方式：移动到独立归档介质或压缩包，保留原始相对路径、文件哈希和归档清单。
归档不改变报告中的状态，不把失败记录改写为通过。

### C 类：本次发布排除并归档

- `Results/native_result_cache`；
- `Results/tmp`；
- `Results/build`、`Results/ros2_build`；
- `Results/agent_runtime`、`Results/agent_packets`、`Results/coagent_transport`；
- `Results/logs`、`Results/mworks_background_capture`、`Results/mworks_gui_incidents`
  等本机工具和临时状态。

这些目录不进入发布包，但在执行归档前仍需生成目录级和文件级清单。

### D 类：需要另一条运行线确认

以下内容涉及 QGC、Gazebo、UE、RViz 或运行时回放，当前不由本线程直接移动：

- `Results/sunray_ros1`；
- `Results/unreal_scene_mapping`；
- `Results/gazebo_review`、`Results/gazebo_ros2`、`Results/px4_gazebo`；
- `Results/ue_build`、`Results/ue_replay_input`、`Results/ui_platform` 和相关运行记录。

在运行线确认保留的实时、回放和视频证据后，只把指定的代表记录复制到发布包，
其余内容再归档。

## 4. 执行顺序

1. 只读生成文件级 `SHA256` 清单，并建立“发布/归档/排除/待确认”索引。
2. 先复制 A 类证据到临时发布目录，计算复制前后哈希并核对引用。
3. 由 QGC/Gazebo 运行线确认 D 类目录中的代表性记录。
4. 将 B/C 类内容压缩或移动到外部归档目录；原位置保留归档说明和索引，不直接
   删除证据。
5. 对发布目录执行源码路径检查、证据路径检查、文档链接检查和压缩包清单检查。
6. 固定发布提交、源码包、资产包和证据包的版本号后再打包。

## 5. 当前禁止事项

- 不整体移动 `Results/control_platform` 或 `Results/sunray_ros1`；
- 不直接删除 `Result.msr`、rosbag、点云或失败记录；
- 不把 `native_result_cache` 当成正式证据；
- 不把窗口截图、地图显示或目录存在写成控制器运行通过；
- 不在归档前修改原始结果内容或重命名导致现有文档链接失效。

本计划只完成盘点和预算，当前没有执行任何移动、删除或压缩操作。
