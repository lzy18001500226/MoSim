## 前言

## 第1章 系统概述

### 1.1 系统定位

MoSim 是面向四旋翼位姿控制、仿真与证据复核的项目平台。MWORKS 的 Sysplorer、Sysblock 和 Syslab 构成模型、控制器、离线整机运行与原生结果审查主线；MoSim Studio 提供配置和模型打开入口；PX4、MAVROS、Gazebo、QGC、RViz 与 UE 分别承担飞控、桥接、运行时物理、飞行操作、机器人审查和展示职责。

项目当前目录包含 48 条控制器路线，按七个算法控制器族与一个工程基线分类组织。所有路线通过四类输出边界接入统一机体模型：ATTITUDE_THRUST、BODY_RATE_THRUST、WRENCH 与 ROTOR_COMMAND。结构可接入不自动等于性能、代码生成或运行时部署已经通过；每项结论必须回链到同次 Profile、原生结果、metrics 和运行记录。

### 2.2 MWORKS安装与授权

安装 MWORKS 时应包含 Sysplorer、Sysblock 和 Syslab 组件，并以拥有授权的用户身份完成登录或许可证处理。启动 Sysplorer 后，先确认主窗口正常、版本可见且可加载本项目的正式包根，再进入模型审查。

**安装后人工检查**

1. 启动 Sysplorer，确认无登录、许可证或授权阻断窗口。
2. 通过“打开包”加载 <code>C:\Users\HP\Desktop\MoSim\Models\MoSimQuadrotorModel\package.mo</code>。
3. 打开 <code>MoSimQuadrotorModel.Vehicle.Sunray150Assembly</code>，确认模型树和装配可见。
4. 打开一个 Formal Runner 并执行 CheckModel。
5. 仅在当前任务授权时继续仿真；检查失败时保留诊断，不进行盲目重试。

登录、许可、验证码、授权确认或未知弹窗属于人工处理事项。本手册不保存账号、口令、令牌、许可证或绕过授权的方法。

### 13.6 状态词典

项目的结果状态必须按证据记录解释，不能只看界面颜色、文件夹是否存在或模型能否打开。

| 状态 | 含义 | 允许的表述 | 禁止的表述 |
|---|---|---|---|
| <code>accepted</code> | 已完成且满足当前 Profile 的证据和门限 | 在该 Profile、该模型版本下通过 | 所有场景、所有版本或真实飞行均通过 |
| <code>passed</code> | 当前记录通过其定义的门限 | 本条记录通过 | 自动等价于部署、闭环或全局排名 |
| <code>failed</code> | 已完成但越过物理或指标门限 | 本条 Profile 下未达门限 | 控制器在所有工况无效 |
| <code>executed_blocked</code> | 执行链、会话、求解器或环境阻断，未形成可评估完整结果 | 执行受阻，需要分类或重试授权 | 已知物理失败或已经通过 |
| <code>failed_execution_solver_stall</code> | 求解器停滞导致记录无法完成 | 求解器执行阻塞 | 控制器容错性能失败或成功 |
| <code>not_run</code> | 没有完成可用于判定的运行 | 未运行或缺少同次证据 | 通过、失败、已部署或已验证 |
| <code>baseline_only</code> | 仅用于隔离基础链路或部署前置条件的历史记录 | 部署基线或可追溯性记录 | 规划器、编队算法或任务成功证明 |
| <code>blocked</code> | 明确原因导致当前任务未闭合 | 当前原因下阻塞 | 后续任务自动完成 |
