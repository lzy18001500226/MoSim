EXECUTIVE SUMMARY
================================================================================

Phase 5 trajectory tracking BLOCKED due to cascade PID architecture designed
for hover at mid-range (command ≈ 0.5) but actual interface provides hover at
command = 0.65. Internal integral pre-saturation at ±0.5 prevents controller
from using upper 45% of thrust authority.

ROOT CAUSE: CascadePidCore.mo line 77
  outer_integral_pre_limit(upLimit=0.5, lowLimit=-0.5)

EVIDENCE: Controller command chain query
  Time    integral    outer_cmd    final_cmd    rotor_speed
  t=2s    0.5 (SAT)   0.528        0.550        65.10 rad/s
  t=50s   0.5 (SAT)   0.528        0.550        65.10 rad/s

  Controller uses only 55% of available thrust authority
  45% of thrust range unused despite 30m tracking errors

INVESTIGATION HISTORY (4 Attempts)
================================================================================

Attempt 1: Gentler Trajectory (2 m/s → 1 m/s)
  Result: 613m → 349m error (partial improvement, still FAIL)

  Result: 349m → 422m error (WORSE, broke hover equilibrium)

  Result: 349m error with 5% thrust margin

  Result: 354m error (NO IMPROVEMENT)
  Anomaly: Controller plateaus at 65.10 rad/s instead of 69.48 rad/s max
  Root cause identified via internal variable query

================================================================================
THREE ARCHITECTURAL MISMATCHES
================================================================================

1. Hover Point
   Design: Hover at command ≈ 0.5, ±50% authority above/below
   Reality: Hover at command = 0.65, only +35% authority above
   Impact: 30% loss of upward thrust capability

2. Integral Saturation Scaling
   Design: Integral ±0.5 allows reaching outer_command = 1.0
   Reality: Integral 0.5 → I-term 0.24, requires P+D = 0.76 for saturation
   Impact: Controller cannot saturate unless errors >> 30m

3. Command-to-Thrust Mapping
   Design: Command 0.528 produces near-maximum thrust
   Reality: Command 0.528 → 65.10 rad/s = 0.95% above hover
   Impact: Controller thinks aggressive, actually producing hover-level thrust

================================================================================
WHY ALL FIXES FAILED
================================================================================

Trajectory Reduction: Doesn't address internal saturation limit

Controller Re-Tuning: Reducing gains makes saturation WORSE
  - Lowers outer_command from 0.528 to ~0.32
  - Final command drops to ~0.35
  - Uses even LESS authority (35% instead of 55%)

Thrust Margin Increase: Controller still outputs same 0.55 command
  - 5% margin: 0.55 command uses 98% of range (nearly saturating)
  - 15% margin: 0.55 command uses 55% of range (internal limit)
  - Expanding range gives headroom controller cannot access
