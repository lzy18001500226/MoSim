# 灵敏度分析实验设计

## 一、目标与边界

本实验评估 `px4ctrl` 与 `official_pid` 在当前 MWORKS FormalRunner
边界下的持续扰动鲁棒性。目标是记录离散扫描网格中的临界阈值，即能满足
50 s 完整性和位置误差门槛的最大持续扰动强度。

本版只保留持续扰动：

- 电机效率故障：`t=15 s` 注入并持续到 `t=50 s`。
- 风扰：`t=15 s` 注入并持续到 `t=50 s`。
- 参数失配：`t=0 s` 到 `t=50 s` 持续存在。

短时 `15-25 s` 注入、故障恢复、恢复时间和
`time_varying_rotor_effectiveness` 均不属于本实验。当前 Plant 不需要也
不允许为此实验增加时变效率实现。

## 二、统一执行契约

- 模型根：`Models/MoSimQuadrotorModel/package.mo`
- 控制器：`px4ctrl`、`official_pid`
- 求解器：Dassl，tolerance `1e-4`，导出间隔 `0.01 s`；MCP 等待上限
  `360 s` 仅约束客户端等待，不修改求解器设置。
- 仿真时长：`0-50 s`
- 每个 case：先 `CheckModel`，再 `SimulateModel`，保存原始 CSV、指标、
  请求的 native `Result.msr`、MCP 日志、注入自检和窗口取证。若 native
  `Result.msr` 未物化而 MWORKS Result API 已导出原始 CSV 与指标，记录必须
  明确该绑定状态，不能把有效结果导出误判为失败。
- 批次只使用一个受控 MWORKS/Sysplorer 会话，串行运行；不调参、不改
  Plant、不改控制律。

**通过条件**：

1. `CheckModel` 成功；
2. 仿真到达 `50 s`；
3. 核心跟踪信号有限；
4. `terminal_position_error_m < 5.0`；
5. `maximum_position_error_m < 10.0`。

失败运行是有效负证据，必须保留，不能覆盖或重试成通过结果。

## 三、实验矩阵

### 3.1 电机效率持续故障

基础轨迹为 Figure8：高度 `2 m`，起飞 `5 s`，`x/y` 幅值 `2/1 m`，
角速度 `0.35 rad/s`。仅 rotor 1 的效率在 `15 s` 后保持故障值。

| Profile | 故障窗口 | fault_rotor_effectiveness | 效率损失 |
|---|---|---:|---:|
| M1 | 15-50 s | 0.85 | 15% |
| M2 | 15-50 s | 0.75 | 25% |
| M3 | 15-50 s | 0.65 | 35% |
| M4 | 15-50 s | 0.55 | 45% |

`4 profiles x 2 controllers = 8` 次仿真。

### 3.2 持续风扰

基础轨迹同为 Figure8。世界坐标 `+X` 外力从 `15 s` 持续 35 s。

| Profile | 风扰窗口 | gust_force [N] |
|---|---|---:|
| W1 | 15-50 s | [0.2, 0.0, 0.0] |
| W2 | 15-50 s | [0.4, 0.0, 0.0] |
| W3 | 15-50 s | [0.6, 0.0, 0.0] |
| W4 | 15-50 s | [0.8, 0.0, 0.0] |

`4 profiles x 2 controllers = 8` 次仿真。

### 3.3 持续参数失配

基础轨迹为 SpiralAscent：`radius=1.5 m`、`angular_rate=0.3 rad/s`、
`climb_rate=0.15 m/s`。物理 Plant 的质量和三轴惯量同步缩放，控制器
保持名义参数。

| Profile | mass_scale | inertia_scale |
|---|---:|---|
| P1 | 1.1 | [1.1, 1.1, 1.1] |
| P2 | 1.2 | [1.2, 1.2, 1.2] |
| P3 | 1.3 | [1.3, 1.3, 1.3] |
| P4 | 1.4 | [1.4, 1.4, 1.4] |

`4 profiles x 2 controllers = 8` 次仿真。

**总计：24 次 MWORKS 仿真。**

## 四、配置与批处理入口

| 场景 | 配置文件 | 结果目录 |
|---|---|---|
| 电机效率 | `Config/control_platform/seven_scenario_experiment_profiles_sensitivity_motor_v1.json` | `Results/control_platform/sensitivity_motor_v1/` |
| 风扰 | `Config/control_platform/seven_scenario_experiment_profiles_sensitivity_wind_v1.json` | `Results/control_platform/sensitivity_wind_v1/` |
| 参数失配 | `Config/control_platform/seven_scenario_experiment_profiles_sensitivity_param_v1.json` | `Results/control_platform/sensitivity_param_v1/` |

`Scripts/control_platform/run_seven_scenario_batch.py` 以唯一的
`profile_id` 作为 case 键，允许任意非零数量的 profile，不要求旧
七场景脚本的 `len(profiles) == 7` 或七个不同 `scenario_id`。

```powershell

  --profile Config/control_platform/seven_scenario_experiment_profiles_sensitivity_motor_v1.json `
```

## 五、临界阈值判读

阈值是扫描网格中从低扰动强度向高扰动强度连续通过的最后一个点：

- 电机故障按效率损失递增判读；报告同时给出 `eta` 和效率损失百分比。
- 风扰按 `+X` 力幅值递增判读。
- 参数失配按同步质量/惯量倍率递增判读。

若后续网格出现非单调的 pass/fail 序列，结果报告必须标为非单调，不能
强行给出单一临界值。阈值是当前 Modelica 模型和离散取样的观测边界，
不是实机物理极限或部署保证。

若一个方向上的最高测试点仍通过，报告只能给出“已测范围下界，尚未观察到
失败边界”；不得把该最高测试值表述为已定位的临界阈值。

## 六、分析与报告映射

批次完成后运行：

```powershell
python Scripts/analysis/analyze_sensitivity_results.py `
  --input Results/control_platform/sensitivity_motor_v1 `
  --input Results/control_platform/sensitivity_wind_v1 `
  --input Results/control_platform/sensitivity_param_v1 `
  --output Results/control_platform/sensitivity_analysis_long_v1 `
  --report Docs/灵敏度分析结果报告.md
```

输出包括汇总 JSON/CSV/Markdown 和临界阈值矩阵。报告使用以下章节边界：

- **§8.6**：只描述持续扰动设计、强度梯度和阈值判定条件；不分析恢复时间。
- **§10.1**：电机效率持续下降下的观测阈值和 50 s 跟踪误差。
- **§10.2**：持续风扰下的观测阈值和 50 s 跟踪误差。
- **§10.3**：持续质量/惯量失配下的观测阈值和 50 s 跟踪误差。

这些章节仅引用本批次的 MWORKS MCP 工程证据，不延伸为实机参数真值、
PX4/Gazebo/ROS 部署性能、恢复能力或闭环任务成功结论。
