# 共享内核与数据契约

Status: discussion draft, 2026-06-14.

## 1. Shared Core Purpose

The shared core lets different vehicle families use different simulators and
flight controllers without changing CoSim's public workflow.

It owns:

- run identity;
- scenario identity;
- vehicle identity;
- authority declaration;
- clock and synchronization policy;
- typed input/output contracts;
- backend lifecycle;
- logs, metrics, replay, and evidence manifests.

It does not own:

- backend-specific dynamics equations;
- PX4 or ArduPilot internal logic;
- UE rendering internals;
- ROS2 algorithm implementation;
- Simulink model internals.

## 2. Minimum Run Manifest

Every run should produce a manifest like:

```yaml
run_id: cosim-YYYYMMDD-HHMMSS-vehicle-scenario
vehicle_family: multirotor | fixed_wing | vtol | ducted_model_aircraft
vehicle_id: sunray150_01
scenario_id: factory_gate_course_v1
authority:
  plant_truth: gazebo | jsbsim | mworks | mujoco | isaac | custom
  flight_control: px4 | ardupilot | simulink_codegen | mworks | rl_policy | direct_controller
  algorithm_bus: ros2 | direct_api | training_loop | none
  renderer: ue | gazebo_gui | rviz | isaac | none
  sensor_profile: gazebo_lidar | ue_lidar | replay | truth_debug | none
time:
  sim_clock: ...
  wall_clock_policy: ...
  fixed_step: ...
  rate_targets: ...
evidence:
  logs: []
  bags: []
  ulog: []
  metrics: []
  screenshots: []
  videos: []
  blockers: []
```

## 3. Public Data Contracts

Draft cross-backend contracts:

| Contract | Purpose |
|---|---|
| `VehicleProfile` | physical dimensions, mass/inertia, actuator layout, source provenance, fidelity level. |
| `ScenarioProfile` | world, terrain, obstacles, weather, mission, dynamic objects, review assets. |
| `ControllerInput` | state estimate, setpoint, sensor summary, mode, limits, timestamp. |
| `ControllerOutput` | desired force/moment, attitude/rate target, actuator command, validity, saturation. |
| `ActuatorCommand` | backend-specific motor/servo/throttle/surface command after adapter validation. |
| `VehicleStateFrame` | pose, velocity, angular rate, acceleration, frame, timestamp, authority source. |
| `SensorFrame` | IMU, LiDAR, camera/depth, GPS, barometer, frame/extrinsic/timestamp/noise policy. |
| `LocalMapFrame` | occupancy/voxel/ESDF/obstacle-set with source and validity labels. |
| `TrajectoryFrame` | path, time allocation, dynamic limits, source, validity, and command target. |
| `RuntimeEcho` | accepted command/mode/profile state returned by authority adapter. |
| `EvidenceManifest` | paths and labels for all proof artifacts. |

## 4. Clock And Synchronization

The clock contract must support:

- fixed-step simulation;
- lockstep with autopilot where required;
- ROS2 `/clock` and bag replay;
- UE render interpolation without state write-back;
- batch/RL stepping;
- HIL wall-clock mode.

No backend may silently change the run clock without writing an echo event.

## 5. Authority Gate

Before a run starts, CoSim must validate:

```text
one plant truth selected
one controller authority selected
command adapter available
sensor profile labelled
clock policy declared
evidence output path writable
frontend mode declared
```

If a backend is missing, the run must fail before partial evidence is created.

## 6. Evidence Model

Evidence levels:

| Level | Meaning |
|---|---|
| `source_static` | files/config/contracts exist, but runtime not proven. |
| `headless_smoke` | bounded runtime produced minimal logs without GUI/manual review. |
| `visual_review` | UE/RViz/Gazebo/MWORKS screenshots or video reviewed. |
| `metric_pass` | quantitative metrics computed from reproducible outputs. |
| `closed_loop_pass` | plant/controller/sensor/planner loop passed declared gate. |
| `deployment_candidate` | generated/autopilot/HIL route has separate deployment evidence. |

Do not promote one evidence level into another by wording.
