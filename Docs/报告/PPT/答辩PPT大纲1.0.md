# MoSim 挑战赛答辩 PPT 逐页方案

> 依据：Docs/报告/MoSim_仿真分析报告.docx、Docs/Design/赛题.md，以及已审阅的《实时数据监控与智能分析模拟系统竞标方案》版式模板。
>
> 建议规格：16:9，30 页主讲 + 6 页备份；讲解约 18-20 分钟，现场演示约 3-4 分钟。主讲页遵循“一个结论、1-2 个证据视觉、两句页脚”的固定合同，不把 Word 报告或宽表缩小后直接贴入。
>
> 证据边界：MWORKS/Sysplorer/Syslab 的模型、结果与指标是正式仿真证据；ROS1/PX4/Gazebo 是 px4ctrl 生成 C99 的运行时部署证据；UE、QGC、Studio、RViz 是展示或操作界面，不能单独证明控制性能。所有“通过”均沿用报告当前的 30/48、七场景或相应运行记录口径。

## 参考模板的执行合同

- **标题栏：**白底页面顶部保留统一标题栏和蓝色竖线，标题直接表达结论；章节起始页在标题前增加小号章节号，不单独增加空白分隔页。
- **主证据区：**单图页让核心图占页面约 65%-70%；双图页按“对照”“因果”或“架构 + 实物”左右排列。保留图例、坐标轴、单位、参考/实际颜色与数据来源。
- **页脚短文：**固定在页面下方约 22%-25%，只写两句：第一句解释图证明什么，第二句说明对评审结论的意义。推导、公式和长表转入备份页。
- **结果页：**曲线或轨迹为主证据，右侧最多三枚大数字卡；橙红色仅用于未达标、风险和当前优化重点，青绿色只用于通过或已接通的部署链路。
- **叙事节奏：**国产化 MWORKS 平台 -> MWORKS 的建模、验证与代码生成能力 -> MoSim 在四旋翼赛题上的领域落地 -> 共同实验基础 -> 筛查与量化结果 -> 扩展、部署与交付。结果是主讲高潮，功能不能按目录堆砌。

## 第二部分：统一模型与可审计实验

### 05. 云纵150参照机体、参数 Profile 与坐标链形成共同物理基准

- **叙事角色：**建立可信对象。
- **模板页型：**实物 + 架构页。
- **本页结论：**模型不是抽象理想四旋翼，而是以云纵150装配关系、参数来源和坐标约定为共同物理基准。
- **图源：**

  1. Docs/报告/图/云纵150/Sunray150_Blender_完整装配模型.png
  2. Docs/报告/图/手绘架构/18_坐标系与FrameContract转换关系.png
- **审核预览（PPT/图源副本）：**
  ![审核预览 05.-1](../PPT/图源/图/云纵150/Sunray150_Blender_完整装配模型.png)

![审核预览 05.-2](../PPT/图源/图/手绘架构/18_坐标系与FrameContract转换关系.png)

- **页内文案：**
  装配体保留机架、旋翼、防护结构和机载设备的相对位置，旋翼中心、机臂长度与传感器安装关系进入参数 Profile。几何与质量参数按依据登记，惯量、气动和执行器参数作为可替换的工程种子，使后续台架或飞行数据可以逐层升级。
- **版式：**左侧装配体大图，右侧坐标链；三个小标注只指出旋翼、传感器与 Profile，不展示完整参数表。
- **讲解重点：**用“可升级、可回溯”替代“当前参数已完全等同实机真值”。

- **本页结论：**不同控制算法面对同一机体动力学、旋翼执行器和 X 型控制分配，性能差异才可以归因于控制路线。

- **审核预览（PPT/图源副本）：**

  控制器输出最终进入同一套姿态、角速度、分配、旋翼动态和限幅链路，公共 Plant 在各路线间保持不变。这样同条件筛查和七场景对比的差异可以归因于控制律，而不是被控对象被替换。
