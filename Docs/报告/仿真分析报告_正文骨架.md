# 云纵150四旋翼位姿控制与仿真分析报告

> 证据收敛稿，2026-07-31。本文只陈述本仓库可回链的 Modelica、配置和结果
> 证据；各项数字以
> `Docs/Design/报告手册交付证据总账_P0_20260731.md` 为共同总账。

## 摘要

项目以云纵150实物结构、安装关系、旋翼位置与坐标关系为参考，建立可追溯的
多领域虚拟机体与参数 Profile。几何参数来源于实物测量与装配关系；惯量、
推力/反扭矩系数、电机动态为有来源标注的工程种子参数，可在后续以动力台或
飞行日志逐项替换而不破坏模型接口。

控制器目录含 48 个设计条目，其中 46 个具有 MWORKS 控制模块，Studio 提供
44 条可手动打开的正式全机入口。三种数字不能相互替代：模块存在不表示性能
通过，Studio 可打开也不表示已自动仿真。统一的 ClimbPath 50 s 筛查中，G2
冻结通过 17/48；G3 修复后有效通过 28/48、有效失败 20/48。失败记录分别为
终端位置误差超限 9 条、仿真超时 8 条、仿真 API 失败 2 条和模型检查失败
1 条，均被保留而非归并为“未运行”。

px4ctrl 是本团队自研的 **MWORKS 图形化工程复现、统一接口、代码生成与 SIL
闭环实现**。其位置/速度外环参考 PX4 开源飞控思路，在 MWORKS 中以图形化
建模，经 EquationBridge 接入姿态环、角速度环与控制分配，形成可审查的整机
闭环。图形模型到 C、编译/共享库、CFunction、50 s 整机 SIL 的链路已经完成；
在相同 Dassl 设置和 5001 样本下，位置 RMSE 差为
`1.1481051588325626e-13 m`，姿态最大绝对差为
`3.2070318622956506e-12 rad`，旋翼指令最大绝对差为
`7.354117315117037e-11 rad/s`，均低于既定门限。当前**尚未证明**该哈希对应
的生成 C 已接入 Gazebo/PX4 运行时；运行时部署仍须按独立证据链验证。

七场景比较保留 Official PID 与 px4ctrl 各 7 条、合计 14 条总记录，其中 12 条
为有效记录，2 条电机效率故障记录为无效负样本。灵敏度实际执行 24 条：17 条
通过、3 条物理门限失败、4 条执行阻塞。固定三角队形 Figure8 仅作为离线参考
接入证据，不扩展为在线自主避障或可重构编队结论。

## 1. 赛题对应、范围与主要工作

### 1.1 目标与判据

本项目面向 A8 四旋翼位姿控制与仿真平台，主线是可审查的多领域机体、控制器
接口、全机闭环、结果提取和代码生成。一次控制器结论必须能够沿着

```text
场景 Profile -> MWORKS 模型 -> 原始结果/指标 -> 结论
```

回链。Studio、QGC、RViz 和 UE 仅承担配置、显示或操作表面职责，不能代替
MWORKS 的控制器成功判据。

### 1.2 赛题对应表

| 赛题需要 | 核心实现 | 主要证据 | 当前边界 |

### 1.3 证据阅读规则

1. `pass`、`valid`、`invalid`、`blocked` 等原始状态不被报告文字覆盖。
2. 目录数量、模块数量、入口数量、运行通过数量分别报告，禁止相互换算。
3. 无原始数据路径、原始指标或源码路径的图片、表格和结论不进入本报告。
4. 当前结果来自 MWORKS 主线；Gazebo/PX4 运行时结论必须另行证明。

### 1.4 主要工作

1. 建立云纵150参照的多领域虚拟机体与**可追溯工程参数 Profile**，并给出
   参数分层和替换边界。
2. 建立四类输出边界（ATTITUDE_THRUST / BODY_RATE_THRUST / WRENCH /
   ROTOR_COMMAND）及 Adapter、Runner、Profile 的统一接入合同。
3. 完成 px4ctrl 的 MWORKS 图形化工程复现与**代码生成 + SIL 等价链**；它不被
   表述为新的控制律，且保留运行时部署边界。
4. 完成名义筛选、七场景对比、灵敏度分析，并将 20 条名义失败、2 条无效
   故障记录和 4 条灵敏度执行阻塞作为负样本保留。

## 3. 云纵150参照虚拟机体与参数 Profile

### 3.1 参数分层

| 层级 | 当前来源与对象 | 替换边界 |
|---|---|---|
| 几何 | 实物测量/装配关系；`mworks_rotor_center_m`、MID360 安装位姿 | 可替换为复测或装配图纸值 |
| 质量 | 整机称重与部件累加的工程 Profile 字段 | 可由新的称重表覆盖 |
| 惯量 | CAD 估算和工程经验种子 | 可替换为台架或其他有来源的参数 |
| 推力/反扭矩系数 | 电机厂商数据与文献典型种子 | 可替换为动力台曲线 |
| 电机动态 | 一阶惯性种子参数 `motor_time_constant_up_s/down_s` | 可替换为阶跃试验或日志拟合值 |

Profile 类
`MoSimQuadrotorModel.Parameters.Sunray150VirtualPx4Classic` 明确标注
“Virtual simulation seed only; not real-aircraft system identification truth”。
因此本文不将该 Profile 写为实机辨识结果。

### 3.2 坐标、旋翼与物理链

MWORKS 活动模型使用世界 ENU 与机体 FLU 的内部约定；在外部运行时接口处才需
显式处理 NED/FRD 的坐标转换。四个旋翼位置、旋转指令符号和偏航反扭矩方向在
`Sunray150VirtualPx4Classic.mo` 的 `mworks_rotor_center_m`、
`mworks_spin_command_sign` 和 `mworks_yaw_direction` 中集中定义。物理力/矩
由 `RotorActuatorCore.mo` 生成，再由 `PhysicalWrenchAdapter.mo` 作用于
MultiBody 机体。

完整符号、实际 X 型分配和源码映射见 `公式与推导.md`；该文使用活动模型的
带符号悬停线性化分配，不用理想化对称矩阵替代当前实现。

## 4. 统一控制器接口

| 输出边界 | 含义 | 典型下游 |
|---|---|---|
| `ATTITUDE_THRUST` | 欧拉姿态参考与总推力 | 姿态/角速度内环与分配器 |
| `BODY_RATE_THRUST` | 机体系角速度参考与总推力 | 速率分配链 |
| `WRENCH` | 机体系力/力矩 | `OfflineWrenchAllocator` |
| `ROTOR_COMMAND` | 四个带符号旋翼角速度指令 | `RotorActuatorCore` |

接口的用途是将控制律实现与全机 Runner 解耦。接口存在只能证明接入路径可被
审查；是否通过同条件实验仍以第 10 章状态表为准。

## 5. Official PID 工程基线

Official PID 保留原生连续 `RotorCommandRunner` 边界。它是同条件名义筛查和
七场景的对照之一，不被用来推断所有控制器均具有相同性能。其七场景具体指标
在第 11 章列出，50% 旋翼 1 效率故障记录为无效负样本，不能被改写为通过。

## 6. 控制器目录与实现状态

48 是设计目录条目数，46 是有 Modelica 控制模块的条目数，44 是 Studio 路由表
允许用户写配置并手动打开的正式全机入口数。实现状态来自
`Config/control_platform/control_scheme_catalog.json`，入口状态来自
`Config/control_platform/model_studio_task_routes_v1.toml`。这三组数字描述不同
层级，不能用“实现了 28 个”或“只有两个可打开”概括。

## 7. 负样本处理原则

失败不被删除、重命名或改写为“待跑”。第 10 章按原始状态保留 9 条终端误差
超限、8 条超时、2 条仿真 API 失败和 1 条模型检查失败；第 11 章保留两条无效
电机效率故障记录。这样可以区分接口存在、模型可检查、仿真完成和性能门限四种
不同事实。

## 8. px4ctrl 图形化工程复现与 SIL 等价链

### 8.1 定位

px4ctrl 是本团队自研的 **MWORKS 图形化工程复现、统一接口、代码生成与 SIL
闭环实现**。其位置/速度外环参考 PX4 开源飞控思路，在 MWORKS 中以图形化
建模，经 EquationBridge 接入姿态环、角速度环与控制分配，形成可审查的整机
闭环。它不是“提出的新控制律”，也不等同原 PX4/ROS C++ 源码在运行时的部署。

图形类为
`MoSimQuadrotorModel.Control.Implementations.Sysblocks.PX4CTRL_Original_OuterLoop_Graphical_Sysblock`，
采样时间为 0.01 s，输入为位置、速度、加速度、偏航参考/测量，输出为期望加速度、
滚转/俯仰/偏航命令、总推力和归一化推力。

### 8.2 图形模型到 C 的链路

```text
PX4CTRL_Original_OuterLoop_Graphical_Sysblock
  -> MWORKS GenerateModelCode（C99）
  -> src/control/codegen/px4ctrl/ 生成源与标量 ABI 包装
  -> 静态库/共享库
  -> CFunction Runner
  -> 与图形基线同一 50 s ClimbPath 的整机 SIL
```

产物目录为 `src/control/codegen/px4ctrl/`；构建和哈希复核方法见该目录的
`README.md`、`CMakeLists.txt`、`codegen_manifest.json` 与哈希脚本。

### 8.3 50 s SIL 结果

来源：
`Results/control_platform/px4ctrl_codegen_sil_v1/logs/CLOSED_LOOP_SIL_RESULT.json`。

| 对比项 | 门限 | 聚合差异 | 判定 |
|---|---:|---:|---|
| 位置 RMSE | `< 1e-6 m` | `1.1481051588325626e-13 m` | 通过 |
| 姿态最大绝对差 | `< 1e-8 rad` | `3.2070318622956506e-12 rad` | 通过 |
| 旋翼指令最大绝对差 | `< 1e-6 rad/s` | `7.354117315117037e-11 rad/s` | 通过 |

两条 Runner 使用同一 Dassl、`StartTime=0`、`StopTime=50`、`Tolerance=1e-4`、
`Interval=0.01`，各有 5001 个样本。生成 C 仅替换控制器类型，未修改初始条件、
轨迹或求解器。该证据表明哈希绑定的图形模型与 CFunction 生成代码在 MWORKS
整机闭环中数值等价；当前**尚未证明**该生成 C 已接入 Gazebo/PX4 运行时。

## 12. 显示与运行时边界

Studio 可写配置并手动打开 44 条正式全机入口；它不自动替用户运行仿真。QGC、
RViz 和 UE 的显示、地图、动画或窗口截图不作为 MWORKS 控制性能的验收替代物。
当前文档只陈述本仓库已有 MWORKS 证据；Gazebo/PX4 运行时部署由独立链路负责。

## 13. 代码生成与交付

`src/control/codegen/px4ctrl/` 保存 MWORKS GenerateModelCode 的 C99 产物、标量
C ABI 包装、CMake 构建、固定输入测试、哈希清单和哈希校验脚本。构建产物需要
在目标平台重新编译；既有 Linux `.so` 仅证明该 WSL Linux 环境当时成功构建，
不表示可在任意机器直接运行。

整机 SIL 证据、生成模型哈希、C 源哈希、求解器设置和数值差异均在
`Results/control_platform/px4ctrl_codegen_sil_v1/` 下保留。生成 C 从 MWORKS
图形模型导出后没有作为控制律被重新设计；C 交付物用于重建和核验这一已通过的
图形模型到 C 的链路。

## 14. 可复现性与已知限制

可复现步骤由根目录 `RELEASE_CHECKLIST.md` 固化：设置 `MOSIM_ROOT`，仅加载
`Models/MoSimQuadrotorModel/package.mo` 作为正式根，使用 Studio 写配置和手动
打开 Runner，执行 CheckModel 与人工仿真，读取 Result.msr/metrics，再按代码生成
目录的构建命令测试 C 交付物。

当前已知限制为：20 条 G3 有效失败的四分类、2 条七场景无效电机效率记录、
灵敏度的 3 条物理门限失败与 4 条执行阻塞，以及生成 C 尚未证明接入
Gazebo/PX4 运行时。它们是交付的一部分，不被本报告掩盖。

## 15. 交付审计说明

报告和手册的路径、数字与哈希检查落在

`src/control/codegen/px4ctrl/codegen_manifest.json` 和
`RELEASE_CHECKLIST.md`。任何后续增补试验必须新增结果记录，不得回写本批次的

## 16. 结论

项目已经形成从云纵150参照虚拟机体、统一控制器接口、FormalRunner、结果指标、
px4ctrl 图形模型到生成 C 与 50 s MWORKS SIL 的可审查闭环。当前的可证明范围是
28/48 的 G3 有效通过、两条代表控制器的 12 条有效七场景记录、24 条灵敏度的
17/3/4 状态，以及图形模型到 CFunction 的数值等价。未完成或未证明的部分已在
对应状态和限制中保留，不能被界面展示、源码存在或历史计划替代。
