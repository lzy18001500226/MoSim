# MoSim报告收敛工作台

> 目的：在时间紧张的情况下，把已经发散的 Markdown 报告收敛成可交付写作主线。本文不是最终正文，而是写作控制台：规定哪些内容必须写、哪些图和公式放在哪里、哪些证据不能过度声明。

## 1. 当前问题判断

当前报告质量差的核心原因不是“项目完全没做”，而是下面四类信息没有对齐：

| 问题 | 表现 | 当前处理策略 |
|---|---|---|
| 图文错位 | 图很多，但正文不知道引用哪张，部分图可能和章节主线不匹配 | 先按章节绑定代表图，不追求每张图都用 |
| 公式缺失 | `仿真分析报告_正文骨架.md` 中还没有嵌入公式 | 从 `公式与推导.md` 按章节抽取，不重新写理论百科 |
| 证据口径混乱 | MWORKS、Gazebo、QGC、RViz、UE、FAST-LIO、FUEL容易混成同一种证据 | 每章必须声明验证层级和证据边界 |
| 入口混乱 | `MoSimQuadrotorModel`、`QuadrotorControllerBlocks`、`QuadrotorExperiments` 三个目录看起来像三套项目 | 比赛前不重构，改为在 README、用户手册和报告中解释职责 |

结论：现在优先写报告和整理证据，不做目录重构，不做66个控制器全量重跑，不把Neural-SMC卡成主线阻塞。

## 2. 报告主线

最终报告按“三大块”写：

1. MWORKS建模与控制器仿真验证：这是正文最大篇幅。
2. 代码生成、Gazebo/PX4/MAVROS、FAST-LIO、Diff/FUEL部署验证：作为工程化复验和问题反馈闭环。
3. Model Studio、QGC、RViz、UE展示与交互平台：作为实验组织、运行展示和视频证据入口。

正文叙事顺序：

```text
赛题需求
-> 四旋翼多领域建模
-> 可组合控制器接口
-> 基线PID与改进PID
-> 现代/鲁棒/非线性控制
-> 智能增强、安全和故障容错
-> MWORKS闭环仿真结果
-> 三机编队
-> 代码生成和Gazebo/PX4复验
-> 部署问题回灌MWORKS再优化
-> 总结
```

## 5. 公式嵌入优先级

公式源文件：

```text

```

正文不需要把77个公式全部塞满。优先嵌入这些：

| 优先级 | 公式编号 | 放入章节 | 作用 |
|---|---|---|---|
| 必须 | F-01到F-09 | 第3章 | 证明建模不是只画图 |
| 必须 | F-10到F-16 | 第5章 | 支撑PID族和改进PID |
| 必须 | F-18、F-19、F-20 | 第6章 | 支撑LQR/LQI/LQG |

| 必须 | F-28、F-39、F-40 | 第6章 | 支撑INDI和MPC主线 |
| 必须 | F-44到F-49 | 第7章 | 支撑扰动补偿和神经残差 |
| 必须 | F-51到F-58 | 第7章/第10章 | 支撑安全和故障容错 |
| 必须 | F-68到F-77 | 第8章/第9章/第10章 | 支撑结果分析 |
| 可选 | F-23、F-37 | 第6章/第7章 | μ-Synthesis和Neural-SMC，只写理论和待补证据 |

写作规则：

- 公式后必须解释变量。
- 公式后必须说明它和项目模型、控制器或指标的关系。
- 对没有完整证据的算法，公式只能证明理论覆盖，不能证明实验完成。


### 7.2 不能过度声明

| 名称 | 正确写法 |
|---|---|
| AWFF | 增强补偿层，不是独立整机控制器 |
| Neural Residual | 神经网络扰动残差补偿，不是完整神经网络飞控 |
| Neural-SMC | 理论和后续闭环尝试，除非另有最新证据 |
| μ-Synthesis | 鲁棒控制理论覆盖和扩展方向 |
| Diff/FUEL | 规划与部署验证，不是控制器本体 |
| QGC/UE/RViz | 展示和交互证据，不是控制性能证据 |
