## 模块 A：开场叙事（黑底/标题卡）

2024 年起，国外主流仿真工具对国内高校全面断供。工具没了，但课题不等人。

MoSim 是我们基于国产 MWORKS 平台从零搭建的完整工具链——Modelica 多领域建模、48 个控制器统一验证、C99 代码生成、ROS/Gazebo 运行时部署，覆盖从算法设计到实际飞行的全部环节。

## 模块 A2：物理建模过程（录屏/图片：Blender 装配体 + Modelica 模型）

整个平台的起点是真机 1:1 建模。我们拿到云纵 150 实物后，在 Blender 中完成了完整的逆向装配——旋翼中心坐标、机臂长度、传感器安装位，每个几何参数都从实物测量得来。

比如 MID360 激光雷达的安装：它相对机体中心偏移 32.3 mm、高出 50.2 mm，并且存在 −90° 的 yaw 旋转——因为雷达出厂坐标系和 PX4 机体系定义不同，这个坐标变换我们在 Modelica Profile、Gazebo SDF 和 FAST-LIO 配置三个地方都做了同步标定，保证仿真链路中坐标系全程一致。

物理参数分五层管理：几何层和质量层来自实测，惯量和气动系数用工程种子填充，每一层都标注了来源和替换条件。后续拿到台架数据或飞行日志，可以逐层升级而不破坏已有的验证结果。这套参数体系最终形成了 Modelica 的 Profile 类，整机模型基于 MultiBody 库搭建，六自由度动力学完整可解。

## 模块 H：代码生成过渡（录屏：代码生成工作区 或 VS Code 打开生成代码）

到这里，所有验证都在 MWORKS 仿真环境内完成。但仿真通过不等于能飞——我们需要把模型变成真正能部署的代码。

MWORKS 代码生成器将 Sysblock 图形化模型自动导出为纯 C99 源码。生成的代码只依赖标准数学库，通过 CMake 构建为静态库和共享库，可以直接嵌入任何 C/C++ 工程。

关键是数值等价性：我们的测试表明，生成代码与 MWORKS 仿真结果之间的最大偏差在 10 的负 13 次方量级——这是双精度浮点的舍入噪声，不是算法误差。模型里验证过的控制律，导出后行为完全一致。

## 模块 J：Gazebo 仿真环境（录屏：Gazebo 中无人机飞行）

这是 Gazebo 物理仿真环境。我们的四旋翼模型在这里接受完整的 ROS/PX4 栈驱动——传感器仿真、物理引擎、控制律、状态估计全部在环。

说一下状态反馈的通路设计：水平方向的 XY 定位由 FAST-LIO 融合激光雷达和 IMU 提供，高度方向使用激光定高传感器独立输出。这样设计是因为 FAST-LIO 水平精度高但 Z 向容易漂移，而激光定高在垂直方向有厘米级绝对精度，两路互补让控制律获得三轴高质量状态反馈。

这里跑的是完整的 ROS/PX4 栈——传感器仿真、物理引擎、控制律、状态估计全部在环，带碰撞检测、气动干扰和传感器噪声。生成代码在这个环境下依然稳定工作，代码生成质量经得起检验。

## 模块 K：FAST-LIO 建图（录屏：RViz 点云累积画面）

FAST-LIO 是我们的实时状态估计方案。它融合激光雷达点云和 IMU 数据，以 100Hz 以上的频率输出位姿估计，同时在线构建环境地图。

画面中看到的彩色点云就是 FAST-LIO 实时累积的三维环境重建。后续所有规划和控制都依赖这个高频状态反馈——定位不准，控制律再好也飞不稳。

## 模块 L：Diff-Planner 局部避障 + 风扰飞行（录屏：RViz 中轨迹规划画面）

Diff-Planner 是局部轨迹优化器。它在 FAST-LIO 提供的地图上，实时求解一条满足动力学约束、远离障碍物且时间最优的飞行轨迹。

画面中绿色是参考路径，红色是无人机实际跟踪的优化轨迹。可以看到在遇到障碍时，Diff-Planner 在毫秒级重新规划，无人机平滑绕行而不减速停车。

这段飞行同时叠加了持续风扰——外风从侧向持续施加，控制器需要一边补偿扰动一边跟踪不断变化的避障轨迹。生成 C99 控制核心在风扰加避障的双重压力下依然稳定跟踪，验证了从 MWORKS 模型到运行时部署的鲁棒性一致性。

## 模块 M：FUEL 自主探索（录屏：FUEL 探索过程长镜头）

FUEL 是自主探索规划器——无人机不需要预设路径，它自己决定去哪里。算法持续评估环境中的未知区域，选择信息增益最大的观测点作为下一个目标，直到整个空间探索完毕。

画面中无人机正在自主探索一个未知的室内环境。没有人给它指路，它一边建图一边自己决定往哪飞，直到把整个空间扫完。从"跟着轨迹走"到"自己决定去哪"，能力层级完全不同。

## 模块 M2：Gazebo 三机编队（录屏：Gazebo 三机同屏 + RViz 多机轨迹）

前面的单机演示验证了感知-规划-控制的完整栈。现在把同一套栈复制三份，在 Gazebo 中跑三机编队。

当前用的是 Swarm Formation 固定队形算法：三架无人机通过 ROS 多机通信共享各自位姿，编队节点按固定三角偏移生成各机的参考轨迹，每架独立运行 PX4 飞控和生成 C99 控制核心。通信拓扑是全连接——任何一架的状态对其他两架可见，队形保持靠各机本地跟踪各自的偏移参考实现。

后续我们还会接入 Diff-Swarm 动态编队——和当前固定队形不同，Diff-Swarm 允许编队形状在线重构，每架无人机自主规划避障轨迹的同时协商队形变化，属于分布式在线优化。两种算法分别对应"队形刚性保持"和"队形柔性重构"两类应用需求。

## 补充模块 P：算法原理简述（可插入长镜头空隙）

### P1：FAST-LIO 原理（~15 秒）

FAST-LIO 的核心是增量式卡尔曼滤波器与 ikd-Tree 数据结构的结合。激光雷达每一帧点云不是全量匹配，而是增量插入到动态 KD 树中，同时用紧耦合的 IMU 预积分提供高频预测。这让它在计算资源有限的嵌入式平台上也能达到 100Hz 以上的状态输出。

### P2：Diff-Planner 原理（~15 秒）

Diff-Planner 将轨迹优化建模为带约束的非线性规划问题。它用可微的距离场表示障碍信息，通过梯度下降在线求解时间最优轨迹。可微框架的优势是：障碍约束的梯度信息可以直接回传到轨迹参数，收敛速度比传统采样方法快一个数量级。

### P3：FUEL 原理（~15 秒）

FUEL 的核心思想是分层决策：全局层维护一张 Frontier 信息图，评估每个未探索边界的信息增益和到达代价；局部层在选定目标后规划安全可行的飞行路径。两层解耦让探索决策不被局部避障干扰，同时保证全局探索效率接近最优。
