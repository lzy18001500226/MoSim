# MoSim系统集成接口与编排架构

> 状态：当前接口架构专题规范，2026-06-24。
>
> 本文回答“控制器、状态源、轨迹、规划、生成代码、前端和运行脚本如何耦合”。
> 本文不定义具体控制律，也不替代各专题规范；它只冻结跨模块连接方式。

## 1. 设计目标

MoSim后续会同时包含多类控制器、FAST-LIO、Diff-Planner当前链路、EGO/EGO-Swarm参考链路、故障扰动、
安全过滤、MWORKS生成代码、RViz/UE/Web/QGC显示和自动评价。若各模块
直接互相调用内部变量，后续控制器扩展和代码生成会失控。

因此集成原则是：

```text
模块之间只通过标准frame、profile、manifest和adapter耦合；
控制器core不依赖ROS、MAVROS、Gazebo、UE、QGC、YAML或Python；
前端只提交experiment profile，不直接拼控制链或运行裸sh；
Orchestrator负责校验、生成launch plan和记录证据；
生成代码只替换controller core，不替换状态适配、轨迹服务、安全和日志层。
```

## 2. 总体运行拓扑

```text
Gazebo / Sunray Plant
  -> SensorAdapter
  -> StateAdapter
  -> StateFrame
                      -> Logger / Evaluator
TrajectoryServer ----> ControllerHost
PlannerAdapter ------> ControllerHost
                      -> SafetySupervisor
                      -> CommandAdapter
                      -> MAVROS / PX4
                      -> Gazebo / Sunray Plant

FAST-LIO / Diff-Planner / planner references
  -> StateFrame / MapFrame / ReferenceFrame / DiagnosticsFrame

RViz / UE / Web / QGC
  -> DisplayFrame / StatusFrame / MetricsFrame
```

关键边界：

```text
StateAdapter对状态源做时间戳、坐标系、有效性和频率对齐；
TrajectoryServer在控制周期求值轨迹，不向控制器发送离散点列表；
ControllerHost只调用IController或生成代码wrapper；
SafetySupervisor拥有最终发布前的否决权；
CommandAdapter负责ATTITUDE_THRUST到MAVROS/PX4消息的映射；
Display层只读，不回写控制结果。
```

## 3. 标准Frame

### 3.1 FrameHeader

所有跨模块数据必须带统一头：

```text
FrameHeader:
  source_id
  profile_id
  frame_id
  child_frame_id
  timestamp_ros
  timestamp_sim
  sequence
  valid
  status_code
```

`timestamp_ros`用于ROS消息时间；`timestamp_sim`用于仿真和日志对齐。若二者
不可同时提供，必须显式标注。

### 3.2 StateFrame

```text
StateFrame:
  header
  position_m[3]
  velocity_mps[3]
  attitude_quat_wxyz[4]
  angular_velocity_radps[3]
  linear_acceleration_mps2[3] optional
  covariance_pose[36] optional
  covariance_twist[36] optional
  source_type
  height_source_type
  estimator_status
```

用途：

```text
PX4/MAVROS融合状态；
FAST-LIO经PX4 EKF融合后的状态；
Gazebo truth debug状态；
混合Z定高替身状态。
```

不同来源必须进入不同 `state_source_profile`，不得静默混合。

### 3.3 ReferenceFrame

```text
ReferenceFrame:
  header
  position_ref_m[3]
  velocity_ref_mps[3]
  acceleration_ref_mps2[3]
  jerk_ref_mps3[3] optional
  snap_ref_mps4[3] optional
  yaw_ref_rad
  yaw_rate_ref_radps optional
  trajectory_id
  reference_mode
```

控制器manifest必须声明自己需要到哪一阶参考：

```text
PID / px4ctrl / SE3 Basic: p, v, a, yaw
DFBC-Full: p, v, a, jerk, snap, yaw
MPC/NMPC: time horizon or sampled reference sequence
```

### 3.4 ControlCommand

第一阶段只正式开放：

```text
ControlCommand:
  header
  interface_type: ATTITUDE_THRUST
  desired_attitude_quat_wxyz[4]
  desired_collective_thrust_N
  controller_status
  saturation_flags
  diagnostics
```

以下字段可在结构中预留，但第一阶段不得作为正式发布接口：

```text
body_rate_ref_radps[3]
wrench_ref_NNm[6]
rotor_thrust_N[4]
rotor_speed_radps[4]
```

### 3.5 DisplayFrame和MetricsFrame

DisplayFrame只服务显示：

```text
vehicle_pose
vehicle_path
reference_path
point_cloud_summary
grid_map_summary
planner_status
controller_status
experiment_status
```

MetricsFrame只服务评价：

```text
run_id
profile_hash
rmse
max_error
steady_state_error
overshoot
settling_time
constraint_violation
localization_error
```

屏幕画面不得作为指标计算来源。

### 3.6 UE/前端显示数据权威

UE、RViz、Web和QGC统一归入显示/操作层。它们可以读取`DisplayFrame`、
`StatusFrame`和`MetricsFrame`，但不能把显示坐标或渲染对象反写成控制状态源。

| 显示对象 | 数据来源 | 可用于 | 禁止用途 |
| --- | --- | --- | --- |
| 飞机三轴和轨迹 | `StateFrame`或truth review frame，按profile标注 | 审核位置/姿态/轨迹是否一致 | 反推控制输入 |
| FAST-LIO累计点云 | FAST-LIO registered cloud/map | 定位和建图可视化审核 | 代替ATE/RPE评价 |
| 栅格/局部地图 | planner/local map输出 | 规划器审核 | 作为全局truth地图 |
| UE画面/摄像头窗口 | 渲染层或相机传感器topic | 展示、视频、第一视角审核 | 作为控制器成功判据 |
| 前端按钮/下拉/滑块 | `ExperimentProfile`字段 | 选择已注册profile并请求运行 | 直接拼裸命令或绕过兼容性检查 |

若未来UE能导出truth，也只能进入带`control_input_allowed=false`的评价truth
profile；除非单独冻结新状态源实验组，否则不得输入控制器。

## 4. Controller Core ABI

所有控制器最终进入统一runtime接口：

```cpp
class IController {
public:
  bool init(const ControllerParams& params);
  void reset(const ControllerReset& reset);
  ControllerOutput update(
      const ControllerState& state,
      const TrajectoryReference& reference,
      double dt);
};
```

架构约束：

```text
controller core不得include ROS/MAVROS/Gazebo/UE头文件；
controller core不得自己读取topic；
controller core不得自己发布MAVROS命令；
controller core不得访问Gazebo truth；
controller core必须显式接收dt、enable、reset和参数；
controller core输出物理语义，不输出散落的私有MAVROS归一化油门。
```

MWORKS生成代码接入路线：

```text
MWORKS/Sysblock model
  -> generated C code
  -> generated_c_abi_wrapper
  -> IController C++ adapter
  -> ControllerHost
  -> SafetySupervisor
  -> CommandAdapter
```

离线一致性比较对象：

```text
原始控制器core
抽取后的C++ core
MWORKS模型
MWORKS生成C代码
```

比较语义：

```text
期望姿态几何误差；
物理总推力N；
积分状态；
饱和标志；
状态码；
诊断量。
```

## 5. Profile和Manifest

### 5.1 ControllerManifest

每个控制器必须声明能力，而不是靠名字猜测：

```yaml
id: se3_basic
implementation: cpp
output_interface: ATTITUDE_THRUST
required_state:
  - position
  - velocity
  - attitude
  - angular_velocity
required_reference:
  - position
  - velocity
  - acceleration
  - yaw
optional_reference:
  - yaw_rate
rate_hz: 100
compatible_adapters:
  - mavros_attitude_thrust_v1
compatible_safety_filters:
  - basic_limiter_v1
realtime_class: onboard_candidate
maturity: baseline_candidate
```

### 5.2 ExperimentProfile

前端、脚本和自动测试只提交实验配置：

详细字段、最小schema、兼容性拒绝规则、自动降级边界、Launch Plan契约和
Run Manifest契约以
`Docs/Design/架构/00_架构与任务/ExperimentProfile与兼容性矩阵.md` 为准。
本文只保留跨模块编排概览。

```yaml
experiment_id: figure8_px4ctrl_px4_state_v1
scenario_profile: obstacle_figure8_v1
plant_profile: sunray150_gazebo_v1
sensor_profile: mid360_imu_height_camera_v1
state_source_profile: px4_mavros_fused_v1
height_source_profile: px4_or_gazebo_rangefinder_proxy_v1
truth_profile: gazebo_truth_eval_only_v1
frequency_profile: attitude_thrust_100hz_v1
trajectory_profile: figure8_v1
planner_profile: none
controller_profile: px4ctrl_attitude_thrust_v1
augmentation_profile: none
safety_profile: basic_limiter_v1
adapter_profile: mavros_attitude_thrust_v1
fault_profile: none
disturbance_profile: none
display_profile: rviz_gazebo_v1
evaluation_profile: tracking_metrics_v1
```

Profile必须计算哈希并写入日志、指标和报告。

最小Profile槽位如下。槽位名必须稳定；具体字段可以在后续schema中扩展。

| 槽位 | 负责内容 | 禁止混淆 |
| --- | --- | --- |
| `scenario_profile` | 地图、障碍物、任务区域、车辆数量和初始位姿 | 不记录plant动力学参数 |
| `plant_profile` | 机体、质量、惯量、电机、桨叶、执行器模型和Gazebo/Sunray版本 | 不记录控制器参数 |
| `sensor_profile` | MID360、IMU、定高、摄像头、噪声、延迟、外参和频率 | 不替代state source |
| `state_source_profile` | 控制器实际使用的位置、速度、姿态和角速度来源 | 不静默混入truth |
| `height_source_profile` | Z轴/定高来源，允许标注Gazebo定高替身或真机激光定高 | 不冒充FAST-LIO完整三维定位 |
| `truth_profile` | 评价真值来源，默认`control_input_allowed=false` | 不输入控制器 |
| `frequency_profile` | 控制、状态对齐、轨迹求值、规划、显示和日志频率 | 不靠topic实测结果反推配置 |
| `trajectory_profile` | 手写任务、样条、阶跃、8字、螺旋等参考轨迹 | 不直接发布MAVROS控制 |
| `planner_profile` | Diff-Planner当前入口、EGO/EGOv2/EGO-Swarm参考/后续对照、FUEL/RACER第二阶段探索及其地图输入 | 不拥有最终控制发布权 |
| `controller_profile` | 名义控制器core和参数 | 不包含SafetySupervisor和Adapter私有逻辑 |
| `augmentation_profile` | INDI、L1、DOB/ESO、AWFF、NN/Fuzzy等补偿模块 | 不掩盖基准控制器问题 |
| `safety_profile` | 限幅、geofence、CBF、急停和发布前否决规则 | 不写入控制器内部状态 |
| `adapter_profile` | ATTITUDE_THRUST/BODY_RATE/WRENCH/ROTOR映射 | 不改变控制器数学输出语义 |
| `fault_profile` | 故障类型、对象、强度、时间和随机种子 | 不通过修改控制误差伪造物理故障 |
| `disturbance_profile` | 风扰、负载、地效、参数摄动和传感器退化 | 不和fault_profile混写 |
| `display_profile` | RViz、Gazebo GUI、UE、Web、QGC窗口和显示桥 | 不作为指标来源 |
| `evaluation_profile` | 指标、truth对照、排行榜分组和证据留存规则 | 不参与控制闭环 |

## 6. Orchestrator流程

```text
1. 读取experiment_profile
2. 解析各profile和manifest
3. 做schema检查
4. 做兼容性检查
5. 生成launch plan
6. 启动runtime
7. 监控topic、状态、频率和超时
8. 收集日志和证据
9. 计算metrics
10. 输出run packet
```

Launch Plan不是用户手写命令集合，而是由固定模板生成：

```yaml
launch_plan:
  run_id: 20260624_figure8_px4ctrl
  steps:
    - id: gazebo
      template: sunray_gazebo.launch
      profile: sunray150_gazebo_v1
    - id: mavros
      template: mavros_px4.launch
      profile: px4_mavros_v1
    - id: controller
      template: controller_host.launch
      profile: px4ctrl_attitude_thrust_v1
    - id: rviz
      template: rviz_review.launch
      profile: rviz_gazebo_v1
```

裸 `sh` 只能作为模板内部实现细节，不作为架构级实验定义。

## 7. 兼容性检查

必须拒绝的组合：

```text
控制器要求jerk/snap，但轨迹只提供p/v/a；
控制器输出BODY_RATE_THRUST，但adapter只支持ATTITUDE_THRUST；
FAST-LIO未通过定位门禁，却被选为controller_state；
NMPC缺失plant_param_profile或约束profile；
安全profile要求geofence，但scenario没有边界定义；
display profile要求UE数据，但runtime没有DisplayFrame bridge。
```

允许但必须显式标注的组合：

```text
Gazebo truth debug state用于控制器极限能力测试；
Gazebo Z定高替身用于模拟真机激光定高；
FAST-LIO直接输出用于独立定位评价；
UE truth用于显示或调试，不用于规划器和控制器。
```

## 7.1 Profile拒绝、降级和恢复契约

Orchestrator的默认行为是“先拒绝错误组合”，不是运行后再靠人工判断。任何
Profile检查失败都必须输出结构化原因：

```yaml
profile_rejection:
  run_id: <planned_run_id>
  rejected_stage: compatibility_check
  rejected_profile: <profile_id>
  reason_code: <stable_error_code>
  human_reason: <short_reason>
  safe_alternative_profile: <optional_profile_id>
  control_started: false
```

只有在控制权尚未发布、且存在同层级安全替代时，才允许自动降级。自动降级
必须写入run packet，不能静默替换用户选择：

| 问题 | 默认动作 | 可建议的替代 |
| --- | --- | --- |
| 控制器所需参考阶次缺失 | 拒绝启动 | 选择Basic版本控制器或换TrajectoryServer |
| 状态源未通过门禁 | 拒绝进入controller_state | 切回`px4_mavros_fused_v1`或仅做评价 |
| Adapter不支持控制输出层级 | 拒绝启动 | 换支持的adapter或换控制器输出层级 |
| PX4 Module未通过影子门禁 | 拒绝控制发布 | 回到ROS/MAVROS `ATTITUDE_THRUST`路径 |
| 显示Profile缺依赖 | 允许控制运行但标记display degraded | 切回RViz/Gazebo审核Profile |
| 评价Profile缺truth/log | 拒绝宣称指标 | 只允许调试运行，不进入排行榜 |

运行开始后，Profile必须锁定。除人工停止和安全回退外，不允许前端在飞行中
直接改controller、state_source、adapter或plant profile。允许在线修改的仅限
HOT参数，且必须经过Controller Manager或PX4参数系统的原子更新边界。

## 8. 多频率和时间对齐

各模块频率不同，不能简单认为所有topic同步：

```text
controller_update: 100Hz first-stage baseline
state_adapter: align to controller clock
trajectory_server: evaluate reference at controller clock
planner: 10-20Hz or event triggered
FAST-LIO: measured profile, not assumed
display: 30-60FPS, drop stale frames
logger: raw topic plus aligned frame
```

StateAdapter负责：

```text
检查状态超时；
选择最近有效状态；
必要时插值或保持；
记录延迟；
记录丢帧；
输出状态有效性标志。
```

TrajectoryServer负责：

```text
轨迹函数/样条求值；
输出p/v/a/jerk/snap/yaw；
检查连续性；
处理轨迹结束和阶段切换；
记录参考有效性。
```

## 9. 安全和发布权

发布链路：

```text
ControllerOutput
  -> SafetySupervisor
  -> CommandAdapter
  -> MAVROS/PX4
```

SafetySupervisor拥有最终发布前否决权：

```text
状态无效；
参考超时；
姿态/推力/速度超限；
geofence违规；
控制器诊断为invalid；
人工急停；
profile不匹配；
外部模块超时。
```

任何控制器都不能绕过SafetySupervisor直接发布最终控制命令。

## 10. 最小实现门禁

最小闭环进入下一阶段前，至少要有：

```text
StateFrame定义和日志；
ReferenceFrame定义和日志；
ControlCommand定义和日志；
scenario/plant/sensor/state/height/truth/frequency profile；
trajectory/planner/controller/augmentation/safety/adapter profile；
fault/disturbance/display/evaluation profile；
ControllerManifest最小字段；
Profile Validator最小检查；
Launch Plan记录；
run_id和profile_hash；
tracking metrics；
RViz/Gazebo审核profile。
```

MWORKS生成代码进入闭环前，额外需要：

```text
generated C ABI wrapper；
IController adapter；
离线四方一致性；
float32/float64容差；
reset/enable/dt语义一致；
物理推力N语义一致；
禁止ROS/Gazebo依赖检查。
```
