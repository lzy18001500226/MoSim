# 0. 当前主线冻结：px4ctrl与大系统最小闭环

## 0.1 当前硬规则

```text
px4ctrl是第一阶段一切控制基准。
第一阶段唯一实际输出层级是ATTITUDE_THRUST。
控制输入默认使用PX4/MAVROS融合状态，Gazebo truth默认只用于评价。
Gazebo Z只有在显式height_source_profile中才能作为真机定高替身进入状态源。
Sunray/Gazebo是当前plant、传感器、truth、故障和扰动运行权威。
MWORKS模型后续向Sunray/Gazebo和真机参数靠拢。
FAST-LIO不参与px4ctrl初始参数是否调好的验收。
Diff-Planner单机和Diff-Planner swarm三机可以在px4ctrl稳定后推进工程基线，不等待MWORKS Golden Slice。
EGO、EGOv2和EGO-Swarm作为参考与后续对照，不作为当前三机最小闭环硬门槛。
FAST-LIO经PX4 EKF融合后的闭环A/B对比是强制状态源替换分支，但不阻塞Diff-Planner工程基线。
离线一致性未通过，不得进入Gazebo闭环回灌。
```

## 0.2 术语冻结

本文中“最小闭环”必须带限定语使用，禁止混用。

```text
控制器最小闭环：
  指 px4ctrl Golden Slice。
  覆盖 G-PX4CTRL-0 至 G-PX4CTRL-7。
  目标是证明原始px4ctrl、抽取core、MWORKS模型、生成C代码和Gazebo回灌一致。

大系统最小闭环V1：
  指当前比赛展示所需的最小工程闭环。
  覆盖 px4ctrl、FAST-LIO独立评价、Diff-Planner单机、Diff-Planner swarm三机、MWORKS版px4ctrl_core接入Diff单机。
  目标是证明控制器、规划器、集群、定位/建图评价、PX4/MAVROS/Gazebo可以组成可复现工程闭环。

状态源替换闭环V1.1：
  指FAST-LIO对齐后经PX4 EKF融合，再由同一px4ctrl/控制器读取MAVROS local position完成A/B对比。
  它是必须完成的后置分支，但不作为Diff-Planner工程基线启动前置条件。
```

默认解释：

```text
G-PX4CTRL-0..7 = 控制器最小闭环门禁。
Goal 1..6 = 大系统最小闭环V1执行颗粒度。
Branch FL-EKF = FAST-LIO状态源替换闭环V1.1。
```

| Goal 2 | px4ctrl轨迹与参数冻结 | G-PX4CTRL-2、G-PX4CTRL-3、G-PX4CTRL-4 | 原始Sunray px4ctrl完成8字、螺旋、阶跃/圆形、安全异常、参数调优和冻结 | core抽取、MWORKS重建、规划/集群 |

## 0.4.1 G9控制器族扩展长任务

G9不是完整UI任务，也不是一次性铺开所有高级控制器。G9的目标是：

```text
控制器替换验证
  +
UI-ready工程接口
  +
G8生成代码闭环模板复用
```

因此每个G9子任务除了让控制器能飞，还必须沉淀控制器注册表、实验
Profile、统一代码生成入口、统一编译入口、统一运行入口、统一RViz/Gazebo
打开入口、统一日志指标输出和统一pass/fail结果格式。后续完整界面只读取
这些Profile和命令契约，不能理解或硬编码具体控制器内部公式。

首批G9只释放以下6个控制器/增强方向：

| 子任务 | 对象 | 控制链路位置 | 第一阶段输出层级 | 完成定义 |
| --- | --- | --- | --- | --- |
| G9-0 | Controller Registry、ExperimentProfile、Launch Plan和结果Manifest | 工程接口层 | 不直接控制 | UI-ready接口可校验；脚本、后端和未来UI使用同一Profile和命令契约 |
| G9-A | 官方PID baseline | 名义位置/速度外环 | `ATTITUDE_THRUST` | 用G8模板完成MWORKS/codegen、离线一致性、单机Gazebo和三机Diff回归 |
| G9-B | SE3 Basic / Geometric controller | 名义几何外环 | `ATTITUDE_THRUST` | 证明非PID结构也能复用同一State/Reference/Adapter/Metric接口 |
| G9-C | DFBC Basic或DFBC-Jerk | 名义微分平坦外环 | `ATTITUDE_THRUST`，高阶版本可声明后续`BODY_RATE_THRUST` | 使用p/v/a/yaw起步；仅当Trajectory Server提供可靠jerk/snap时释放高阶模式 |
| G9-D | SMC，优先Classical或Boundary-layer SMC | 鲁棒名义外环 | `ATTITUDE_THRUST` | 建立滑模鲁棒对照，记录抖振、边界层和执行器饱和 |
| G9-E | INDI / PID-INDI增强 | 增强模块或姿态/角速度内环候选 | 第一阶段只做有界增强，不抢最终控制权 | 不作为独立名义控制器混报；需消融对比证明贡献 |
| G9-F | NMPC外环 / trajectory tracking NMPC | 优化控制外环 | 首版优先`ATTITUDE_THRUST`或等效外环输出 | 必须有plant、约束、求解器、超时和上一可行解Profile；实时性不过不得进入回归 |

G9每个控制器进入实现前必须完成资料审计：

```text
开源代码或论文公式来源；
控制链路位置；
所需状态、参考阶数和输出层级；
是否适合ATTITUDE_THRUST；
MWORKS/Sysblock或CFunction建模路线；
C/C++代码生成可行性；
ROS/Sunray/px4ctrl adapter接入点；
已知失败模式和禁止声明。
```

G9默认不做完整前端。允许先实现命令契约和最小实验平台骨架，但完整UI、
UE集成、按钮面板和权限系统属于S11正式任务。G9期间任何按钮或脚本入口
都必须调用Profile Validator和Launch Plan，不得直接拼接裸命令替代实验定义。

## 0.4.2 G9.5/G9.6/G10/G11控制器长任务

本阶段不是“挑一个最好控制器冻结”，而是把控制器质量、增强层和代码生成闭环
依次做实。执行顺序固定如下：

执行原则：

```text
先站在现有论文、作者代码、开源MATLAB/Simulink/C++工程和官方文档上复现；
再做MoSim接口适配和必要的安全封装；
最后用Gazebo/Sunray/PX4/MAVROS/RViz运行证据判断是否真实提升。

静态公式、离线脚本或MWORKS内部仿真都不能替代Gazebo闭环结论。
若论文级控制器没有提升，也必须保留失败归因，而不是继续调静态模型自洽。

每个控制器或增强层的实际推进循环固定为：

资料/开源审计
  -> 最小接口适配
  -> 静态和离线准入
  -> 最小Gazebo/Sunray场景
  -> 完整基础轨迹矩阵
  -> Diff单机/三机回归
  -> MWORKS/codegen闭环。

静态和离线准入只回答“能不能进真实闭环测试”，不能作为阶段完成。若已有可
运行核心，下一步必须转入最小Gazebo场景或写明阻塞原因。MWORKS live阶段若
遇到登录、许可、授权、GUI-error或未知阻塞，立即停止并按MWORKS技能规则形成
blocker；非许可类崩溃或模型连线错误必须先截图/记录原始错误，再做一次有界
重启或修复，不能盲目重试到成功。
```

| 阶段 | 目标 | 完成定义 | 进入下一阶段条件 |
| --- | --- | --- | --- |
| G9.5 | 高性能名义控制论文复现 | 复现基于高阶参考的DFBC/NMPC对照路线；同场景比较px4ctrl、SE3 Basic、DFBC Basic、NMPC outer和论文级控制器误差 | 有静态门禁、参考轨迹字段审计、至少单机基础轨迹A/B指标；若效果无提升，形成失败归因 |
| G9.6 | 抗风/鲁棒DFBC论文复现 | 复现smooth bounded feedback、扰动补偿或等价鲁棒项；在风扰、质量误差、推力衰减代理下做消融 | 证明鲁棒项有独立贡献，或明确不适合当前ATTITUDE_THRUST/PX4内环边界 |
| G10 | 增强层矩阵 | 当前冻结为backlog；已完成的探针和失败/静态证据只作为后续选择依据，不作为当前主线完成项 | G9 codegen闭环完成后，优先重新打开L1/AWFF、安全过滤、故障分配的最小Gazebo验证；每个增强模块都声明作用位置、输入输出、兼容控制器、禁用条件、安全权责和消融实验 |
| G11 | 全控制器MWORKS/codegen闭环 | G9-A..G9-F中进入implemented或accepted的控制器先全部按G8模板完成模型、生成代码、离线一致性、ROS/Sunray回灌和Gazebo回归；增强组合后置 | 所有未完成项必须有明确blocker、降级或撤销理由；不得只对最佳候选做codegen |

G10第一轮“做完”的含义是覆盖关键工程类别，不是实现所有论文变体。第一轮必须覆盖：

```text
DOB/ESO: 扰动估计和有界补偿；
L1/AWFF: 风扰、气动阻力或模型误差补偿；
INDI: 从G9-E整理为标准增强层，明确是否仍复用PX4内环；
Safety Filter: 推力、倾角、角速度、加速度、边界和障碍距离保护；
Fault Allocation: 推力衰减、电机失效和控制分配降级；
Parameter Scheduling: 质量、电池、推力系数或工况变化下的参数调度；
NN/Fuzzy Compensation: 先作为有界残差或参数调节研究候选，不默认进入安全关键闭环。
```

后置展示路线固定为：

```text
G12 UE真值地图、Gazebo物理地图、RViz点云/栅格地图一致性；
    先调研现有UE/Unreal、Gazebo、SDF/URDF、heightmap、mesh和collision导入案例；
    目标是尽量无损或仅因网格/体素量化产生可解释损失，不接受手工积木式替代地图；
    若现有工具链无法给出可验证导入质量，则形成放弃或降级结论。
G13 UE渲染和QGC二次开发界面集成，目标是RflySim式体验；
    QGC只提交ExperimentProfile、目标、控制器选择和显示请求；
    Orchestrator负责校验、生成Launch Plan和启动受控脚本；
    QGC/UE按钮不得直接拼裸命令绕过验证器。
G14 自动评估、视频和报告证据包。
```

G12-G14不能提前取代G9.5/G9.6/G10/G11，也不能把UE/QGC展示作为控制器、
定位、规划或代码生成闭环证据。

| PXC-00 | PX4、MAVROS、px4ctrl正常启动 | 无启动错误，必要Topic出现 |

## A.3 G-PX4CTRL-1：基础闭环功能验收

目标：证明原始 Sunray px4ctrl 能完成基本闭环控制和状态机任务。

起飞-悬停-降落场景必须同时输出两个悬停窗口：`hover_before` 记录进入悬停后的完整收敛过程，用于诊断调参和报告分析；`steady_hover` 记录悬停末段稳态窗口，用于 G-PX4CTRL-1 的通过/阻塞门禁。当前 Goal 1 默认采用最后 2 秒作为稳态门禁窗口，阈值仍使用本文下方的悬停误差目标，不得只保留稳态结果而隐藏完整窗口指标。

| 编号 | 仿真场景 | 主要检查 |
| --- | --- | --- |
| PXC-11 | 自动起飞-悬停-降落 | 完整状态机、落地后无异常滑移 |
| PXC-12 | 30秒定点悬停 | 稳态误差、漂移、抖动 |
| PXC-13 | X方向1 m阶跃 | 水平位置响应 |
| PXC-14 | Y方向1 m阶跃 | 坐标和对称性 |
| PXC-15 | Z方向1 m阶跃 | 高度环和推力映射 |
| PXC-16 | Yaw 30度阶跃 | 小航向响应 |
| PXC-17 | Yaw 90度阶跃 | 大航向响应 |
| PXC-18 | 初始位置偏差恢复 | 收敛和过冲 |
| PXC-19 | 初始Yaw偏差恢复 | 姿态恢复 |

阶跃测试不能使用“最大误差小于5 cm”作为判据。阶跃发生瞬间误差本来就是设定阶跃量。

```text

上升时间
调节时间
```

```text

无持续电机饱和
```
