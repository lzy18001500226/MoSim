本文用于发现和追踪架构问题，不用于替代具体架构文档。Agent执行任务时应按
以下顺序读取：

```text

2. 本任务对应的专题规范
3. 本文中对应ARCH-Q条目
```

若本文与专题规范不一致，以专题规范为准，并回到本文更新追踪状态。任何只

## 1. 总体判断

MoSim当前大方向成立：

```text
MWORKS负责控制器建模、仿真、优化和代码生成；
PX4/Gazebo/Sunray负责工程级闭环验证；
ROS负责FAST-LIO、Diff-Planner、EGO参考链路和Swarm等外部算法；
RViz/UE/Web/QGC负责审核、展示和操作；
Profile/Frame/Manifest/Adapter负责模块耦合。
```

系统核心方向已经冻结；本文保留的问题用于防止后续实现中出现边界漂移。
这些问题不是某个功能没实现，而是若不持续维护架构边界，后续实现会产生
反复返工、指标混乱和模块互相污染。

当前需要优先冻结三类矩阵：

```text
1. 控制链路分层与控制器/增强模块归属矩阵；
2. 状态源/真值/评价实验组矩阵；
3. 需求-架构-实验-证据追踪矩阵。
```

## 3. 目标系统层级决策

当前建议冻结优先级：

```text
P0: 比赛控制系统
  控制器建模、优化、对比、代码生成、指标和报告。

P1: 工程闭环验证平台
  PX4/MAVROS/Gazebo/Sunray，证明控制器能进入真实飞控接口链路。

P2: 自主飞行扩展
  FAST-LIO、Diff-Planner、EGO/EGOv2/EGO-Swarm参考链路，用于证明控制器可接入感知规划系统。

P3: 展示与实验平台
  UE/Web/QGC/RViz，负责操作、审核、视频、报告入口和人机展示。
```

架构规则：

```text
P3不能反向阻塞P0；
P2不能替代P0控制器创新；
P1不能替代MWORKS代码生成证据；
P0算法结论不能只靠P1画面证明。
```

## 4. 权威关系决策

建议冻结如下：

| 权威 | 当前归属 | 说明 |
| --- | --- | --- |
| 算法权威 | MWORKS模型、controller source、论文/公式 | 证明控制律是什么 |
| 工程闭环权威 | PX4 + MAVROS + Gazebo/Sunray | 证明能进入飞控仿真链路 |
| plant参数权威 | 当前Sunray/Gazebo plant profile | MWORKS模型向其校准，而不是反向强迫Gazebo匹配理想模型 |
| 评价真值权威 | truth_profile | 每次实验显式记录，不允许静默混入控制器 |
| 状态源权威 | state_source_profile | 控制器只使用声明的状态源 |
| 显示权威 | RViz/UE/Web/QGC display_profile | 只负责看，不负责判定控制成功 |

## 5. 控制链路分层矩阵

| 控制链路位置 | 代表算法/模块 | 是否是Controller Core | 是否可作为增强模块 | 第一阶段状态 |
| --- | --- | --- | --- | --- |
| 轨迹/参考生成 | minimum snap、B-spline、time allocation、reference governor | 否 | 是 | 只作为Trajectory/Reference |
| 外环位置/速度控制 | PID、LQI、SE3、DFBC、SMC、Backstepping、NMPC | 是 | 部分可增强 | px4ctrl/PID/SE3优先 |
| 姿态/角速度内环 | PX4 inner loop、SO(3)、INDI、body-rate control | 部分是 | 是 | 第一阶段保留PX4内环 |
| 扰动补偿 | DOB/ESO、L1、RBF/NN compensation、AWFF | 否 | 是 | 后续释放 |
| 安全约束 | limiter、CBF、geofence、safety filter | 否 | 是 | basic limiter优先 |
| 故障诊断 | FDI、health monitor、fault estimator | 否 | 是 | 后续释放 |
| 控制分配 | control allocation、fault allocation、QP allocation | 否 | 是 | BODY_RATE/WRENCH阶段再进入 |
| 执行器映射 | thrust mapping、rotor mapping、motor model | 否 | Adapter/Plant | 第一阶段集中在Adapter |

结论：

```text
不是所有算法都进入controller_profile；
部分算法属于augmentation_profile、safety_profile、allocation_profile或trajectory_profile；
前端选择必须体现链路位置，不能把所有模块铺成平级按钮。
```

## 6. 增强模块信号语义待冻结项

| 模块 | 需要冻结的问题 | 建议默认作用点 |
| --- | --- | --- |
| AWFF | 输出加速度前馈、力前馈还是推力补偿 | Reference/Controller输入侧 |
| DOB/ESO | 输出扰动加速度、扰动力还是控制补偿 | Controller Core内部或Augmentation |
| L1 | 修正参考、力、姿态还是推力 | Controller输出前的受限增强 |
| CBF/Safety Filter | 过滤参考还是过滤最终命令 | SafetySupervisor，靠近输出侧 |
| Fault Allocation | 在推力映射前还是电机分配层 | BODY_RATE/WRENCH/ROTOR阶段再启用 |
| NN/RBF补偿 | 补偿模型误差还是输出残差控制量 | 有界Augmentation，不直接替代主控制器 |

未冻结前，不允许在前端提供任意勾选组合。

## 7. 状态源/真值/评价实验组矩阵

| 组 | 状态源 | 真值 | 用途 | 是否可进主排行榜 |
| --- | --- | --- | --- | --- |
| A组 | PX4/MAVROS融合状态 | Gazebo truth | 当前工程控制基线 | 是 |
| B组 | Gazebo truth debug state | Gazebo truth | 控制器极限能力检查 | 否，必须标debug |
| C组 | FAST-LIO直接输出 | Gazebo truth | 定位独立评价 | 否，定位榜 |
| D组 | FAST-LIO -> PX4 EKF -> MAVROS | Gazebo truth | 替换定位来源后的闭环评价 | 是，单独榜 |
| E组 | FAST-LIO XY/Yaw + Gazebo/Laser Z替身 | Gazebo truth | 模拟真机激光定高假设 | 是，必须单独标Hybrid-Z |

禁止：

```text
把B组当A组；
把C组直接当闭环控制成功；
把E组说成纯FAST-LIO；
把Gazebo truth静默混入D组。
```

## 8. 多机架构边界

多机必须分为每机局部链路和集群链路：

```text
per_uav:
  state_source_profile
  controller_profile
  adapter_profile
  logger_profile
  display_profile

swarm_level:
  mission_manager
  swarm_planner
  formation_reference_generator
  inter_uav_communication
  collision_avoidance
  assignment_or_reconfiguration
```

Diff-Planner swarm三机第一阶段只是已知目标点条件下的官方/参考多机规划工程
基线，不等于MoSim自研编队控制系统。EGO-Swarm保留为后续参考和对照。

## 9. UE/前端数据权威边界

UE/Web/RViz/QGC只能消费显示与状态数据：

```text
vehicle_state_frame
trajectory_frame
point_cloud_frame
grid_map_frame
camera_frame
experiment_status_frame
metrics_frame
fault_status_frame
```

UE truth若未来导出，只允许：

```text
显示调试；
场景资产校验；
离线对照；
显式标注的oracle实验。
```

不得：

```text
直接喂给规划器作为未知环境地图；
静默输入控制器；
替代Gazebo/PX4闭环指标；
与FAST-LIO地图混报。
```

## 10. Safety权责边界

| 层 | 职责 |
| --- | --- |
| MoSim SafetySupervisor | 状态超时、参考超时、命令限幅、profile不匹配、实验急停、发布前否决 |
| PX4 failsafe | Offboard丢失、EKF异常、飞控模式、底层安全保护 |
| 前端急停 | 发出停止请求，不直接绕过SafetySupervisor和PX4 |
| 控制器core | 输出控制建议和诊断，不拥有最终发布豁免权 |

最终发布顺序：

```text
ControllerOutput
  -> SafetySupervisor
  -> CommandAdapter
  -> PX4/MAVROS
  -> PX4 failsafe / inner loop / allocation
```

## 11.1 PX4/uORB部署路径决策

MWORKS生成代码进入PX4时，必须拆成以下独立门禁：

```text
G-CODEGEN-0: 生成C/C++可独立编译；
G-CODEGEN-1: 生成代码与参考core离线一致；
G-ROS-0: 生成core经ROS/Sunray/MAVROS回灌闭环A/B通过；
G-PX4-0: 空PX4 Module、Kconfig、module.yaml和SITL构建通过；
G-PX4-1: uORB影子订阅和参数更新正常；
G-PX4-2: uORB影子计算和诊断日志正常；
G-PX4-3: SITL中拥有控制发布权后闭环稳定；
G-PX4-4: 目标飞控board配置、参数可见性和固件构建通过；
G-PX4-5: HITL候选通过。
```

当前最小闭环只要求到`G-ROS-0`。PX4内部Module路径必须单独验收，不得反向
阻塞当前ROS/MAVROS `ATTITUDE_THRUST`基线。

## 12. 需求-架构-实验-证据追踪

建议追踪结构：

```text
Requirement ID
  -> Architecture Block
  -> Profile Set
  -> Experiment ID
  -> Metrics
  -> Evidence Path
  -> Report Section
```

示例：

```text
REQ-CTRL-32 SE3 Geometric Control
  -> 外环位置/速度控制
  -> controller_profile: se3_basic_attitude_thrust_v1
  -> experiment: figure8_se3_px4_state_v1
  -> metrics: RMSE / max / steady-state / overshoot
  -> evidence: Results/<run_id>/
  -> report: 控制器对比章节
```
