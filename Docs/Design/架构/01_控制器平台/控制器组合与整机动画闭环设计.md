# MWORKS整机模型与动画证据设计

> 状态：MWORKS离线整机、原生结果和动画证据专题，2026-07-21。
>
> 控制责任链、PX4/MWORKS替换位置、Model Studio配置字段和组合合法性由
> `MWORKS控制器关系与组合架构.md` 统一定义。本文只说明该关系如何落进整机母模型、
> `Result.msr`、曲线和三维动画证据，不能用动画替代运行时闭环。
>
> 当前 G1-G4 只允许审计和非破坏模型重构；本文第 4 节的 MWORKS 验收步骤属于
> G5 及以后，不能提前启动。

## 1. 本文的证据职责

MWORKS 离线模型需要固定飞机物理、传感器、结果合同和动画来源，并为已通过组合
提供可审查的控制链实例。它不创建第二套控制架构，也不授权任意 UI 候选直接运行。

```text
Profile / 认证组合
  -> 已声明的控制槽位实例
  -> 固定 Plant + sensor + Result contract + animation
  -> Result.msr / 曲线 / 指标 / 动画证据
```

每次运行只能从已验证预设或经过新一轮门禁的候选组合实例化。曲线、静态模型图、
离线回放和动画分别只证明各自的证据层，不能替代 PX4/Gazebo/PX4/MAVROS 运行时证据。

## 2. 当前模型状态

### 2.1 已有基础

当前存在以下类型的源模型或实验模型：

- `References/MWORKS/QuadrotorModel/package.mo` 中的 `QuadrotorModel.Examples.Example1/2/3` 上游基线；
- `Models/MoSimQuadrotorModel/Controllers/Sysblocks/` 下的 AWFF、INDI、L1、线性 MPC、QP/NMPC 和混控相关模型；
- `Models/MoSimQuadrotorModel/Missions/Official/` 下的 AWFF、INDI、L1、线性 MPC 闭环场景；
- `Models/MoSimQuadrotorModel/Controllers/Baselines/` 下的 PID 变体；
- `Models/MoSimQuadrotorModel/Robustness/Scenarios/` 下的质量、风扰和转子故障场景；
- `Models/MoSimQuadrotorModel/Planning/Scenarios/` 和 `Formation/Scenarios/` 下的规划与编队实验。

许多闭环场景包含 `QuadrotorModel.Mechanics.QuadChassis`、四个执行器和传感器，因此具备三维动画的结构基础。但“存在 `QuadChassis`”只证明模型具备动画潜力，不等于该场景已经通过动画验收。

### 2.2 尚不能统一宣称的内容

当前不能统一宣称以下事项已经完成：

1. 所有控制器家族都有统一的可替换接口；
2. 所有控制器都有行为等价的图形化 Sysblock；
3. 所有控制器组合都已经接入同一整机母模型；
4. 所有组合都已经生成原生 `Result.msr` 并播放三维动画；
5. 故障场景已经拥有统一的注入和参数入口；
6. 所有模型的结果变量名称已经统一；
7. 公式模型、图形模型、代码生成和 Gazebo 运行时已经全部通过同一条证据链。

配置目录中同时存在 `quality_status: pass` 和 `quality_status: needs_iteration`，因此必须以具体场景的最新证据矩阵判断，不得用文件数量推断闭环完成度。

## 3. 目标整机母模型

应建立一个固定的整机母模型，固定以下部分：

```text
轨迹输入
传感器与状态反馈
控制器槽位
安全槽位
故障槽位
混控器和四电机
QuadChassis 与 MultiBody.World
统一结果变量
原生三维动画
```

只允许替换下列槽位：

```text
formation_controller (0..1，输出每机参考)
reference_governor (0..1，约束原始参考)
nominal_controller (exactly 1，主 CommandFrame)
augmentation (0..1，受控单增强；多增强只能作为已登记固定集成链内部拓扑)
safety_filter (exactly 1，命令发布前约束)
attitude_rate_inner / control_allocator（由 Profile 明确 owner）
fault_manager (0..1，执行器响应和健康侧链)
```

这不是允许任意笛卡尔拼接。当前 Profile 只能选择 registry 已解析、接口和下游
owner 已明确的组合；P4 legacy bundle、P6/P7 aggregate 和未完成通信建模的 P8
mode 不能仅靠名称自动填入上述槽位。

这比为每种算法手工复制一套完整模型更容易检查，也能避免系统架构图与实际飞行动力学模型继续分离。

### 3.1 组合实现的三级降级

APP 始终面向 Profile 和兼容性目录，不直接向用户暴露底层模型名。底层按以下顺序选择执行后端：

```text
1. 共用 Plant/Animation + 共用输出边界 Runner + 薄 Wrapper
2. 共用 Plant/Animation + 组合专用 Runner + 薄 Wrapper
3. 组合专用完整模型
```

第三级只用于真实短时 MWORKS 数值门已经证明前两级存在结构或执行语义不兼容的组合。独立完整模型仍必须实现统一结果合同，不能因此绕过 `Result.msr`、姿态/位置门限或动画窗口验收。APP 根据目录中的 `available`、`blocked_current_run` 和 `disabled_reason` 启用或禁用选项。

2026-07-19 的 QP/NMPC Safety 复测同时覆盖了共用 Runner、组合专用 Runner 和既有独立实验模型；这些路线当前均出现数值失稳，因此该项保持可见禁用。飞机疯狂翻滚属于控制闭环失败，不能因模型检查、求解或动画窗口成功打开而认证。

## 4. 每个组合的正式验收流程

每个候选组合必须按以下顺序执行：

```text
1. 注册 ControllerProfile / ExperimentProfile
2. 确认层级、输入输出、单位、坐标系、采样和复位语义
3. 确认方程实现与图形化 Sysblock 的行为对应关系
4. 在 Sysplorer 中加载依赖和整机模型
5. 点击“检查”，检查通过后才允许仿真
6. 点击“仿真”，保存当前场景的原生结果
7. 在结果查看器打开当前 Result.msr
8. 创建关键曲线并检查位置、姿态、电机和状态量
9. 创建三维动画并确认原生动画窗口成功打开；比赛前批量验收不要求逐项播放
10. 导出 raw CSV、指标、截图和结果清单
11. 通过 MWORKS/codegen/SIL 门禁后，才进入 ROS1/Sunray/Gazebo 验证
```

曲线窗口、模型结构窗口和三维动画窗口的证据职责不同：

```text
模型窗口：检查模块和连线
曲线窗口：检查控制误差、参考、控制量和状态
三维动画窗口：检查机体运动的可视化表现
Gazebo/RViz：检查代码、传感器、运行时和机器人系统闭环
```

三维动画不能替代曲线和指标；曲线也不能替代 Gazebo/PX4/MAVROS 运行时证据。

每次批量仿真完成并保存证据后，必须关闭本次模型、曲线、结果和动画窗口，并关闭该次专用 Sysplorer 会话。认证脚本统一使用 `--gui-reset-windows --shutdown-session`，避免窗口和会话累积导致 MWORKS 崩溃。若同一批次明确复用一个会话，也只能保留一个主窗口，并在批次结束时清理。

## 5. 剩余模型与证据工作

### P0：按关系文档冻结模型实例

- 以 `MWORKS控制器关系与组合架构.md` 的槽位和 owner 为准，补齐每个模型实例的
  `ControllerProfile`、兼容性和参数开关；
- 明确哪些组合有工程意义，拒绝无意义的笛卡尔积；
- 把故障注入、FDI 和容错响应分别落到可审查模型或 blocker，不能继续混成一个槽位。

### P1：建立整机母模型

- 固定 `QuadChassis`、四电机、传感器、结果变量和动画链路；
- 预留控制器、增强、安全和故障槽位；
- 解决 `QuadrotorModel` STL/图片资源的正式加载路径。

### P2：补齐图形化对应物

- 对每个要进入正式证据矩阵的算法建立图形化 Sysblock；
- 检查图形连线、端口和内部可审查拓扑；
- 不能用空壳包装器或方程模型代替内部图形结构。

### P3：逐组合整机仿真和动画验收

- 先验证 `PID + PID` 基线；
- 再验证 `AWFF`、`INDI`、`L1`、线性 MPC 和 QP/NMPC 的代表性组合；
- 每个组合分别生成原生结果、曲线、动画截图和指标；
- 失败结果保留为失败证据，不通过改名或替换窗口隐藏。

### P4：统一故障和结果接口

- 把 GPS 丢失、风扰、质量变化、转子故障和故障分配统一为场景配置；
- 统一 `time`、位姿、姿态、电机、控制器状态、故障状态和安全状态变量；
- 建立控制器组合与证据路径的最终矩阵。

### P5：选择器和前端

Model Studio 当前已经提供“快速预设 / 自定义组合”与位置外环、姿态内环、增强、
安全、故障场景、编队和输出边界等字段。它允许编辑候选，但离线 MIL 仍只对与
已登记预设完全匹配的组合开放；实时路径另受单机 `ATTITUDE_THRUST` 合同约束。
字段含义和未来拆分原则以 `MWORKS控制器关系与组合架构.md` 为准，前端不得临时
拼接未通过兼容性门禁的模型。

## 6. 当前结论

截至 2026-07-19，比赛前离线可组合平台的当前状态为：

```text
四类输出边界 Runner：已建立并通过静态门
共用单机 Plant/Animation：已用于 8 个 Certified 和 2 个 Custom Profile
8 个单机 Certified Profile：当前真实 MWORKS 认证通过
1 个三机 Certified Profile：当前真实 MWORKS 认证通过
2 个 Custom Compatible Profile：按需生成、仿真、Result.msr 和动画窗口通过
QP/NMPC Safety：当前数值失稳，可见禁用，不计入认证通过项
所有历史算法全部适配：未完成，未适配项保持禁用
Gazebo 最终运行时验证：按组合分别进行，不能由 MWORKS 动画替代
```

机器可读权威为 `Config/control_platform/offline_composition_catalog.json`，checker 为 `Scripts/quality/check_offline_composition_catalog.py`。认证记录位于 `Results/mworks_generated_profiles/<run_id>/CERTIFICATION.json`；较长路径的 `Result.msr` 可按 manifest 安全落到 `Results/native_result_cache/`，认证器拒绝任何指向项目 `Results/` 之外的路径。

本文不改变当前 ROS1/Sunray/Gazebo/PX4/MAVROS 主线，也不授权启动 MWORKS 或进行模型迁移。实现任务必须先按本文冻结接口和验收层级，再进入具体模型修改。
