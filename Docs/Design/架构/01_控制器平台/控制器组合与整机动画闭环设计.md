# 控制器组合与整机动画闭环设计

> 状态：设计基线，2026-07-18。本文只记录当前源文件可确认的结构和未完成项，不把未经过 MWORKS 实时证据的模型标记为最终闭环。

## 1. 目的

MoSim 的目标不是把所有算法同时堆进一个模型，而是建立一个固定的四旋翼整机模型，并允许在明确的控制链路层级中替换兼容模块：

```text
任务轨迹
  -> 位置外环
  -> 姿态指令
  -> 姿态内环
  -> 扰动补偿/增强
  -> 安全过滤
  -> 故障检测与控制分配
  -> 四电机与机体动力学
  -> 传感器反馈
```

每次运行选择一个有效组合，使用同一套整机、结果变量和证据流程。不能把曲线、静态模型图或离线回放当作三维动画闭环证据。

## 2. AWFF 的边界

`AWFF` 不是当前所有控制器家族的总称。它既出现在基础控制结构中，也出现在部分 MWORKS/Sysblock 文件名中；文件名前缀不能决定算法所属层级。

当前应按下面的职责分类：

| 层级 | 当前代表 | 说明 |
| --- | --- | --- |
| 名义位置外环 | PID、改进 PID、线性 MPC、QP/NMPC | 同一运行中不能无定义地并列承担同一外环职责 |
| 名义姿态内环 | PID、INDI，以及后续经过接口审查的其他内环 | 接收姿态/角速度参考并输出姿态控制量 |
| 增强与扰动补偿 | AWFF、L1 残差、DOB/ESO、模糊/神经补偿 | 是可开关、可消融的增强层，不自动等同于名义控制器 |
| 安全层 | QP/NMPC 安全约束、限幅、后续安全过滤器 | 对名义控制命令做约束或降级处理 |
| 故障层 | 故障注入、故障检测、隔离、控制分配和重构 | 负责“注入 -> 检测 -> 隔离 -> 重构 -> 恢复” |
| 执行层 | 混控器、四电机、`QuadChassis`、传感器 | 固定的整机物理闭环和三维动画来源 |

当前工程中可见的实现包括 PID 变体、AWFF、INDI、L1 残差/故障分配/多故障隔离、线性 MPC、在线故障分配和 QP/NMPC 安全模型。LQR、LQI、滑模、反步、模糊控制、神经网络等不能因为曾经列入规划就标记为当前已接入整机闭环，必须以现有模型、检查日志和结果证据为准。

## 3. 组合规则

### 3.1 合法组合

组合必须满足层级职责和接口类型。例如：

```text
PID 位置外环 + PID 姿态内环 + 混控器
线性 MPC 位置外环 + INDI 姿态内环 + 混控器
AWFF 名义控制结构 + INDI 姿态内环 + L1 扰动补偿
线性 MPC 外环 + INDI 内环 + 安全层 + 故障控制分配
```

### 3.2 禁止的隐式组合

以下情况不能直接拼接：

- PID 外环和线性 MPC 外环同时驱动同一控制量；
- 把 L1、INDI、AWFF、安全过滤器或故障分配误登记为同一级名义控制器；
- 只替换控制器方程，却没有确认输入输出单位、坐标系、采样时间、限幅和复位语义；
- 用方程模型运行成功替代图形化 Sysblock 和整机连线验收；
- 用静态系统架构图、离线动画或漂亮截图替代原生仿真结果。

统一控制接口的公共语义见 `统一控制接口.md`。当前控制器核心应保持以下输出边界：

```text
desired_attitude_quaternion
desired_collective_thrust_N
controller_status
controller_diagnostics
```

控制核心不直接发布 MAVROS 话题；适配器负责把控制输出映射到 PX4/MAVROS 语义。

## 4. 当前模型状态

### 4.1 已有基础

当前存在以下类型的源模型或实验模型：

- `References/MWORKS/QuadrotorModel/package.mo` 中的 `QuadrotorModel.Examples.Example1/2/3`；
- `Models/QuadrotorControllerBlocks/` 下的 AWFF、INDI、L1、线性 MPC、QP/NMPC 和混控相关模型；
- `Models/QuadrotorExperiments/OfficialScenarios/` 下的 AWFF、INDI、L1、线性 MPC 闭环场景；
- `Models/QuadrotorExperiments/ControllerBaselines/` 下的 PID 变体；
- `Models/QuadrotorExperiments/RobustFaultScenarios/` 下的质量、风扰和转子故障场景；
- `Models/QuadrotorExperiments/PlanningScenarios/` 和 `FormationScenarios/` 下的规划与编队实验。

许多闭环场景包含 `QuadrotorModel.Mechanics.QuadChassis`、四个执行器和传感器，因此具备三维动画的结构基础。但“存在 `QuadChassis`”只证明模型具备动画潜力，不等于该场景已经通过动画验收。

### 4.2 尚不能统一宣称的内容

当前不能统一宣称以下事项已经完成：

1. 所有控制器家族都有统一的可替换接口；
2. 所有控制器都有行为等价的图形化 Sysblock；
3. 所有控制器组合都已经接入同一整机母模型；
4. 所有组合都已经生成原生 `Result.msr` 并播放三维动画；
5. 故障场景已经拥有统一的注入和参数入口；
6. 所有模型的结果变量名称已经统一；
7. 公式模型、图形模型、代码生成和 Gazebo 运行时已经全部通过同一条证据链。

配置目录中同时存在 `quality_status: pass` 和 `quality_status: needs_iteration`，因此必须以具体场景的最新证据矩阵判断，不得用文件数量推断闭环完成度。

## 5. 目标整机母模型

应建立一个固定的整机母模型，固定以下部分：

```text
轨迹输入
传感器与状态反馈
控制器槽位
安全槽位
故障槽位
混控器和四电机
QuadChassis 与 MultiBody.World
统一结果变量
原生三维动画
```

只允许替换下列槽位：

```text
position_outer_controller
attitude_inner_controller
disturbance_compensation
safety_filter
fault_handler
```

这比为每种算法手工复制一套完整模型更容易检查，也能避免系统架构图与实际飞行动力学模型继续分离。

## 6. 每个组合的正式验收流程

每个候选组合必须按以下顺序执行：

```text
1. 注册 ControllerProfile / ExperimentProfile
2. 确认层级、输入输出、单位、坐标系、采样和复位语义
3. 确认方程实现与图形化 Sysblock 的行为对应关系
4. 在 Sysplorer 中加载依赖和整机模型
5. 点击“检查”，检查通过后才允许仿真
6. 点击“仿真”，保存当前场景的原生结果
7. 在结果查看器打开当前 Result.msr
8. 创建关键曲线并检查位置、姿态、电机和状态量
9. 创建三维动画并人工播放，确认机体位置、姿态和旋翼运动
10. 导出 raw CSV、指标、截图和结果清单
11. 通过 MWORKS/codegen/SIL 门禁后，才进入 ROS1/Sunray/Gazebo 验证
```

曲线窗口、模型结构窗口和三维动画窗口的证据职责不同：

```text
模型窗口：检查模块和连线
曲线窗口：检查控制误差、参考、控制量和状态
三维动画窗口：检查机体运动的可视化表现
Gazebo/RViz：检查代码、传感器、运行时和机器人系统闭环
```

三维动画不能替代曲线和指标；曲线也不能替代 Gazebo/PX4/MAVROS 运行时证据。

## 7. 剩余工作分解

### P0：冻结接口和分类

- 固定位置外环、姿态内环、增强、安全、故障和执行层归属；
- 为每个模块补齐 `ControllerProfile`、兼容性和参数开关；
- 明确哪些组合有工程意义，拒绝无意义的笛卡尔积。

### P1：建立整机母模型

- 固定 `QuadChassis`、四电机、传感器、结果变量和动画链路；
- 预留控制器、增强、安全和故障槽位；
- 解决 `QuadrotorModel` STL/图片资源的正式加载路径。

### P2：补齐图形化对应物

- 对每个要进入正式证据矩阵的算法建立图形化 Sysblock；
- 检查图形连线、端口和内部可审查拓扑；
- 不能用空壳包装器或方程模型代替内部图形结构。

### P3：逐组合整机仿真和动画验收

- 先验证 `PID + PID` 基线；
- 再验证 `AWFF`、`INDI`、`L1`、线性 MPC 和 QP/NMPC 的代表性组合；
- 每个组合分别生成原生结果、曲线、动画截图和指标；
- 失败结果保留为失败证据，不通过改名或替换窗口隐藏。

### P4：统一故障和结果接口

- 把 GPS 丢失、风扰、质量变化、转子故障和故障分配统一为场景配置；
- 统一 `time`、位姿、姿态、电机、控制器状态、故障状态和安全状态变量；
- 建立控制器组合与证据路径的最终矩阵。

### P5：选择器和前端

只有 P0-P4 稳定后，才实现下拉选择：

```text
位置外环
姿态内环
增强层
安全层
故障场景
任务轨迹
```

前端只编排已注册且已通过兼容性门禁的组合，不负责临时拼接未验证模型。
