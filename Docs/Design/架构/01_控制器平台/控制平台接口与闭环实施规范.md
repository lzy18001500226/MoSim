# MoSim控制平台接口与闭环实施规范

> 状态：G1-G7实施入口，2026-07-16。
>
> 本文是控制模块组合、机器注册和闭环晋级的短权威入口。数学公式仍由各控制器
> 专题文档负责；Profile解析仍由`ExperimentProfile与兼容性矩阵.md`负责。旧文档
> 中与本文冲突的批量控制器或任意组合描述，不作为当前实施依据。

## 1. 冻结控制图

```text
Trajectory / Mission
  -> Formation Controller (0..1)
  -> Reference Governor (0..1)
  -> Nominal Outer Controller (exactly 1)
  -> Augmentation (0..N, registry order)
  -> Safety Filter (exactly 1, none is forbidden for runtime)
  -> Attitude / Rate Inner Controller (exactly 1)
  -> Control Allocator (0..1, required for WRENCH/ROTOR)
  -> Command Adapter (exactly 1)
  -> PX4 / MAVROS / Gazebo plant
```

Formation只生成每架飞机的`ReferenceFrame`。增强模块不得伪装成名义控制器，
Safety拥有发布前最终否决权，Adapter只转换语义而不得修改控制律。

当前运行基线仍是：

```text
Nominal ATTITUDE_THRUST outer controller
  -> basic_limiter_v1
  -> PX4 attitude/rate inner loops
  -> PX4 allocator
  -> mavros_attitude_thrust_v1
```

在进程边界上，MAVROS Adapter先把类型化命令发布给PX4；PX4随后执行其后端拥有的
姿态/角速度内环和控制分配。上面的控制图描述控制责任链，不表示跨进程调用顺序。
`adapter_profiles`必须绑定`backend_inner_profile`和`backend_allocator_profile`，两者
必须在Registry中以`backend_owned=true`登记。

`BODY_RATE_THRUST`、`WRENCH`和`ROTOR_COMMAND`可以登记和做离线门禁，但没有匹配
Adapter与运行证据时不能成为可启动Profile。

## 2. 类型化Frame

跨模块只传递下列语义对象，不传ROS消息、YAML对象或后端私有变量：

| Frame | 必需语义 |
| --- | --- |
| `FrameHeader` | schema、run/profile/source id、frame id、source/sim时间、sequence、valid |
| `StateFrame` | p、v、q(wxyz)、body rate、可选加速度、状态源健康与新鲜度 |
| `ReferenceFrame` | p/v/a/yaw，可选jerk/snap/yaw rate与预测时域 |
| `CommandFrame` | 一个且仅一个命令变体、单位、有效期、饱和标志和fallback状态 |
| `ModuleDiagnostics` | module id、health、reason code、计算时间、饱和/约束/估计量 |
| `LifecycleContext` | dt、reset、enable、run id、profile hash、参数版本和随机种子 |
| `ParameterSet` | 类型、单位、范围、更新等级、值、hash和父版本 |

`CommandFrame.variant`只允许：

```text
ATTITUDE_THRUST
BODY_RATE_THRUST
WRENCH
ROTOR_COMMAND
```

所有实现必须显式处理`reset`、无效输入、超时、NaN/Inf、禁用和fallback。模块不得
在构造函数或首次step时读取ROS参数形成不可追溯的隐式状态。

## 3. 分层接口

| 接口 | 输入 | 输出 |
| --- | --- | --- |
| `ITrajectoryGenerator` | mission、time、constraints | `ReferenceFrame` |
| `IFormationController` | multi-state、formation goal | per-vehicle `ReferenceFrame` |
| `IReferenceGovernor` | state、raw reference、constraints | governed `ReferenceFrame` |
| `INominalController` | state、reference、lifecycle、params | `CommandFrame` |
| `IAugmentation` | state、reference、candidate command、diagnostics | augmented command/term |
| `ISafetyFilter` | state、candidate command、constraints | pass/modify/reject command |
| `IAttitudeController` | state、attitude/body-rate reference | body-rate or wrench command |
| `IControlAllocator` | wrench、actuator health/limits | rotor command |
| `ICommandAdapter` | typed command | backend command plus mapping diagnostics |

第一阶段可以由PX4实现`IAttitudeController`和`IControlAllocator`，但Registry必须
明确记录`backend_owned`，不能假装它们不存在。

## 4. 组合与切换规则

1. Profile只能引用Registry中`selectable=true`的模块。
2. 输出变体必须与下游输入完全相同，不允许静默降级。
3. 增强模块按Registry声明顺序执行；同一stage默认最多一个模块。
4. 第一阶段只允许run之间切换控制器，飞行中不得热切换名义控制器或状态源。
5. `planned`、`blocked`、`audit_only`模块只能进入候选或拒绝测试。
6. 参数修改产生新`ParameterSet`，正式run期间Profile和参数hash冻结。
7. 神经网络首阶段只能作为有界残差、估计或参数调度，并必须有确定性fallback。

当前已实现模块的机器源：`Config/control_platform/control_module_registry.json`。
扩展 Goal 的完整目标清单机器源：`Config/control_platform/extended_control_scope_catalog.json`。
该目录中的每个 `required_algorithm_ids` 都必须最终进入 Registry、Profile 和证据矩阵；
目录通过前不得以“当前已有模块覆盖”解释为已完成。
校验入口：`python Scripts/quality/check_control_module_registry.py`。
扩展清单校验：`python Scripts/quality/check_extended_control_scope.py`。

## 5. 单模块闭环晋级

每个正式模块按同一状态机晋级：

```text
planned
  -> source_selected
  -> interface_ready
  -> mworks_mil_passed
  -> sil_codegen_passed
  -> factory_runtime_passed
  -> accepted
```

最低产物：

```text
licensed upstream or project-owned derivation
source audit and mathematical mapping
pure deterministic core
golden vectors
Controller/ModuleProfile and ParameterSet
MWORKS graphical model
MIL/SIL result
generated-C equivalence result
Factory runtime result when shared resources are available
evidence manifest and claim ceiling
```

状态不可跨级推断。MWORKS图形化通过不等于generated C通过；generated C通过不等于
Gazebo/PX4通过；已有历史runtime证据也不自动证明新生成代码已回灌。

## 6. 算法家族与止损

实现按家族推进，数学核心相同的变体优先做Profile，不复制框架：

```text
linear optimal: LQR / LQI / LQG
geometric: SE(3) / SO(3)
nonlinear: NDI / feedback linearization / backstepping
robust: SMC variants / H-infinity
predictive: NMPC / robust or tube MPC
augmentation: INDI / DOB-ESO / L1 / ADRC
safety and allocation
formation
bounded learning augmentation
```

候选出现以下任一情况时淘汰或降级为公式参考：无许可证；依赖无法隔离；核心不是
确定性固定尺寸；连续三次在同一证据门失败且无新诊断；需要破坏当前架构才能运行；
收益与已有家族重复且没有独立报告价值。淘汰必须记录原因，不能删除审计证据。

## 7. Factory与简化故障面

前端前的G6只冻结两个可控量：

```text
wind: speed_mps + direction_deg (direction可后置)
motor effectiveness: rotor_index[1..4] + effectiveness[0..1]
```

运行前配置与运行中命令使用同一语义对象：

```text
DisturbanceCommand / FaultCommand
  command_id, run_id, profile_hash, target, requested_at,
  apply_mode, value, ramp_s, duration_s, restore_policy, source
```

后端必须返回`accepted/applied/rejected/restored`事件。曲线至少记录请求值、实际值、
各电机效能、可得的转速/推力、姿态误差、控制输出和安全介入。当前不新增GPS、
通信或复杂传感器故障；Gazebo默认噪声只记录配置，不做前端滑块。

## 8. G1-G7执行顺序

```text
G1 本文与Frame/接口/组合规则
G2 Registry、Profile兼容性和自动门禁
G3 现有控制器与增强模块统一登记
G4 有许可证上游调研、家族选择和淘汰记录
G5 各家族source -> MWORKS -> codegen -> Factory闭环
G6 Factory风扰/电机效能命令、事件、曲线和回放契约
G7 前端handoff契约、生命周期、遥测与嵌入边界（不实现前端）
```

共享Gazebo/PX4/MAVROS被RACER占用时，G5/G6只能完成源码、MWORKS、codegen和
replay门禁，并明确保留`factory_runtime_pending`，不得抢占或重启共享进程。

扩展 P1 PID 第一波统一入口为
`Scripts/control_platform/pid_unified_core.[ch]`。它冻结 Cascade、tracking
anti-windup、reference feedforward、bounded gain schedule、bounded fuzzy schedule
和 bounded neural residual 的共同 ABI。当前新增 Profile 只处于
`interface_ready/selectable=false`；在 C golden vector、MWORKS MIL、generated-C
SIL 和 Factory runtime 依次通过前，不得晋级为 `implemented` 或继承 Official PID
的历史运行证据。

当前机器入口：

```text
G5 Wave A core: Scripts/control_platform/wave_a_controller_core.[ch]
G5 offline gate: Results/control_platform/g5_wave_a_20260716/G5_WAVE_A_GATE.json
G5 blocker/claim: Results/control_platform/g5_wave_a_20260716/G5_WAVE_A_SUMMARY.json
G5 Wave B SMC gate: Results/control_platform/g5_wave_b_smc_20260716/G5_WAVE_B_SMC_GATE.json
G5 Wave B Hinf gate: Results/control_platform/g5_wave_b_hinf_20260716/G5_WAVE_B_HINF_GATE.json
G5 Wave C summary: Results/control_platform/g5_wave_c_20260716/G5_WAVE_C_SUMMARY.json
G5 runtime resource audit: Results/control_platform/g5_runtime_resource_audit_20260716/G5_RUNTIME_RESOURCE_AUDIT.json
G6 contract: Config/control_platform/factory_injection_contract.json
G6 replay: Scripts/control_platform/factory_injection_replay.py
G7 handoff: Config/control_platform/frontend_handoff_contract.json
G7 offline lifecycle adapter: Scripts/control_platform/offline_runtime_adapter.py
G1-G6 closeout matrix: Docs/Design/架构/01_控制器平台/G1_G6闭环验收矩阵.md

`offline_runtime_adapter.py`是前端和真实后端之间的离线契约门禁。它复用
ExperimentProfile校验，提供`validate_experiment_profile`、`start_run`、
`stop_run`、`apply_injection`、`restore_injection`和`snapshot`命令，并严格
返回`request_id/accepted/reason_code/run_id/profile_hash/timestamp`。它不会
启动MWORKS、ROS、Gazebo、PX4或MAVROS，因此其通过只代表生命周期、profile
绑定和注入事件语义通过，不代表控制性能或运行时闭环通过。
```
