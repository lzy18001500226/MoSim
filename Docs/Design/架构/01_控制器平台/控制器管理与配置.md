# 0. 当前阶段管理范围

当前不实现完整 Controller Manager。

当前只冻结最小 Profile 和运行记录：

```text
state_source_profile: px4_mavros_fused_v1
frequency_profile: attitude_thrust_100hz_v1
controller_profile: px4ctrl_original_profile / px4ctrl_mosim_profile
scenario_profile: 基础任务/地图/车辆数量
plant_profile: Sunray/Gazebo当前plant权威版本
sensor_profile: MID360、IMU、定高、camera和外参
height_source_profile: PX4/Gazebo定高替身或真机rangefinder
truth_profile: Gazebo truth评价源
trajectory_profile: G0-G7对应测试轨迹集
fault_profile: none或已批准故障注入
disturbance_profile: none或已批准扰动注入
log_profile: 每次运行的Topic、参数、版本、指标和结果路径
```

当前禁止：

```text
热切换完整控制器体系
影子控制器长期运行
自动故障降级Manager
前端直接切换最终控制权
多个控制器同时争夺最终命令发布权
```

完整 Controller Manager 在 px4ctrl Golden Slice、官方PID替换和 SE3 Basic 替换均通过后再启动。

## 0.1 当前阶段可组合实验平台边界

当前阶段的“自由选择”不是任意控制模块排列组合，而是通过固定流水线中的有限
插槽选择已批准 Profile。

固定流水线：

```text
experiment_profile
  -> scenario_profile
  -> plant_profile
  -> sensor_profile
  -> state_source_profile
  -> height_source_profile
  -> truth_profile
  -> frequency_profile
  -> trajectory_profile
  -> planner_profile
  -> controller_profile
  -> augmentation_profile
  -> safety_profile
  -> adapter_profile
  -> fault_profile
  -> disturbance_profile
  -> display_profile
  -> evaluation_profile
```

第一阶段只允许一个 `controller_profile` 拥有最终控制权，且输出层级固定为：

```text
ATTITUDE_THRUST
```

前端、脚本和UE面板不得直接拼接控制器模块，也不得直接执行任意裸 `sh` 作为
实验定义。正确流程是：

```text
前端/脚本选择实验配置
  -> 写入或提交 experiment_profile
  -> Orchestrator读取Profile
  -> Profile Validator做兼容性检查
  -> Launch Plan Builder生成固定模板命令
  -> Runtime Runner执行ROS launch / shell wrapper / replay任务
  -> Logger记录profile、hash、命令、topic、指标和证据路径
```

不兼容组合必须拒绝启动，不能静默降级。例如：

```text
DFBC-Full需要p/v/a/jerk/snap参考；
若trajectory_profile只提供p/v/a，则必须拒绝DFBC-Full或显式选择DFBC-Basic。

FAST-LIO状态源未通过定位门禁；
则只能进入evaluation_profile，不能进入controller_state。

NMPC需要plant_param_profile和约束profile；
缺失时不得启动NMPC闭环。
```

当前UI建议只暴露：

```text
主控制器/控制器方案下拉框
位置环、速度环、姿态环、角速度环职责摘要（自动解析、默认只读）
控制分配/输出边界摘要（自动解析、默认只读）
状态源下拉框
轨迹/规划器下拉框
增强Profile选择
安全Profile选择
场景扰动/故障注入开关（默认关闭；控件可见但禁用）
显示Profile选择
运行/停止/导出报告按钮
```

环路职责摘要的最终来源必须是 Registry/Profile 的显式 owner 字段，不能由 UI 标签或
文件名推断。当前 Registry 尚未完整登记位置、速度、姿态、角速度和分配五类 owner，
在字段补齐前只能显示经过源码、Adapter 和冻结 Profile 审计的只读摘要。不要在第一阶段
提供任意模块拖拽、任意顺序编排或飞行中热切换控制器。
场景注入不等于故障容错控制；只有具备注入、检测、隔离、重构和安全动作证据的
专用 Profile 才能进入故障管理实验。

## 0.2 G9阶段UI-ready接口冻结

G9期间不实现完整RflySim式界面，但所有控制器替换工作必须按未来可接入UI
的方式沉淀接口。UI-ready不是视觉界面完成，而是以下对象已经稳定：

```text
controller_registry
experiment_profile
launch_plan
run_manifest
result_manifest
artifact_index
controller_acceptance_summary
```

未来按钮只允许调用这些稳定入口：

| 按钮/动作 | 后端入口 | 输入 | 输出 |
| --- | --- | --- | --- |
| 打开MWORKS图形模型 | `open_mworks_model`或等价wrapper | model/profile id | MWORKS窗口状态和截图证据 |
| 检查模型 | `check_mworks_model` | model/profile id | check结果、日志、错误码 |
| 生成代码 | `generate_controller_code` | controller profile、model id | generated source manifest、hash、编译入口 |
| 编译控制器core | `build_controller_core` | generated source manifest | library/binary manifest |
| 运行单机基线 | `run_single_uav_gate` | experiment profile | run manifest、metrics、log dir |
| 运行三机Diff | `run_diff_swarm_gate` | experiment profile | per-uav metrics、collision/min-distance |
| 打开RViz点云/栅格 | `open_rviz_review` | display profile | 窗口状态、截图/人工审核入口 |
| 收集报告 | `collect_metrics_report` | run/result manifest | metrics table、figures、report note |

这些入口可以先由`.cmd`、`.sh`或Python wrapper实现，但名称、输入、输出和
manifest语义必须稳定。前端不能直接写死：

```text
wsl ...
roslaunch ...
python ...
```

而应调用Orchestrator或wrapper生成的Launch Plan。这样后续替换PID、SE3、
DFBC、SMC、INDI/PID-INDI、NMPC时，UI只读取注册表和Profile，不需要理解
每个控制器的内部公式。

G9控制器注册表首批字段：


# 1. 文档目的

本文档规定MoSim控制器的注册、发现、配置、实例化、组合、启停、切换、健康监测、故障降级、参数管理、Profile管理、前端控制和配置追溯机制。

本文档主要解决以下问题：

```text
几十种控制器怎样统一注册
基础控制器和INDI、L1、AWFF怎样组合
当前控制器由谁选择
多个控制器能否同时运行
控制器切换时怎样避免输出突变
NMPC失效后怎样自动切换到SE3或PID
不同机型怎样加载不同参数
MWORKS参数、PX4参数和前端参数怎样保持一致
哪些参数可以在线修改
参数修改失败后怎样回滚
控制器配置怎样随实验和固件完整追溯
```

# 2. 管理体系定位

MoSim控制器管理体系位于控制算法与运行平台之间。

```text
前端 / 测试脚本 / 任务系统
              ↓
Controller Management API
              ↓
Controller Manager
              ↓
Controller Registry
              ↓
Profile Resolver
              ↓
控制器实例与增强模块
              ↓
Command Arbiter
              ↓
最终控制命令
              ↓
PX4 / ROS / MWORKS / Gazebo
```

Controller Manager不实现具体控制算法。

它负责：

```text
决定谁运行
决定谁拥有控制权
决定使用哪些参数
决定何时切换
决定失败时如何降级
决定最终命令能否发布
```

# 3. 核心设计原则

## 3.1 单一控制权原则

同一时刻只有一个控制器或控制Profile拥有最终控制权。

可以同时运行多个控制器：

```text
主控制器
影子控制器
备用控制器
诊断控制器
```

但只有Controller Manager选择出的唯一命令可以进入最终输出链。

---

## 3.2 算法与配置分离

控制器代码只描述算法结构。

参数、机型、增强模块和部署方式由配置决定。

禁止创建：

```text
pid_light_vehicle.cpp
pid_heavy_vehicle.cpp
pid_wind.cpp
pid_fault.cpp
```

应采用：

```text
同一个PID控制器
+
不同Vehicle Profile
+
不同Parameter Set
+
不同Augmentation Profile
```

---

## 3.3 原子算法与组合Profile分离

原子算法：

```text
PID
SE3
DFBC
LMPC
NMPC
INDI
L1
AWFF
DOB
QP控制分配
```

组合Profile：

```text
PID + AWFF
DFBC + INDI
SE3 + L1
NMPC + INDI + L1
SE3 + FDI + 故障QP分配
```

原子模块保存在算法目录。

组合关系保存在Profile中。

---

## 3.4 配置必须可追溯

任意一次实验必须能够恢复：

```text
控制器版本
参数版本
机型版本
增强模块配置
规划器配置
输出层级
飞控固件版本
配置文件哈希
```

禁止只记录：

```text
“使用了优化后的PID”
```

---

## 3.5 安全优先于性能

控制器切换和自动选择的优先级：

```text
飞行稳定
>
状态有效
>
执行器安全
>
碰撞安全
>
任务连续
>
控制性能
>
控制效率
```

性能更高的控制器不能覆盖安全状态判断。

# 5. Controller Descriptor

Controller Descriptor描述一种控制算法的固定能力。

```cpp
struct ControllerDescriptor {
    uint16_t controller_id;

    const char* name;
    const char* display_name;
    const char* version;

    ControllerCategory category;
    ControlOutputType output_type;

    uint64_t required_state_mask;
    uint64_t required_reference_mask;

    bool supports_constraints;
    bool supports_faults;
    bool supports_shadow_mode;
    bool supports_state_transfer;
    bool supports_hot_update;
    bool supports_codegen;
    bool supports_ros;
    bool supports_px4_sitl;
    bool supports_px4_onboard;

    bool requires_dedicated_task;
    bool requires_reference_horizon;
    bool requires_motor_feedback;

    double nominal_rate_hz;
    double maximum_rate_hz;

    IController* (*create)();
};
```

Descriptor属于编译期或加载期静态信息。

运行时不得修改。

# 21. 配置层级

# 44. 生命周期说明

## UNAVAILABLE

控制器未编译、依赖缺失或当前平台不支持。

## UNCONFIGURED

控制器存在，但没有有效配置。

## CONFIGURING

正在加载参数和模型。

## READY

已初始化，可以运行。

## STANDBY

已准备，但不执行完整控制计算或不参与控制。

## WARMING_UP

正在预填充滤波器、观测器或优化器状态。

## SHADOW

执行完整计算，但没有最终控制权。

## ARMED

已经获得接管许可，等待切换时刻。

## ACTIVE

拥有最终控制权。

## DEGRADED

仍然可用，但性能或输入质量下降。

## FAILING

正在进入失败状态，允许短时保持或降级。

## FAILED

输出不可信，不得进入执行器链路。

## FALLBACK

作为备用控制器接管。

# 47. 控制权角色

定义：

```text
PRIMARY
SECONDARY
SHADOW
FALLBACK
EMERGENCY
DIAGNOSTIC
```

## PRIMARY

当前主控制器。

## SECONDARY

准备接替主控制器。

## SHADOW

运行但不控制。

## FALLBACK

主控制器失败后自动接管。

## EMERGENCY

用于悬停、降落或最低风险控制。

## DIAGNOSTIC

仅输出诊断，不参与控制。

# 59. 渐变切换

设原控制器输出为：

[

]

目标控制器输出为：

[
u_b
]

切换输出：

[
u=(1-\alpha)u_a+\alpha u_b
]

其中：

[
\alpha:0\rightarrow1
]

只有相同物理输出层级的命令可以直接混合。

# 79. 连续失败门槛

```text

警告，使用上次可行输出

2～3次连续失败：
```

```text
优化控制器：
可以短时使用上一可行解
```

超过有效期后必须拒绝。


# 147. 强制性设计规则

1. 同一时刻只有一个控制器拥有最终控制权。

2. 所有控制器必须通过Controller Registry注册。

3. 原子控制器与组合Profile必须分离。

4. Controller Manager不得包含具体控制算法。

5. 控制器切换必须经过兼容性和健康检查。

6. 新控制器在正式接管前应优先进行WARMING_UP或SHADOW运行。

7. 控制器输出不得依靠Topic最后到达顺序完成仲裁。

8. Command Arbiter是最终命令的唯一选择者。

9. 控制器失效必须有明确Fallback Policy。

10. 紧急控制器必须简单、确定且经过充分验证。

11. 参数修改必须采用事务和原子提交。

12. 参数必须具有类型、单位、范围和更新等级。

13. 飞行中不得修改COLD和BUILD参数。

14. 参数提交失败必须回滚。

15. 正式实验必须冻结配置。

16. 每个Profile必须计算版本和哈希。

17. PX4、ROS、MWORKS和前端不得各自维护独立参数语义。

18. 所有配置必须由Config Resolver合并。

19. 安全参数优先级高于普通Profile。

20. 控制器自动切换必须设置滞回和冷却时间。

21. 不同输出层级切换不得简单数值插值。

22. 控制器状态迁移必须显式定义。

23. 多机系统中每架无人机必须具有独立控制器运行状态。

24. Controller Manager不得绕过PX4系统级解锁和失效保护。

25. 前端不得直接控制执行器。

26. 配置损坏时必须加载安全默认控制器。

27. 所有切换、回滚和降级事件必须记录。

28. 未通过相应验证等级的Profile不得用于更高风险环境。

# 148. 最终结论

MoSim控制器管理系统不能采用：

```text
前端直接修改控制器变量
每个控制器自己读取参数
多个控制器同时发布PX4控制Topic
切换时直接停止旧控制器并启动新控制器
NMPC失败后继续发送旧命令
每种组合复制一份控制器工程
```

应采用：

```text
Controller Registry
        ↓
Profile Resolver
        ↓
Parameter Transaction
        ↓
Controller Instance
        ↓
Health Monitor
        ↓
Switch Manager
        ↓
Command Arbiter
        ↓
统一最终控制输出
```

最终实现：

```text
控制器可注册
控制器可组合
参数可追溯
配置可验证
切换可无扰
失败可降级
多机可管理
前端可统一控制
实验可完整复现
```

这样MoSim中的PX4原生控制器、px4ctrl、MWORKS生成控制器、SE3、DFBC、LMPC、NMPC、INDI、L1和故障容错控制器，才能真正作为同一平台内可安全替换、可组合、可部署和可评价的控制组件运行。
