# 展示与实验平台接口

> 状态：设计冻结入口，2026-06-24。
>
> 本文定义RViz、诊断用Gazebo GUI、UE、Web、QGC和实验平台如何接入MoSim。
> 显示层不拥有控制闭环权威；实验平台只提交受约束的Profile，不直接拼裸命令。

## 1. 平台定位

展示与实验平台负责：

```text
实验Profile选择；
兼容性检查结果展示；
运行状态、窗口和证据入口；
RViz/UE/QGC/Web多视图审核，Gazebo GUI仅作诊断或人工要求窗口；
指标、日志、截图、视频和manifest收集入口。
```

展示与实验平台不负责：

```text
计算控制器成功指标；
替代PX4/MAVROS/Gazebo日志；
直接改控制器参数或PX4参数；
直接发布MAVROS setpoint；
绕过Orchestrator运行任意shell命令；
把UE或RViz画面当成truth。
```

## 2. 显示层职责

| 显示面 | 当前职责 | 不允许做的事 |
| --- | --- | --- |
| RViz | 点云、累计地图、栅格地图、TF、飞机三轴、参考轨迹、实际轨迹、规划结果审核 | 作为指标计算源；隐藏frame错误后继续验收 |
| Gazebo | 后台plant运动、机体/雷达/相机装配、碰撞、场景和基础动画；GUI只在诊断或人工要求时打开 | 常驻前台展示；替代日志评价；显示卡顿时判定控制失败 |
| QGC | PX4连接、模式、解锁、failsafe、参数可见性和人工急停观察 | 作为控制器配置主入口；绕过Profile改实验参数 |
| Web/前端 | ExperimentProfile选择、兼容性结果、运行状态、证据入口 | 按钮直接运行裸`sh`或`roslaunch` |
| UE | 后置增强展示、场景视频、多机总览、第一视角窗口、10Hz全局姿态轨迹、可选场景校验面 | 当前阶段作为控制闭环依赖、truth来源或轨迹精度评价源 |

展示路线以UE展示、QGC/前端受约束实验入口和RViz工程审核分工为主，而不是先做
独立Web大界面：

```text
QGC二次开发:
  实验Profile选择、飞控状态、模式/解锁/failsafe、参数可见性、人工干预入口

UE:
  高质量场景渲染、多机展示、第一视角、视频素材、Factory L2静态地图导入/校验

Orchestrator:
  接收QGC/前端提交的Profile，校验兼容性，生成Launch Plan并记录Manifest
```

当前可推进的S11前置工作是Factory L2静态导入Gazebo、单向UE渲染镜像和
UE Global Overview 10Hz姿态轨迹；QGC二次开发、完整UE实验控制台和实时UE truth
仍属后置阶段。上述任何展示工作都不能替代ROS/Sunray/Gazebo/PX4/MAVROS/RViz
日志与指标证据。

UE第一版实现采用单向渲染镜像，详见
`Docs/Design/架构/04_展示与实验平台/UE渲染镜像桥接方案.md`：

```text
Gazebo/PX4/MAVROS/ROS1/Sunray
  -> state/log/topic export
  -> bridge adapter
  -> UE actor pose/camera/trajectory rendering
```

该桥接不允许UE反向发布MAVROS setpoint、改PX4模式/参数、反写Gazebo状态，
也不允许UE truth直接进入FAST-LIO、planner或controller。

因此展示平台的UE任务必须先分清四个产物：

| 产物 | 解决的问题 | 不解决的问题 |
| --- | --- | --- |
| Scene Base | 场景背景、坐标原点、可选碰撞/占据对齐 | 运行状态、轨迹、机体姿态、数据实时性 |
| Data Bridge | ROS/Gazebo/PX4/MAVROS/Sunray状态帧、轨迹、事件进入UE | 场景资产导出、控制/规划/定位成功 |
| Runtime Display | UE中按真实状态流显示机体、第三视角、Global Overview和姿态残影 | 评价指标、planner成功、闭环成功 |
| Evidence Export | 截图、视频、manifest和review bundle | 替代RViz/log/metrics工程证据 |

第一版运行时显示必须优先做`T0 replay`：从已有run bundle导出
`ue_render_frame.jsonl`和`mosim.ue_render_stream_manifest.v1`，再驱动UE播放。
只有T0契约稳定后，才进入`T1 live sidecar at 10Hz`。UE端可以插值、丢帧或只显示
最新帧，但不得反压ROS、Gazebo、PX4、MAVROS、planner或controller。

Factory是第一张正式UE地图。地图路线优先做L2静态导入Gazebo，而不是实时UE
truth。L2导入必须包含真实visual mesh、分块collision mesh、semantic manifest、
坐标契约、对齐报告和用户审核包，详见
`Docs/Design/架构/04_展示与实验平台/Factory地图导入与全局态势视图.md`。
Factory L2只证明Scene Base可用；没有Data Bridge和stream manifest时，不得声明
UE运行时展示系统完成。

## 3. ExperimentProfile入口

前端和脚本入口只能提交已注册Profile。Profile至少包含：

```text
scenario_profile
plant_profile
sensor_profile
state_source_profile
height_source_profile
truth_profile
trajectory_profile
planner_profile
controller_profile
augmentation_profile
safety_profile
adapter_profile
fault_profile
disturbance_profile
frequency_profile
display_profile
evaluation_profile
```

Orchestrator必须先完成兼容性检查，再生成launch plan。检查失败时必须拒绝
启动，并记录失败原因；不得静默换控制器、换状态源或关闭安全模块。

## 4. 多窗口审核布局

第一阶段单机默认布局：

```text
RViz主窗口:
  点云/地图/TF/飞机三轴/参考轨迹/实际轨迹

QGC:
  模式、解锁、failsafe和参数状态

UE Global Overview:
  10Hz显示当前机体姿态、可配置采样间隔的历史姿态轨迹和起终点/事件标记
```

多机扩展默认布局：

```text
RViz总览:
  多机三轴、轨迹、局部地图或累计地图

UE Global Overview:
  多机空间关系、每机颜色、当前姿态、可配置采样间隔的延时摄影轨迹

第一视角窗口:
  每架飞机一个相机窗口；三机时形成2个总览 + 3个第一视角窗口
```

若机器性能不足，第一视角窗口可以降帧或录制回放，但不得阻塞控制、定位和
规划进程。

## 5. RViz frame和轨迹规则

RViz必须清楚区分以下对象：

| 对象 | 语义 |
| --- | --- |
| 飞机三轴 | 飞控/机体中心，代表当前控制状态或评价状态Profile指定的机体位姿 |
| 参考轨迹 | Trajectory Server或Planner Adapter输出的参考路径 |
| 实际轨迹 | 机体中心实际轨迹，不能用雷达中心轨迹冒充 |
| FAST-LIO轨迹 | 定位算法输出，可用于对照，但默认不作为飞机实际轨迹主显示 |
| 点云/累计地图 | 传感器或FAST-LIO地图结果，必须声明frame和来源 |

若雷达不在飞控中心，显示层必须使用已冻结外参把雷达位姿转换到机体中心；
否则只允许标注为LiDAR frame，不得标注为飞机中心。

## 6. 证据采集

每次正式实验至少采集：

```text
run_id；
profile manifest和hash；
ROS/PX4/Gazebo日志；
控制状态、参考轨迹、控制输出和truth数据；
metrics.json或等价指标表；
RViz截图或录屏；
Gazebo/UE/QGC按需截图或录屏；
失败时的blocker和禁止声明。
```

显示证据只能辅助审核“看到了什么”；最终误差、稳定性和成功/失败必须来自日志
和评价脚本。

## 7. 禁止声明

```text
禁止把RViz点云非空声明为FAST-LIO闭环成功；
禁止把UE/Gazebo动画流畅声明为控制器误差达标；
禁止把前端按钮能启动声明为实验平台完整；
禁止把多窗口打开声明为多机编队完成；
禁止把显示层frame修正声明为控制状态源修正；
禁止在飞行中无门禁切换Controller Core或状态源。
禁止把UE Global Overview轨迹残影声明为轨迹精度、碰撞或planner成功证据；
禁止把AABB/box proxy导出声明为Factory L2近无损地图导入完成。
```
