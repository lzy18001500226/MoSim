# 0. 当前阶段测试入口

当前对象级验收不在本文重复展开，入口固定为：

```text
WF-01 附录A：px4ctrl Golden Slice执行与验收矩阵
WF-01 附录B：EGO、EGO-Swarm与FAST-LIO阶段验收矩阵
```

本文继续负责：

```text
通用场景定义
通用指标公式
通用失败判据
最终横向比较规则
报告证据规范
```

当前阶段验收不得只看截图或“能飞”。px4ctrl 至少需要完成：

```text
G0 接口与状态机
G1 基础闭环
G2 标准轨迹
G3 异常处理
G4 参数冻结
G5 core抽取一致性
G6 MWORKS/代码离线一致性
G7 Gazebo闭环A/B一致性
```

FAST-LIO 不参与 G0-G7 的阻塞验收；它属于后续状态源替换与完整工程验证。

G9 控制器扩展中的 `step_x / step_y / step_z` 使用 step response gate，
不得再用全程轨迹 RMSE 评价阶跃瞬态。主判据是阶跃后 settled window 的
primary-axis RMSE / p95 / max、settled XYZ RMSE / p95 / max，以及起飞前后的
稳态悬停窗口。`truth_local_delta_error` 在 step gate 中只作为状态源 sanity
检查，检查窗口限定为 `hover_before + step_* + hover_after`；降落段 PX4 local
Z 滞后真值下降的瞬时 max 只保留为 diagnostic，不得否决 step_z 控制响应。

MWORKS代码生成与PX4部署另设独立门禁，不能与G0-G7混用：

| 门禁组 | 验收对象 | 当前阶段关系 |
| --- | --- | --- |
| G-CODEGEN-0/1 | 生成C/C++可编译、与参考core离线一致 | MWORKS Golden Slice必需 |
| G-ROS-0 | 生成core通过ROS/Sunray/MAVROS回灌A/B | 第一阶段生成代码进入闭环的最高门禁 |
| G-PX4-0/1/2 | PX4空Module、uORB影子订阅、影子计算和日志 | 后续PX4内部部署预备门禁 |
| G-PX4-3 | PX4 SITL中发布控制setpoint并稳定闭环 | 后续PX4内部控制门禁 |
| G-PX4-4/5 | 目标飞控编译、参数可见、HITL候选 | 板载和真机前置门禁 |

`G-ROS-0`通过不代表PX4内部Module完成；`G-PX4-0/1/2`通过也不代表控制器
已经拥有飞行控制权。每组门禁必须有独立日志、profile hash和禁止声明。

## 0.1 需求-架构-实验-证据追踪矩阵

每个正式实验必须能从需求追到架构profile、运行配置和证据目录。最小字段为：

| 追踪对象 | 必填内容 | 失败示例 |
| --- | --- | --- |
| Requirement | `REQ-*`编号、验收目标、场景类型 | 只有口头目标，没有需求编号 |
| Architecture Profile | controller、state_source、truth、trajectory、plant、display、frequency profile | 使用混合状态源但未声明 |
| Experiment Config | run_id、launch plan、参数文件、随机种子/扰动配置、车辆数量 | 只保存截图，没有可复现实验配置 |
| Runtime Evidence | rosbag/log/csv、Gazebo truth、控制输出、状态健康、planner状态 | RViz非空即宣称成功 |
| Metrics | RMSE、max、稳态窗口max、overshoot、settling、频率、丢帧、约束违例 | 只报全程max，不报稳态窗口 |
| Review Assets | RViz/Gazebo/UE截图或视频、轨迹图、点云/地图图 | 图像没有profile和时间戳 |

排行榜和横向比较必须按实验组分开。非FAST-LIO基线、Gazebo truth debug、
FAST-LIO独立评价、FAST-LIO经PX4 EKF闭环、混合Z定高替身不能混在同一张
控制器性能表里比较。

## 0.2 当前比赛 Control Profile 测试矩阵

当前已批准的目标目录是 47 个 Control Profile：46 条现有路线按七族重新归类，再加
目录中仍标记为 `planned/not_runnable` 的 `PidAwffLinearEso`。当前 46 条路线的
G6 记录是图形内部探针/执行证据，不是 46 条完整整机闭环；该 Profile 已另行登记
FormalRunner 并完成一条 50 s 负性能记录，但尚未完成 `current_model` 映射和正式
选择资格。因此下面是后续实验矩阵，不是完成声明。

| 阶段 | 对象 | 最低目标 | 不能据此宣称 |
| --- | --- | --- |
| M1 最小闭环 | 46 条现有路线；另行保留 `PidAwffLinearEso` 的 FormalRunner 负记录 | 每条路线通过明确 Adapter 接入同一 `Sunray150Assembly`，完成一次有界、可记录的整机最小闭环 | 七场景性能、代码生成或 Gazebo 部署成功 |
| M2 家族筛选 | 七个控制器族各一条冠军，外加 Official PID | 在相同机体、初值、参考、限幅和评价窗下完成七场景 A/B | 其他同族 Profile 已被完全淘汰或不值得保留 |
| M3 ESO 消融 | `PidAwff`、`PidAwffL1Residual`、`PidAwffLinearEso` | 在名义、风扰和参数失配下比较，并记录估计扰动、补偿幅值和限幅状态 | ESO/L1 已发明，或任一补偿一定优于另一补偿 |
| M4 编队专项 | 选定的单机冠军加编队参考 | 单独验证编队参考、协同性和安全距离 | 编队参考等于新增单机控制器 Profile |

M2 的正式七场景固定为：

| 场景 | 评价重点 |
| --- | --- |
| 悬停 | 稳态位置/姿态误差与控制抖动 |
| 阶跃 | 超调、调节时间和 settled-window 误差 |
| 8 字 | 连续横向轨迹跟踪 |
| 螺旋 | 三维连续轨迹跟踪 |
| 风扰 | 外部扰动下的性能保持度 |
| 参数失配 | 模型不确定性下的稳定性和误差退化 |
| 电机效率下降 | 执行器能力下降下的稳定性和任务退化；仅作为物理注入，不等于 FDI/FTC |

每次 M2/M3 对比至少输出位置 RMSE、p95、峰值、终端误差；阶跃额外输出超调和调节时间；
同时记录姿态误差、控制峰值、饱和比例和控制增量。失败、发散、接口不匹配或无有效结果
都必须单列为失败证据，不能用截图或相邻 Profile 的结果补位。`CBF` 在尚无真实约束场景
及触发记录时只能保留为研究候选，不进入 M2 冠军收益结论。

本规范用于测试：

```text
回归验证
```

# 2. 测试总体目标

MoSim测试体系应回答以下问题：

## 2.1 控制器是否正确

验证：

```text
控制公式实现是否正确
坐标系和符号是否正确
输入输出语义是否正确
控制方向是否正确
离散化是否正确
状态初始化是否正确
```

## 2.2 控制器性能如何

评价：

```text
跟踪精度
动态响应
姿态稳定性
控制平滑度
能量消耗
约束满足程度
计算开销
```

## 2.3 控制器是否鲁棒

验证控制器面对以下变化时是否仍然稳定：

```text
质量和惯量偏差
气动参数偏差
质心偏移
电机性能差异
风扰和外力
测量噪声
状态估计延迟
控制通信延迟
执行器延迟
```

## 2.4 控制器是否安全

验证：

```text
是否超过速度和倾角限制
是否超过电机能力
是否发生碰撞
是否离开地理围栏
求解器失效时是否正确降级
数据失效时是否进入安全状态
```

## 2.5 控制器是否可以部署

验证同一控制算法在：

```text
MWORKS模型
离线C++程序
ROS 1节点
Gazebo联合仿真
PX4 SITL Module
真实飞控板
```

上的结果是否具有可接受的一致性和实时性。

# 3. 强制性测试原则

## 3.1 公平性原则

比较不同控制器时必须保持以下条件一致：

```text
同一四旋翼模型
同一初始状态
同一参考轨迹
同一仿真步长
同一扰动信号
同一噪声序列
同一执行器限制
同一状态估计输入
同一失败判定规则
同一评价时间区间
```

禁止为某一控制器单独降低轨迹速度、扰动幅度或执行器约束。

---

## 3.2 可复现原则

每次实验必须记录：

```text
实验编号
随机种子
代码版本
模型版本
控制器版本
参数版本
PX4版本
MWORKS版本
ROS工作空间版本
Gazebo世界版本
操作系统与硬件信息
```

所有随机扰动、噪声、故障时刻和初始误差必须由记录的随机种子重新生成。

---

## 3.3 分层验证原则

控制器必须从低风险测试逐级进入高风险测试。

```text
单元测试
  ↓
算法开环测试
  ↓
MWORKS模型闭环
  ↓
软件在环闭环
  ↓
ROS 1 + Gazebo联合仿真
  ↓
PX4 SITL
  ↓
板载计算测试
  ↓
HITL
  ↓
真机测试
```

上一层未通过时，不得直接进入下一层。

---

## 3.4 基线对照原则

每项对比实验至少包含：

```text
官方原始PID
PX4原生控制器
px4ctrl复现控制器
待评价控制器
```

根据实验目标，可以增加：

```text
SE(3)几何控制
DFBC
LMPC
NMPC
最佳已知控制器
```

---

## 3.5 名义控制与增强模块分离原则

测试增强模块时必须进行消融实验。

例如：

```text
NMPC
NMPC + INDI
NMPC + L1
NMPC + INDI + L1
```

或：

```text
DFBC
DFBC + 阻力补偿
DFBC + INDI
DFBC + 阻力补偿 + INDI
```

禁止只提供最终组合，而不说明性能提升由哪个模块产生。

# 4. 测试等级体系

MoSim定义八个测试等级。

## L0：静态与单元测试

测试对象：

```text
坐标转换
四元数计算
数学函数
控制分配
推力映射
滤波器
限幅器
轨迹求值器
故障注入器
指标计算器
```

不运行完整四旋翼闭环。

验收重点：

```text
公式正确
边界正确
无NaN
可重复
覆盖异常输入
```

---

## L1：算法开环测试

向控制器输入预先记录或人工构造的：

```text
状态序列
参考序列
执行器状态
扰动估计
故障状态
```

检查控制器输出是否符合理论预期。

典型测试：

```text
位置误差为正时输出方向是否正确
姿态误差方向是否正确
悬停推力是否接近mg
约束是否正确生效
积分器是否正确复位
求解器失败是否返回正确状态
```

---

## L2：MWORKS纯模型闭环

使用MWORKS内部：

```text
四旋翼动力学模型
电机与电调模型
传感器模型
控制器模型
扰动和故障模型
```

完成闭环仿真。

用途：

```text
算法设计
参数整定
理论验证
快速批量仿真
控制器消融
模型参数扫描
```

---

## L3：控制器生成代码闭环

将MWORKS控制器生成的C/C++代码接入独立闭环测试程序。

动力学可使用：

```text
MWORKS导出的动力学模型
MoSim C++动力学模型
离线记录状态回放
```

用途：

```text
验证生成代码与原模型一致
发现代码生成限制
检查固定步长执行
检查内存与运行时间
```

---

## L4：ROS 1 + Gazebo联合仿真

运行：

```text
ROS 1
Gazebo
MoSim控制节点
规划器或轨迹发生器
传感器与状态估计节点
日志与Test Harness
```

用途：

```text
验证ROS接口
验证坐标和时间同步
验证Gazebo动力学
验证传感器闭环
验证规划器—控制器闭环
验证多机系统
```

---

## L5：PX4 SITL测试

运行PX4 SITL，并根据控制接口测试：

```text
PX4原生控制器
Offboard位置控制
姿态 + 推力控制
角速度 + 推力控制
力矩 + 推力控制
PX4内部自定义Module
```

用途：

```text
验证uORB接口
验证PX4状态机
验证模式切换
验证控制环绕过关系
验证Controller Manager
验证日志和参数机制
```

---

## L6：板载计算与实时性测试

在目标飞控板上运行控制器，但不驱动真实螺旋桨。

包括：

```text
控制器单独基准测试
完整PX4固件调度测试
CPU占用测试
栈和堆内存测试
最坏执行时间测试
参数更新测试
长时间稳定性测试
```

---

## L7：HITL测试

真实飞控板运行目标PX4固件，外部仿真器提供动力学和传感器。

重点验证：

```text
真实飞控板调度
真实编译配置
真实uORB通信
真实串口或网络链路
板载求解器实时性
硬件相关延迟
```

---

## L8：真机测试

按照风险逐步增加：

```text
拆桨台架
系留测试
低高度悬停
低速轨迹
高动态轨迹
扰动试验
容错试验
多机飞行
```

真机阶段不以复现所有极端仿真故障为目标。

完全电机失效、多机失效和高风险故障优先在仿真与安全台架中完成。

# 22. 姿态跟踪指标

## 22.1 旋转误差

期望姿态和当前姿态分别为：

[
R_d,\ R
]

定义姿态误差角：

[
e_R =
\cos^{-1}
\left(
\frac{\operatorname{tr}(R_d^T R)-1}{2}
\right)
]

计算：

```text
姿态角RMSE
最大姿态误差角
P95姿态误差角
```

该指标不受欧拉角奇异性影响。

# 29. 鲁棒性指标

## 29.1 性能保持率

[
R_{perf}=
\frac{J_{nominal}}
{J_{disturbed}}
]

也可以表示为性能下降百分比：

[

\frac{J_{disturbed}-J_{nominal}}
{J_{nominal}}

[
R_{success}=
\frac{N_{successful}}
{N_{total}}

# 36. 控制器验收等级

## A级：算法正确

满足：

```text
单元测试通过
算法开环方向正确
悬停闭环稳定
无NaN和发散
```

## B级：标准轨迹通过

满足：

```text
阶跃
圆形
8字
螺旋
多航点
```

达到基本性能阈值。

## C级：鲁棒性通过

在规定模型偏差、风扰、噪声和延迟下保持稳定。

## D级：工程集成通过

通过：

```text
ROS 1
Gazebo
PX4 SITL
代码生成一致性
```

## E级：板载实时通过

在目标飞控板上满足周期和资源限制。

## F级：高级安全通过

根据控制器类型通过：

```text
故障容错
约束管理
控制器降级
多机防碰撞
```

## G级：真机验证通过

在批准的真机测试范围内完成飞行验证。

## G9控制器族工程验收分级

G9控制器族不采用“所有控制器必须达到同一厘米级最优指标”的单一门槛。
不同控制器可能因控制结构、输出层级、实时性和约束处理能力不同而停在不同
等级。验收采用三档：

```text
PASS：工程可用，能稳定完成任务，可作为对照组或后续改进基础。
REPORT：效果较好，可进入报告横向对比。
CANDIDATE：效果接近比赛主控候选，值得继续做鲁棒性和真机化投入。
```

G9所有控制器共同硬门槛：

```text
无坠机；
无碰撞；
无NaN或Inf；
无错误坐标系/控制方向；
无持续电机饱和；
Offboard/PX4状态机正常；
日志、Profile、参数和证据路径完整；
资料/论文/开源依据审计完成；
若涉及MWORKS/codegen，离线一致性通过后才允许Gazebo闭环。
```

名义低速、无扰动、PX4/MAVROS融合状态下的G9首版指标：

| 场景 | PASS | REPORT | CANDIDATE |
| --- | ---: | ---: | ---: |
| 起飞/悬停/降落稳态XYZ RMSE | <= 0.05 m | <= 0.03 m | <= 0.02 m |
| 起飞/悬停/降落稳态max error | <= 0.10 m | <= 0.06 m | <= 0.04 m |
| 8字/圆形/螺旋XYZ RMSE | <= 0.10 m | <= 0.05 m | <= 0.03 m |
| 轨迹终点/悬停收敛误差 | <= 0.10 m | <= 0.05 m | <= 0.03 m |
| 三机Diff每机目标误差 | <= 0.10 m | <= 0.05 m | <= 0.03 m |
| 三机最小机间距离 | >= 0.80 m | >= 0.90 m | >= 0.95 m |

说明：

```text
1. 全程max error只作为诊断，不作为唯一通过门槛。
2. 稳态窗口max error有验收意义，必须单独报告。
3. 阶跃测试不使用“全程max小于厘米级”判据，必须报告超调、调节时间和稳态误差。
4. 若控制器优化到头只能达到PASS，仍可作为有效对照组；不得伪造为REPORT或CANDIDATE。
5. 若控制器在单机场景优秀但三机Diff失败，只能记录为单机通过，不能宣称G9完整通过。
6. FAST-LIO状态源、混合Z替身、Gazebo truth debug必须使用独立排行榜，不能与PX4/MAVROS融合状态基线混报。
```

# 48. 回归测试规范

## 48.1 快速回归

每次控制器代码提交执行：

```text
单元测试
悬停10秒
位置小阶跃
短8字轨迹
NaN和超时检查
```

目标运行时间应尽可能短。

## 48.2 标准回归

合并到主分支前执行：

```text
基础稳定性
标准轨迹
标称参数
基础风扰
基本模型摄动
ROS/Gazebo接口
```

## 48.3 完整回归

版本发布前执行全部：

```text
TS00～TS15
```

HITL和真机根据硬件条件单独安排。

## 48.4 性能回退判断

新版本若出现以下情况，应阻止合并或要求人工审核：

```text
RMSE明显增大
执行时间明显增加
新出现约束违反
新增失败场景
输出不再跨平台一致
日志字段缺失
```

允许控制器在某一指标退化而另一指标改善，但必须记录设计权衡。

# 53. 强制性规则汇总

1. 所有控制器使用同一参考轨迹、模型、扰动和评价区间进行公平比较。

2. 所有含随机因素的试验必须记录随机种子。

3. 控制器求解失败、超时和坠机不得作为异常值删除。

4. 每个控制器必须先通过低等级测试，再进入高等级测试。

5. MWORKS模型与生成代码必须进行单周期和闭环一致性验证。

6. ROS、Gazebo和PX4日志必须使用实验ID和统一时间基准对齐。

7. 跟踪性能不得只报告单一RMSE，必须同时报告最大值和统计分布。

8. 实时控制器必须报告执行时间分布和截止时间错过率。

9. 故障诊断必须报告检测延迟、隔离精度、误报率和漏报率。

10. 多机系统必须报告编队误差、最小机间距离、通信负载和成功率。

11. 综合评分不得覆盖硬性安全门槛。

12. 出现碰撞、坠机、NaN或严重约束违反时，实验不得判定通过。

13. 控制器增强模块必须通过消融实验验证实际贡献。

14. 正式版本必须保存原始日志、配置和代码版本，而不只是结果图。

15. 所有自动生成结论必须能追溯到具体指标和原始数据。

# 54. 文档结论

MoSim控制系统测试体系的目标不是简单生成若干轨迹曲线，而是建立从数学实现到真实部署的完整验证链：

```text
单元正确
    ↓
模型闭环稳定
    ↓
生成代码一致
    ↓
Gazebo环境可运行
    ↓
PX4 SITL集成正确
    ↓
目标飞控板满足实时性
    ↓
HITL验证硬件集成
    ↓
真机验证最终能力
```

每个控制器都必须使用统一工况、统一指标和统一失败规则进行评价。

最终，MoSim应能够自动完成：

```text
选择控制器
选择轨迹
选择扰动和故障
启动仿真
记录多源数据
计算性能指标
与基线比较
判断是否通过
生成测试报告
归档原始结果
```

使控制器性能不再依赖人工观察和主观描述，而形成可量化、可复现、可回归、可扩展的完整测试闭环。
