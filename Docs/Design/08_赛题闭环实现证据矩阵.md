# 08 赛题闭环实现证据矩阵

Status: implementation evidence audit, 2026-06-10.

Purpose: record what is already implemented and evidence-backed before
post-competition platform expansion. This file does not change the acceptance
rules in `07_验收Gate与交付物.md`; it maps current source/model/config/result
artifacts to the C0/C1/C2 competition gates.

## 1. Status Vocabulary

Use these statuses when reviewing competition completion:

| Status | Meaning |
|---|---|
| `evidence_backed` | Source/config/result artifacts exist and metrics or logs support the specific claim. |
| `partial_evidence` | Meaningful artifacts exist, but the gate still needs a narrower review, final choice, or missing evidence type. |
| `source_static_only` | Source/config/checker artifacts exist, but no accepted live/runtime/result claim is proven. |
| `blocked_not_accepted` | Current evidence explicitly blocks the claim or records the absence of required proof. |
| `design_only` | The design exists, but implementation/result evidence has not been accepted. |
| `post_competition_only` | The item belongs to platform expansion and must not be counted as competition closure unless a future requirement explicitly pulls it into scope. |

## 2. Competition Scope Boundary

The competition closure target is:

```text
C0 minimum MWORKS-native control loop
  -> C1 single-UAV optimized control and robustness evidence
  -> C2 minimum multi-UAV / formation evidence
```

PX4, QGC, SITL/HIL, full ROS2/FAST-LIO planning closure, UE runtime/editor/build
acceptance, hardware replay, and final platform UI are designed for later
expansion. They are not counted as C0/C1/C2 completion unless a future PMO/user
decision changes the competition claim.
