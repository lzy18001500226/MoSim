# MoSim系统架构定版

> 状态：当前架构入口，2026-06-23。
>
> 本文只定义系统级架构、当前执行路线和禁止边界。控制接口、FAST-LIO、
> 规划/编队、代码生成、调参和测试细节由对应专题规范负责。

## 1. 架构结论

MoSim 当前不是通用机器人导航栈，而是面向 A8 四旋翼赛题的控制系统工程。
主线是：

```text
MWORKS/Sysblock 控制器建模与代码生成
  -> 标准 C/C++ controller core
  -> Controller ABI / Adapter
  -> PX4/MAVROS 飞控仿真接口
  -> Sunray/Gazebo plant、传感器和执行器
  -> FAST-LIO / EGO / EGO-Swarm 自主飞行组件
  -> RViz/Gazebo/UE/前端展示与证据
```

其中 MWORKS 是控制算法建模、MIL/SIL、代码生成、等价性测试和报告证据
的主体；Sunray/PX4/Gazebo 是工程级运行基线；FAST-LIO、EGO、EGO-Swarm
是外部自主飞行组件，不搬进 MWORKS 重写。

## 2. 当前运行基线

当前可执行审核路线冻结为：

```text
Ubuntu-20.04 / ROS1 Noetic
  -> References/Sunray
  -> reviewed sunray150_with_mid360
  -> Gazebo Classic
  -> PX4 + MAVROS
  -> px4ctrl
  -> MID360 / FAST-LIO / EGO / RViz review
```

当前不得把以下路线作为正式进度：

```text
Ubuntu-22.04 / ROS2 Humble / PX4 x500
ROS2 直接写 Gazebo motor/actuator topic
Python truth-feedback 控制器
MWORKS CSV 开环回放
fake/static point cloud
只看 RViz/Gazebo 非空画面
```

这些只能作为诊断夹具或历史参考，不能替代当前 Sunray/PX4/Gazebo 主链路。

## 3. 四层职责

| 层 | 权威内容 | 当前规则 |
|---|---|---|
| MWORKS 建模层 | 控制器模型、MIL/SIL、参数优化、代码生成、离线一致性 | 是比赛控制算法主体，但不单独证明工程闭环 |
| 飞控接口层 | PX4、MAVROS、Offboard、EKF、模式、解锁、failsafe | 每次运行只允许一个主动控制后端 |
| Plant/传感器层 | Sunray/Gazebo 机体、动力学、执行器、MID360、IMU、定高、摄像头 | 是当前工程验证 plant 权威 |
| 自主飞行与展示层 | FAST-LIO、EGO/EGO-Swarm、RViz、Gazebo GUI、UE、前端 | 证明感知/规划/展示接入，不拥有控制成功判定 |

任何结果必须说明自己验证的是哪一层。显示层画面对，不等于控制器或定位闭环
通过；MWORKS 模型跑通，也不等于已进入 PX4/Gazebo 工程闭环。

## 4. 最小大系统闭环

当前先完成“最小大系统”，再批量控制器迁移。

最小大系统包括：

```text
Sunray150 + MID360 装配模型
PX4 + MAVROS + px4ctrl 基线
Gazebo Classic 起飞、悬停、降落、8字、螺旋、阶跃
RViz 默认轨迹、累计点云、栅格/规划显示
FAST-LIO 独立定位与 PX4 EKF 融合门禁
EGO 单机
EGO-Planner-v2 单机
Diff-Planner 单机
EGO-Swarm 2机 / 3机基础隔离与避碰
```

最小大系统完成后，才能把它作为后续控制器和 MWORKS 代码生成的统一验证台。

## 5. 控制器推进顺序

控制器不批量铺开。当前顺序是：

```text
1. px4ctrl 作为黄金基线
2. 官方 PID 作为简单替换模板
3. SE3 Basic 作为结构不同的代表控制器
4. MWORKS Golden Slice
5. 后续控制器逐个释放
```

这样可以先证明：

```text
状态源一致
轨迹参考一致
ATTITUDE_THRUST 输出一致
推力映射集中在 Adapter
Gazebo/Sunray plant 一致
评价指标一致
```

再迁移增强 PID、LQI、DFBC、LMPC、NMPC、INDI、L1、安全滤波、故障容错等
控制器。

## 6. 第一阶段控制接口

第一阶段只实际实现：

```text
ATTITUDE_THRUST
```

控制器 core 输出：

```text
desired_attitude_quaternion
desired_collective_thrust_N
controller_status
controller_diagnostics
```

物理总推力到 MAVROS/PX4 归一化推力的映射只允许放在公共 Adapter 中，
不得散落到各个控制器模型里。

以下接口只保留为规划枚举，不进入第一阶段实现：

```text
BODY_RATE_THRUST
WRENCH
ROTOR_THRUST
ROTOR_SPEED
```

## 7. 状态源边界

当前 px4ctrl 基线状态源：

| 数据 | Topic | 用途 |
|---|---|---|
| 位置、速度、姿态 | `/mavros/local_position/odom` | 控制器主要状态输入 |
| 角速度 / IMU | `/mavros/imu/data` | 控制器角速度输入 |
| 模式、解锁、有效性 | `/sunray/uav_state` | 状态机、显示和诊断 |
| Gazebo truth | 实际 truth pose/odom topic | 评价真值，不静默输入控制器 |

FAST-LIO 不能因为 RViz 点云可见就直接进入控制。正确路线是：

```text
MID360 点云 + 雷达 IMU
  -> FAST-LIO
  -> 输出对齐到飞控中心 / base_link
  -> 完整 pose、quaternion、velocity、covariance、timestamp、status
  -> PX4 EKF external odometry / vision 融合
  -> /mavros/local_position/odom
  -> 同一个 px4ctrl
```

`/mosim/fastlio/odom_aligned` 在定位门禁通过前只能作为被测候选，不得直接
作为控制状态源。

## 8. MWORKS Golden Slice

MWORKS 不等到所有控制器都做完才接入。正确时机是：

```text
最小大系统闭环通过
  -> px4ctrl / PID / SE3 三个代表控制器模板通过
  -> 立即做 MWORKS Golden Slice
  -> 再批量控制器迁移
```

Golden Slice 路线：

```text
冻结上游 px4ctrl 与 Sunray px4ctrl
  -> 差异审计
  -> 抽取 px4ctrl_core
  -> 原包装层 / 抽取 core 离线对齐
  -> MWORKS 重建 px4ctrl_core
  -> MWORKS 生成 C/C++
  -> 四方离线一致性
  -> 接回同一个 Sunray/ROS 包装层
  -> Gazebo 闭环 A/B 对齐
```

离线一致性未通过，不允许进入 Gazebo 闭环。

## 9. 规划与集群边界

EGO、EGO-Planner-v2、Diff-Planner、EGO-Swarm 保留为 ROS 外部规划组件。
它们只输出轨迹或规划参考，不直接拥有 MAVROS 控制话题。

规划链路：

```text
Gazebo/MID360/FAST-LIO 或当前基准状态源
  -> planner map / occupancy / bspline
  -> TrajectoryReference
  -> px4ctrl 或 MWORKS 生成 controller core
  -> ATTITUDE_THRUST Adapter
  -> PX4/MAVROS
  -> Gazebo plant
```

集群第一阶段只做官方链路和工程隔离：

```text
2机 / 3机启动
PX4实例隔离
MAVROS实例隔离
px4ctrl实例隔离
规划Topic隔离
FAST-LIO/点云/地图Topic隔离
基础目标导航与避碰
```

暂不做自研一致性控制、Leader-Follower、CBF、故障成员退出和复杂队形重构。

## 10. 真机化边界

在线闭环关键路径最终必须是 C++ 或 MWORKS 生成 C/C++：

```text
T0: controller core
T1: FAST-LIO odom alignment、PX4 external odometry、trajectory server、
    Controller Adapter、safety/failsafe
T2: 上游 C++ 组件，如 FAST-LIO、EGO、px4ctrl
T3: Python launch、metrics、plot、review、offline compare
```

Python 可以作为实验和证据工具，但不能长期作为正式控制律、状态源适配、
external odometry 发布或安全门禁。

## 11. 当前执行顺序

当前推荐执行流：

```text
G0 文档和路径入口冻结
G1 Sunray/PX4/MAVROS/px4ctrl 基线
G2 起飞、悬停、降落、8字、螺旋、阶跃
G3 FAST-LIO 独立定位与 PX4 EKF 融合门禁
G4 EGO / EGOv2 / Diff-Planner 单机复现
G5 EGO-Swarm 2机 / 3机工程隔离
G6 px4ctrl / PID / SE3 代表控制器模板
G7 MWORKS Golden Slice
G8 后续控制器逐个迁移
G9 UE / 前端 / 报告展示
```

每个 Gate 的完成必须有日志、指标、截图、结果包或源码/静态检查证据。文档
本身不是运行成功证据。

## 12. 禁止事项

当前禁止：

```text
遇到问题后静默换主线
把 Python truth-feedback 当正式控制器
把 ROS2/x500 历史路线当当前 Sunray 证据
把 RViz 点云可见当 FAST-LIO 定位闭环
把 Gazebo truth 静默混入 FAST-LIO 后宣称全雷达定位
把 planner 输出当闭环飞行成功
把 MWORKS 模型仿真当 PX4/Gazebo 部署成功
在离线一致性失败时继续做 Gazebo 闭环
批量铺开控制器后再补接口
```

## 14. 结论

当前架构可以概括为：

```text
先把 Sunray/PX4/Gazebo/FAST-LIO/EGO/EGO-Swarm 组成的最小大系统跑通；
再用 px4ctrl、PID、SE3 建立控制器替换模板；
随后立即做 MWORKS Golden Slice；
最后逐个迁移高级控制器、故障容错、集群和展示系统。
```
