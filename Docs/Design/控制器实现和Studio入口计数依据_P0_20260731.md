# 控制器实现与 Studio 入口计数依据（P0，2026-07-31）

## 1. 静态核对方法

本清单不使用目录中全部 `.mo` 文件数来替代控制器数量。它以
`Config/control_platform/current_model_entry_map.json` 的 `schemes` 为计数对象：

1. `implementation_status=implemented` 的条目数为 46；
2. 对每条 `current_model_file` 执行静态存在性检查，以下 46 条均存在；
3. Studio 入口以 `Config/control_platform/model_studio_task_routes_v1.toml` 的
   `available=true` 为准，数为 48；其 Runner 全类名和文件清单见根目录
   `RELEASE_CHECKLIST.md` 第 4 节，并已逐条核对文件存在。

因此，46 是“当前映射到存在的 Modelica 源文件的已实现控制模块”数量，48 是
“Studio 可写配置并手动打开的 FormalRunner”数量；两者都不表示性能通过。
其中 5 条 `fixed_*` 集成链的源文件位于 `Experiment/Templates/IntegratedChains/`，
不能把“46 个实现模块”机械表述为全部都在 `Control/` 目录。

### 1.1 当前运行与截图统计口径

本文件的 46 是静态实现数，不是当前运行完成数。报告截图审计暂采用
48 条可追溯名义运行证据作为分母：46 条已有 MWORKS Profile、1 条独立
`px4ctrl` MWORKS 基线和 1 条 `pid_awff_linear_eso` 50 s 负证据。后者已
生成终端 `RUN_RECORD`，纳入运行证据分母，但不计入报告通过数。

该 48 条并不等于 48 条性能通过，也不等于 48 条整机闭环截图：G6 的 46
条结果截图审计中仍有 `internal_fixed_input_probe` 证据类别；只有明确绑定
到整机 FormalRunner 的记录才能写成整机仿真。逐项截图覆盖见
`Docs/报告/审计/控制器原生截图归位/FORMAL_RUN_SCREENSHOT_COVERAGE_20260731.md`。

## 3. 计数边界

`current_model_entry_map.json` 的 `implementation_status` 是实现状态，不是 G2/G3
性能状态。其余目录中的辅助类、Adapter、Bridge、基类、历史示例和 `package.mo`
都没有被重复计入 46。Studio 入口则单独由任务路由表维护，不能由本文件反推。
