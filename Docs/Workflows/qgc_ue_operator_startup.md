# MoSim Flight Console 独立操作流程

本文是比赛版 Flight Console/QGC 的操作者入口。目标是操作者只使用根目录脚本和 QGC 完成飞行，不需要临时补终端命令。

## 1. 首次启动

比赛演示推荐顺序：

1. 双击仓库根目录的 `启动MoSim地面站.cmd`。
2. 若当前没有飞行运行时，Flight Console 先进入任务配置模式；此时 UE 区域显示等待状态是正常现象。
3. 在右侧“任务”页选择任务和已开放的控制器 Profile，点击“验证配置”。
4. 确认场景摘要、哈希和 `run_id` 后，点击“启动仿真并连接飞机”或“启动并执行自动任务”。
5. QGC 启动与该 Profile 对应的 Gazebo/PX4/MAVROS 后端，并弹出独立状态终端；保持该终端打开。
6. 运行时就绪后 UE 自动启动并嵌入 Flight Console，QGC 开始显示飞机连接和任务阶段。
7. 按任务页的“下一步”和“操作进度”继续操作。

两个入口职责分离：

- `启动MoSim地面站.cmd` 可以在没有飞行运行时的情况下先打开 QGC，供操作者选择和验证任务。
- `启动Gazebo飞行仿真.cmd` 是独立运行时入口：没有已验证任务时启动单机地面待命；存在 QGC 已冻结的 `ready` 任务时启动该任务。
- 若 QGC 已经验证并冻结了一个 `ready` 任务，`启动Gazebo飞行仿真.cmd` 必须启动该任务，不能另建默认单机任务。
- 若飞行运行时已经存在，`启动MoSim地面站.cmd` 连接当前 `run_id` 并恢复 UE；若运行时不存在，则只启动 Flight Console 配置界面。
- 从 QGC 点击“启动仿真”后，Orchestrator 完成唯一启动裁决，并自动弹出独立的 Gazebo 状态终端；该终端只显示当前 `run_id` 的状态和日志，不拥有飞行控制权。
- 关闭并重新打开 Flight Console 不应停止飞行仿真。
- `停止所有仿真.cmd` 只清理当前 `run_id` 记录的受管进程，不关闭其他 Unreal 项目。

## 2. 单机定点操纵

在“任务”页选择“单机定点操纵”。首次启动脚本已经准备了该 Profile；若切换过其他任务，则重新点击“验证配置”和“启动仿真并连接飞机”。

操作顺序：

1. 等待“飞行阶段”显示飞机已连接。
2. 使用 QGC 原生飞行操作解锁并起飞到悬停高度。
3. 切换到 `Position` 模式。
4. 勾选“启用W/A/S/D定点操纵”，点击键盘控制区使其获得焦点。
5. 使用 `W/A/S/D` 前后左右平移。
6. 结束时使用 QGC 原生降落，确认飞机落地并解除武装。
7. “停止当前仿真”可用后再停止运行时。

单机定点的解锁、起飞和降落责任属于 QGC。未连接、未解锁或不在 `Position` 模式时，键盘操纵必须保持禁用。

## 3. 自动任务

以下任务不要求操作者手动解锁：

| QGC任务 | 飞机数 | 自动执行内容 |
|---|---:|---|
| 单机8字飞行 | 1 | 连接检查、解锁、起飞、8字、降落 |
| 生成代码控制器8字飞行 | 1 | 生成代码运行时、解锁、起飞、8字、降落 |
| FUEL单机自主探索 | 1 | MID360/FAST-LIO/FUEL链路、解锁、起飞、探索、降落 |
| 三机固定编队避障 | 3 | 三机连接、逐机解锁起飞、编队避障、目标保持、降落 |

统一操作顺序：

1. 确认上一任务全部飞机已落地并解除武装。
2. 若上一任务仍处于运行态，先执行“请求安全停止”，等待“安全停止完成”，再点击“停止当前仿真”。
3. 选择任务。控制器 Profile 和无人机数量由任务联动，不在空中切换。
4. 点击“验证配置”，确认显示冻结场景摘要、场景哈希和新的 `run_id`。
5. 点击“启动并执行自动任务”一次，启动期间不得重复点击。
   启动 ACK 成功后会弹出独立的 Gazebo 状态终端；同一 `run_id` 只保留一个监视终端。
6. 在 QGC 中确认连接数、解锁数、任务 Adapter 阶段、飞机位置和告警。
7. 只有任务 Adapter 返回终态 ACK、全部飞机降落并解除武装，任务才算完成。

自动任务的飞行控制权属于 Mission Adapter。操作者不得再使用 QGC 手动解锁、W/A/S/D 或其他控制入口与其争抢控制权。

### 3.1 任务按钮可用性合同

QGC 中显示为可用的任务不能只是界面占位。每个任务必须同时满足：

- Profile、控制器、飞机数量和唯一运行后端能够一一对应；
- 单机定点操纵明确由 QGC 原生飞行操作拥有解锁、起飞和降落权限；
- 自动任务明确由 Mission Adapter 独占解锁、起飞、任务执行和降落权限；
- 自动任务必须向当前 `run_id` 发布任务阶段、逐机连接/解锁状态和终态 ACK；
- 自动任务必须响应当前 `run_id` 的幂等安全停止请求，并确认降落和解除武装；
- 任一合同缺失时，任务必须在源代码检查或 QGC 中保持禁用，不能留作可点击按钮。

静态合同由 `Config/control_platform/runtime_backend_catalog.json` 声明，并由
`Scripts/ui/check_runtime_backend_catalog.py` 检查。静态检查通过只证明接口闭合，
仍需冷启动飞行证据才能把任务标记为运行验收通过。

## 4. 地图与显示

- 工厂缩略图和放大图显示当前飞机位置；无有效运行时遥测时隐藏飞机图标。
- FUEL Profile 显示已冻结的探索边界、任务时长、随机种子和速度限制。
- 三机编队 Profile 显示目标中心、编队间距和逐机状态。
- 实际轨迹、预期轨迹和任务阶段来自当前 `run_id`，不得复用上一任务的数据。
- RViz 点云和栅格地图从“显示”页按需打开；UE 是展示层，Gazebo/PX4/MAVROS/RViz日志是飞行与规划成功的权威证据。

## 5. 异常处理

1. 按钮显示“请求处理中”时不要重复点击。
2. 自动任务异常时先点击“请求安全停止”，等待悬停、降落和解除武装 ACK。
3. 飞机仍处于解锁状态、遥测过期或解除武装证据缺失时，不得强制停止运行时。
4. 基础设施启动失败允许自动重试一次；任务、调参或代码生成失败后等待人工确认。
5. 飞机已起飞时绝不自动重启任务，只允许悬停、降落或安全停止。
6. 本轮全部结束后双击 `停止所有仿真.cmd`。

## 6. 录制前检查

- QGC 显示的任务、控制器、飞机数与冻结 RunManifest 一致。
- UE 已嵌入且显示当前运行的飞机，不是上一 `run_id` 的残留画面。
- 单机定点可由 QGC 原生解锁、起飞、Position/WASD 和降落。
- 自动任务可从 QGC 一次启动，并能看到连接、解锁、执行、降落和终态 ACK。
- FUEL 和编队的地图要素、实际/预期轨迹均来自当前运行。
- 运行编号、日志目录和结果包可追溯。
