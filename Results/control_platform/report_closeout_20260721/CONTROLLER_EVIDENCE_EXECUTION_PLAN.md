## 2. 赛题映射

赛题要求的是基于 MWORKS 的 PID 基线与优化算法对比、螺旋与 8 字等典型轨迹、
阶跃/跟踪指标、风扰或参数摄动鲁棒性，以及多机编队验证。它并不要求每条
控制器路线重复跑全部场景。

因此执行分为两条互不替代的线：

| 线 | 覆盖对象 | 完成条件 |
|---|---|---|
| E1 图形与结果可信度 | 67 条登记路线 | 真实内部图、准确结果绑定、或明确的不可用/接口壳边界。 |
| E2 赛题场景验证 | 官方 PID + 一条经同配置比较后选定的优化路线 | 起飞-悬停-降落、阶跃、8 字、螺旋、风扰、参数摄动、电机效率故障的同配置记录；三机编队以独立代表场景验证。 |

目前的 PID 与 `gain_scheduled_pid` 七场景 A/B 已有运行记录，但汇总为
`1 accepted / 11 executed_blocked / 2 not_run`，不能写成七场景验证完成，
也不能据此声称 `gain_scheduled_pid` 全面优于 PID。E2 开始前必须重新确认
哪条优化路线在同配置、同指标下适合做正文比较对象。

## 3. E1 逐条审查方法

仅在授权且非演示版的 MWORKS 会话中，每条 `native_graphical_candidate` 固定执行：

```text
相位截图和窗口状态
  -> load_file
  -> CheckModel
  -> 打开实际内部控制律子模型
  -> 导出/截取可读的总览和必要局部图
  -> 仅在 CheckModel 成功后 simulate_model
  -> 绑定 Result、变量、指标、结果图和 manifest
```

图形布局的通过条件：控制信号方向和功能分组可读，关键积分/微分/饱和/观测器
或预测器模块可定位，连线能够追踪，且不是缩放后无法阅读的全图总览。复杂图可
采用“一个总览 + 少量逻辑分区局部图”，但每一张图都必须来自同一次打开的实际
内部模型。

`atomic_cfunction_wrapper` 不得以外层输入输出壳冒充算法内部图。应先查是否存在
可验证的等价 Sysblock 内部实现；若没有，则只保留接口集成和运行证据，不作为
正文算法结构图。检查或仿真失败必须保留失败结果，不能用旧 PNG 覆盖。

## 4. 恢复后的批次顺序

首批每次最多四条，先验证流程和会话稳定性：

1. `official_pid`、`gain_scheduled_pid`、`super_twisting_smc`、`linear_mpc`。
2. `cascade_pid`、`smc_boundary_layer`、`standardized_indi`、`pid_indi`。
3. `nmpc_outer`、`awff`、安全与故障容错主线、编队主线。
4. 其余原生图形候选按审计台账的 family 分批推进；每批结束即更新对应行，
   不等待 47 条全部跑完才保存结论。

每批的止损条件是：发现演示版、登录/授权窗口、未知弹窗、`CheckModel` 失败、
结果变量缺失或图形不可读时立即记录该条状态，停止该条的后续仿真，不用相邻
控制器的结果补位。

## 5. E2 场景执行前置条件

1. 官方 PID 与候选优化控制器均有 E1 通过的图形和模型检查记录。
2. 两条路线使用同一机体、参考轨迹、求解器、时长、初值、风/参数/故障注入和
   指标脚本；每次运行都必须有独立 manifest。
3. 先跑最小的起飞-悬停-降落和阶跃烟测，确认同配置可重复后，再依次扩展至
   8 字、螺旋、风扰、参数摄动、电机效率故障。
4. 电机故障场景优先复用已验收的 P7 rotor-1 0.65 效率损失注入与接管边界；
   不宣称完全停转或多故障恢复。
5. 三机编队不乘以七个单机场景，复用独立三机代表验证，并明确它不是自主探索。

## 6. 报告使用规则

- 正文仅使用 E1/E2 明确绑定的模型图、结果图、指标和运行 manifest。
- `neural_smc`、`mu_synthesis` 和任何未通过模型检查的路线不作为完成控制器展示。
- 历史结果可作为失败分析或已有证据索引，但必须标注其运行状态，不能替代当前
  MWORKS 复检。
- 47 条图形审查、七场景对比和三机编队各自有不同验收目的，任何一条完成均不
  自动提升其他两条的状态。
